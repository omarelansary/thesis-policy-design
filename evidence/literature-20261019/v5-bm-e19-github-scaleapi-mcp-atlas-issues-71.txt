Hi,

For closed-SaaS services (Notion, Slack), if a model calls a write tool during one task, that mutation persists and could affect the subsequent tasks. I noticed there is slack-conversations_add_message  in enabled tools, so write tools aren't universally excluded from task definitions.

How does the eval harness handle this? Is the SaaS state restored between tasks (e.g., re-seeding MongoDB)? Or does the harness rely on the model not writing since the GTFA claims are read-only?

Apologies, I couldn't find anywhere in the code how this is handled?

Sandbox per Task

2. Tolerance to Modifications and Static Validation of GTFA. In scenarios where fully restoring the state of a "closed" cloud SaaS application is too costly or slow (in the absence of a simulated local environment), the framework relies on the evaluation structure: No impact on metrics: Since the GTFA evaluation checks only whether the final response contains an exact string or key value (e.g., an ID, a name, or an extracted number), the fact that the model redundantly calls a write tool does not directly penalize the score, provided the agent does not enter an infinite loop and succeeds in returning the correct answer. Prompt consistency (System Prompt Constraints): The system also relies partly on system instructions, where the model is explicitly told to adopt a passive analysis or "read-only" behavior. However, the presence of the function in the schema acts as a "stress test" (or trap) to see if the model can ignore tools irrelevant to the task. Why are there no references in the local code? If you analyze the test suite's client code, the reset logic is not visible because the SaaS state is managed at the orchestrator/server level (the platform hosting the MCP server or the simulated API) rather than within the agent's evaluation script. The script merely sends the instruction, executes the trajectory, and passes the result to the GTFA judge.
