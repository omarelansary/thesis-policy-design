Search Engines Never Say No: 

How Frozen Agents React When the Retrieval Tool Refuses

Ramraj Chandradevan

Sayontan Ghosh

Vinoth Selvendran

Email: {first.last,first.last,vinoth459005}@gmail.com

Abstract

A search tool never says no: it returns its top-kk passages even when the index holds no answer, so the agent sees irrelevant text instead of a miss signal. We ask what frozen search agents do when the tool refuses instead. On an index-hole testbed (257 NQ and 300 HotpotQA questions run with and without their gold passages in a 21M-passage BM25 index), seven agents receive one of five refusal wordings. An un-announced one-sentence refusal raises abstention on unanswerable questions from 23% to 97% on average for Qwen3-8B/32B and from 28% to 57% for Claude Haiku 4.5, cutting wrong answers almost one-for-one and beating a system-prompt instruction by 51 points on average. Search-R1 ignores the refusal and fabricates retrievals; Claude Sonnet 5.5 and Opus 5.5 answer from memory (abstention +2+2 points) and obey a system-prompt directive instead (+16+16). We also found that wording matters: an explanation beats a bare token; a directive inside the observation is decisive for Haiku; a soft warning is useless. Realistic triggers, from a lightweight score-based predictor to an LLM grounding judge, fall well short of the oracle, and all land on a benefit-versus-signal-quality curve that prices any trigger by its recall at a fixed false-refusal budget: for compliant agents the bottleneck is the detector inside the tool, not the agent, and the curve tells future detector work what each point of recall is worth.

1 Introduction

A search agent is a language model that answers a question by calling a retrieval tool, reading what it returns and searching again if needed (Yao et al., 2023; Jin et al., 2025; Li et al., 2025). Today’s retrieval tools have a blind spot: they return their top-kk passages even when the index contains nothing that answers the query, so a miss looks exactly like a hit (Hua and Xiao, 2026; Li et al., 2026).

Fixing this blind spot is hard on either side of the tool call. On the agent side, training a model to abstain on irrelevant, missing or misleading evidence works (Zhang et al., 2026; Feng et al., 2026), but it needs access to the weights. Generally, strongest agents are closed models served through an API, and the open models that can be trained are smaller and less capable. Therefore, for most deployments only prompt engineering is left. On the tool side, a production search stack chains a first-stage retriever and one or more rerankers, each tuned for ranking quality rather than for detecting its own misses; teaching it to report a miss means re-optimizing every stage together. Due to the aforementioned challenges, in practice both components are frozen. What a system builder does control is the contract between them: what the tool returns. We propose to put the control there, as a gate at the tool’s outlet that makes one binary decision per call (pass the passages through, or refuse) and leaves both the retrieval stack and the agent untouched.

A question is unanswerable, an index hole, when no passage that could answer it is in the index. We change the tool contract so that the tool can refuse: instead of passages it returns a NULL observation, a short message saying that nothing reliable was found. We then ask what frozen agents (models used exactly as released, with no training) do with it: do they abstain (answer ‘unknown’, ‘I don’t know’ or similar), search again, or ignore the refusal and answer anyway?

Such a gate depends on two links. The first, retrieval→\totrigger, is how reliably a detector recognises a miss from what the retrieval stack returns. It depends on the retriever, the rankers and the detector, and can be summarised by the trigger’s recall at a fixed false-refusal budget. The second, trigger→\toagent, is what the agent does once the tool refuses. The second link comes first: a perfect detector is worthless if the agent ignores the refusal, and how off-the-shelf agents respond to one has not been measured. We therefore study the trigger→\toagent link and leave detector design to future work. We control the refusal directly with an oracle and with noisy oracles of known recall, measure how each agent’s behaviour changes as recall varies, and place realistic triggers on the resulting curve only to show where today’s detectors land.

Unlike score-based abstention in single-shot retrieval-augmented generation (RAG) or training the agent to abstain (Section 2), a tool-side refusal is a one-line contract change that applies even to closed models. Our key contributions are as follows:

• 

Introduced a search tool that can say no: a tool-side, training-free change to the tool contract that lets the tool refuse (return a NULL observation) when the index cannot answer; it needs no access to the agent and therefore works with frozen and closed models.

• 

Conducted the first comprehensive behavioral study of off-the-shelf agents facing a tool refusal, on an index-hole testbed that runs each question with and without its gold passages, so that unanswerability is known by construction rather than annotated (seven frozen agents, two datasets), which reveals: behavior: Qwen3-8B/32B and Haiku 4.5 obey the refusal and abstain (+243+243% relative on average), Search-R1 fabricates retrievals, Sonnet 5.5 and Opus 5.5 answer from memory; wording: directive >> explanation >> bare token ≈\approx empty list, and a soft warning is useless; safety and cost: hallucinated answers of the compliant agents fall by 84% at unchanged answerable accuracy and search calls.

• 

Presented a benefit-versus-signal-quality curve that prices any refusal trigger by its recall at a fixed false-refusal budget. Realistic triggers, from a lightweight score-based predictor to an LLM grounding annotator, all land on the curve, confirming that for compliant agents the bottleneck is the detector in the tool, not the agent, and giving future detector work a target to read off. Code, data splits, traces and the tool harness will be released upon acceptance.

2 Related Work

Silent tool failure.

Tool failures are usually silent (Gopalan et al., 2026; Li et al., 2026), and agents treat an empty payload as data (Singh, 2026). Sethi et al. (2026) show that an explicit error flag removes fabrication for API tools; a search tool cannot know that it failed, so the refusal must be predicted. Xu and Wu (2026) show that the wording of tool error messages governs recovery; we show that refusal wording governs abstention. Luo et al. (2026) and Xie et al. (2026) find that frozen agents rarely stop when answers run out; we ask whether they stop when told.

Sufficiency signals.

Query performance prediction (QPP) from score distributions (Cronen-Townsend et al., 2002; Zhou and Croft, 2007; Shtok et al., 2012) has been re-purposed for RAG abstention (Holdcroft et al., 2026; Veselý et al., 2026; Bacellar, 2026), cross-encoders as sufficiency gates (Mondal et al., 2026), and QPP correlates with agent answer quality (Tian et al., 2025; Tian et al., 2026); in none of these does the agent see the signal. Agent-side training (Zhang et al., 2026; Feng et al., 2026) and judges that stop an agent when evidence is sufficient (Roh and Han, 2026b; Roh and Han, 2026a; Luo, 2026) are complementary: our signal fires when evidence is absent. Knowledge-gap canaries (Do Rosario et al., 2026) and GRAB-RAG (Setiawan, 2026) delete answers from single-shot RAG contexts; our holes sit inside an index that a multi-turn agent searches, and their tool always returns kk passages after a deletion, so a shorter result list cannot betray the hole.

3 Experimental Setup

Testbed.

The corpus is wiki-18, 21M Wikipedia passages (Karpukhin et al., 2020), indexed with BM25 (Robertson and Zaragoza, 2009; Lin et al., 2021). Questions from KILT-NQ dev (Kwiatkowski et al., 2019; Petroni et al., 2021) and HotpotQA bridge dev (Yang et al., 2018) are kept only if their gold passages are retrievable in the intact index and no other top-50 passage contains the answer once the gold articles are removed (Appendix A): 257 NQ questions (all used) and 783 HotpotQA, of which 300 are sampled (due to costly API calls) and used for every agent. Each question is run in two roles: ans, with the intact index, and hole, where a per-call filter deletes every passage of the question’s gold articles (about 30) and, as a safety net, any passage containing an answer string. We confirmed that the passages for every hole episode returned to the agent contained no gold answer, so a correct hole answer can only come from memory.

Tool contract and wordings.

search(query) returns the top-5 passages (top-3 for Search-R1, its native setting); the tool description never mentions refusal, so a refusal is un-announced. When a signal fires, the tool returns one of five observations instead: N-bare, the token NULL_RESULT; N-empty, an empty result list; N-explain, the token plus “No reliable results were found for this query. The index may not contain the information needed.”; N-directive, N-explain plus a sentence suggesting a different query or answering ‘unknown’; N-soft, the normal top-kk passages preceded by a low-confidence warning. Baselines: V, the vanilla tool, and V+P, V plus a system-prompt directive to answer ‘unknown’ without supporting evidence. Agents may call the tool at most eight times in a single episode.

Signals.

oracle fires on every hole query (question-level ground truth). oracle-q fires only on the hole queries whose top-kk the deletion actually changed (76–92%); it is the ceiling for any trigger that sees one query at a time. qpp is the realistic trigger: a logistic regression on 14 statistics of the BM25 score list of the returned candidates estimates from the list alone whether the search succeeded; its threshold is calibrated on held-out agent queries so that at most 5% of answerable calibration episodes receive a false refusal, and it adds negligible latency. Section 4.4 studies additional three triggers with details in the Appendix.

Agents (all frozen).

Qwen3-8B and Qwen3-32B (Yang et al., 2025) via vLLM tool calling (thinking off, greedy); Claude Haiku 4.5, Sonnet 5.5 and Opus 5.5 via API (the 5.5 models run with provider-default sampling; Limitations), with the previous-generation Sonnet 4.6 in the appendix; Search-R1 (Jin et al., 2025), a Qwen2.5-7B model post-trained to search with an exact-match reward, with its native prompt.

4 Results

4.1 Do agents obey a refusal? Tool-side versus prompt-side

Table 1 shows that under the vanilla tool every agent hallucinates on a large share of the unanswerable questions; 65% of these answers copy a span from a shown, irrelevant passage. The N-explain/oracle refusal changes this for three agents: averaged over Qwen3-8B, Qwen3-32B and Haiku 4.5, hole abstention significantly rises from 24.4% to 83.7%, a relative improvement of 243%, and the wrong rate falls from 64.5% to 10.5% (−84-84% relative), almost one-for-one across both datasets. Three agents do not comply. Search-R1, whose post-trained exact-match reward never paid for ‘unknown’, abstains in under 1% of episodes and keeps 94% wrong answers. Sonnet 5.5 and Opus 5.5 move from 1.4% to 3.2% abstention (+1.9+1.9 points; significant only for Opus).
Tool-side versus prompt-side: For the compliant agents the prompt directive alone (V+P) raises abstention from 24.4% to 32.3% (+32+32% relative); the tool refusal raises it to 83.7%, beating the prompt by 51.4 points. For Sonnet 5.5 and Opus 5.5 the order reverses: the prompt lifts them to 17.3%, whereas the refusal to only 3.2%.

The wording of one-line tool-side refusal makes substantial differences in HOLE abstention rates. Table 2 confirms the following findings: (i) The explanation beats the bare token: 83.7% versus 79.5% abstention averaged over the two compliant agents (Haiku and Qwen3-8B). (ii) A bare token and an empty list are indistinguishable (79.5% vs. 79.4%). (iii) The directive is the strongest lever (92.5%); for Haiku it is decisive (80.7%, +23+23 points over the explanation). (iv) The soft warning is nearly useless (29.2%, +4.8+4.8 points over V): the agent anchors on visible passages.

4.3 What non-compliant agents do?

Search-R1 never abstains (<<1%, Table 1); a refusal only makes it search more before answering (2.9 →\to 4.6 and 3.5 →\to 5.2 calls), and in 72% of these wrong episodes its reasoning reports a finding it never saw (“I found out that …” after four consecutive refusals; Appendix B). Sonnet 5.5 and Opus 5.5 answer from memory: the Mem. column of Table 1 shows they are right without any supporting passage in 39% of unanswerable questions under the refusal (37% under V), Sonnet 5.5 after more reformulation (2.2 →\to 4.3 calls on NQ), and Opus 5.5 without (2.3 →\to 2.3). Opus 5.5, the strongest model here (highest ans EM), is no more compliant than Sonnet 5.5 under any tool refusal (within 3 pts).

4.4 How far can a realistic trigger get today?

Realistic triggers fall well short of the oracle; what they deliver is the recall they achieve within a false-refusal budget. Figure 1 plots, for Qwen3-8B, abstention and wrong-answer rates on unanswerable questions against the share of those questions with at least one refusal; the lines connect V, two noisy oracles, oracle-q and oracle. Because a compliant agent reacts only to whether the tool refused, the curve prices any trigger: a detector on the line delivers exactly what its recall predicts, so its benefit can be read off before deployment. We placed four triggers on it (refer Appendix C), from lightweight to LLM-based. (1) The lightweight BM25 qpp refuses in 16%/37% of unanswerable questions (NQ/HotpotQA) and raises abstention by 69%/109% relative to V. (2) A zero-shot cross-encoder (Chen et al., 2024b) at the same 5% budget refuses in 26%/39% and raises it by 92%/160% (det-bge). (3) Relaxing its budget to 10% roughly doubles recall (46%/61%) and raises abstention by 197%/266% (det-bge-hi). (4) A strict LLM grounding judge Chandradevan (2024) used as a hard filter (detf-llmjudge: drop rejected passages, refuse if none is left) refuses in 61%/71% and raises it by 253%/363%, closest to oracle-q (+412+412%/+483+483%) but unbudgeted (at the cost of refusing 28%/36% of answerable questions). Every marker lies on or near the line: for a compliant agent the detector, not the agent, is the bottleneck, and the curve states in advance what any future detector is worth.

5 Conclusion

A retrieval tool that can say no is a cheap, training-free safety mechanism for the agents that obey it: for Qwen3-8B/32B and Haiku 4.5 an explanatory refusal raises abstention on unanswerable questions by 243% and cuts hallucinated answers by 84%, at unchanged answerable accuracy and search calls. It is of little use for the post-trained Search-R1 and for Claude Sonnet 5.5 and Opus 5.5, which answer from memory instead. Three recommendations follow: make a failed search visible; explain it, and put the directive where the agent reads it (the observation for Qwen and Haiku, the system prompt for the 5.5 models); and pick the false-refusal budget knowingly, since realistic triggers deliver only the recall that budget buys. The benefit-versus-signal-quality curve makes that trade explicit: every trigger we tried lands on it, so for compliant agents the open problem is the detector inside the tool, and the curve tells future detector work what each point of recall is worth.

Limitations

Scope of the testbed. Our index holes delete the gold Wikipedia articles of one corpus and two QA datasets; the strict eligibility filter leaves 257 NQ questions, and unanswerability in the wild (stale facts, false premises, private data) may look different to both the trigger and the agent.

Automatic scoring. Outcomes are scored by string matching against gold aliases and a frozen abstention lexicon; an LLM-judge audit shows the abstention label is reliable but the correct/wrong split is conservative, so absolute hallucination rates are upper bounds while every between-condition difference is unaffected.

Agents and triggers are snapshots. We study seven frozen agents with fixed prompts and default decoding, and every realistic trigger was calibrated once on one agent’s queries; different prompts, per-agent calibration, or future models could shift the absolute numbers, although the benefit-versus-signal-quality curve lets a reader price any new trigger.

Ethical considerations

The intervention reduces confident wrong answers on questions the index cannot support, which is the intended safety benefit. But it also introduces false refusals on answerable questions (1–23% of episodes here for the 5%- and 10%-budget triggers and 16–58% for the hard-rule LLM as a judge, depending on agent). For compliant agents each false refusal costs the answer. Deployments should calibrate the trigger per agent and monitor false-refusal rates. All data are public English Wikipedia QA benchmarks (NQ, HotpotQA, KILT, wiki-18) used under their licences; no human subjects were involved in our study; commercial model outputs were used only for evaluation. Language-model coding assistants were used in the implementation, as disclosed in the checklist.

Appendix A Testbed and tool strings

Eligibility funnel.

A question enters the testbed only if its unanswerable version is unanswerable by construction. Starting from the KILT-NQ and HotpotQA (bridge) development sets, we first drop questions whose answer would make the hole leaky or the metric unreliable: yes/no, purely numeric, year, very short (under four characters) or stop-word answers, and answers longer than six tokens. We then require every gold Wikipedia title to resolve to a passage in the wiki-18 corpus, and at least one gold passage to contain an accepted answer string, so that deleting the gold articles really removes the answer. Because the tool also removes any surviving passage that contains an answer string, we keep only answers that occur in at most 2,000 corpus passages; otherwise the deletion would gut the corpus rather than carve a hole. The question must be answerable in the intact index (an answer-bearing gold passage in the BM25 top-20 for the question itself), and, after the gold articles are removed, none of the next 50 best passages may still contain the answer; otherwise the answer is redundantly present and the hole is vacuous. Table 3 gives the surviving counts after each step. All 257 surviving NQ questions are used; of the 783 HotpotQA survivors we sampled 300. Calibration pools for the trigger apply the same rules to the training splits (300 questions per dataset) and are disjoint from the evaluation questions.

Alias safety net.

Every hole query additionally removes surviving passages that contain a gold alias as a whole-word, case-folded phrase. The net fires on 27% of hole calls overall, more often for Claude (27–36% of calls) than for Qwen (18–24%) or Search-R1 (19–22%), because Claude often searches for the answer it already suspects; the effective hole for Claude is therefore the title hole plus on average 17–31 alias-bearing passages per question, still negligible relative to the corpus. A full scan of all 266,969 passages shown in 127,791 hole calls of all seven agents found 0 passages with a gold alias, gold title or gold docid, and every NULL observation was byte-identical to its format string. On ans the filter is inactive by construction.

Observation strings.

The tool returns a JSON string in the vanilla conditions; the refusal strings below are the experimental manipulation and were byte-identical across agents. For Search-R1, whose native protocol wraps observations in <information> …</information>, the same strings are placed inside that block and N-empty is the empty block. ↩\hookleftarrow marks a newline.

V (and N-soft body): {"results": [{"rank": 1, "title": …, "text": …}, …]}

N-bare: NULL_RESULT

N-empty: {"results": []} (Search-R1: <information></information>)

N-explain: NULL_RESULT: No reliable results were found for this query. The index may not contain the information needed.

N-directive: NULL_RESULT: No reliable results were found for this query. The index may not contain the information needed. Consider a different query, or answer ’unknown’ if the question cannot be answered from the search results.

N-soft: WARNING: low-confidence results; these passages may be irrelevant to the query.↩\hookleftarrow followed by the normal V observation.

Prompts (tool-calling agents).

The system prompt is byte-identical across all conditions; the +P conditions append exactly one sentence; the tool description never mentions refusal. After the eighth observation an identical neutral user turn is inserted in every condition. Search-R1 keeps its native prompt and protocol; closed-book prompts and the full tool schema are in the released code.

System prompt: You are a question-answering assistant. Answer the user’s question using the search tool. You may call search up to 8 times. When you are ready to answer, end your reply with exactly one last line of the form:↩\hookleftarrow Final answer: <short answer>↩\hookleftarrow The short answer must be a few words (an entity, name, place, date or short phrase), not a sentence. If you cannot answer the question, the last line must be exactly:↩\hookleftarrow Final answer: unknown

+P directive (appended): If the search results do not contain evidence supporting an answer, you must answer unknown rather than guess.

Tool search(query: string), description: Search a Wikipedia passage index. Returns the top passages for the query.

Forced-final user turn (after 8 calls): You have no more search calls. Give your final answer now.

Table 5: Realistic triggers, live (%), observation N-explain throughout: hole abstention (Abst.), Recall = share of hole episodes with ≥\geq1 refusal, FR = share of ans episodes with ≥\geq1 false refusal, EMans{}_{\textsc{ans}} = ans cover-EM. DET = refuse-only, DETF = filter+refuse (drop rejected passages, refuse if none is left); cheap = 56-feature logistic regression, bge = zero-shot bge-reranker-v2-m3 at the 5% (hi: 10%) calibration false-refusal point, llmjudge = Qwen3-8B strict few-shot grounding judge (thresholds in Appendix C); markers as in Table 4; –: not run.

Every trigger decides, per search call, from the post-filter candidate list and nothing else; it never sees the gold answer. Thresholds were fixed once on the calibration split, using Qwen3-8B’s pilot queries, so that at most 5% of answerable calibration episodes receive a false refusal (10% for the “hi” operating point), and were shared by all agents. Table 5 reports every live trigger cell.

• 

QPP (BM25 score list). An L2-regularised logistic regression on 14 statistics of the BM25 scores of the returned candidates (top score, mean and spread at k=5/10/20k{=}5/10/20, gaps between the top and the kk-th score, NQC- and WIG-style normalisations, number of query terms in the top passage, number of distinct titles in the top five, list length), trained on 1,461 agent-issued calibration queries labelled by whether the returned list contained an answer-bearing passage.

• 

Dense QPP (DQPP). The same recipe with e5-base-v2 Wang et al. (2022) cosine similarities between the query and the same BM25 candidates in place of BM25 scores (bounded scores, unaffected by term statistics when passages are removed); the retriever itself is unchanged.

• 

Cheap feature set. The 14 QPP features plus 42 list-level lexical features (query-term coverage, title diversity and entropy, IDF-weighted matches, Clarity-style divergence), fitted with the same logistic regression.

• 

Cross-encoder (DET-bge, DET-bge-hi, DETF-bge). Zero-shot bge-reranker-v2-m3 Chen et al. (2024a) scores each shown passage against the query; the trigger refuses when the best passage scores below the calibrated cut (DET-bge at the 5% point, DET-bge-hi at 10%). The filter variant additionally drops passages below the per-passage cut and refuses only when none survives.

• 

Strict LLM grounding judge (DETF-llmjudge). Qwen3-8B labels each shown passage 1 or 0 with a few-shot prompt that accepts a passage only if it can ground an answer, or the bridge an entity the query is looking for, and rejects passages that are merely on topic; passages labelled 0 are dropped and the tool refuses when none remains Chandradevan (2024). This rule has no false-refusal budget.
