## 2. Problem families (merged taxonomy; evidence strongest first)
| Family | What is known (strongest evidence) | Open question / uncertainty |
|---|---|---|
| **Reliability of selection as catalogues grow** | Degradation claims exist but are confounded: LongFuncEval ties tool count to context length and adds distractors at random (r3-longfunceval L241-255, Table 3 L623-638; checked V3). Counter-evidence: no significant difference from 50 to 300 tools at 200K in one single-author study (TSCG, checked); a benchmark where large catalogues helped for several models (MCPVerse quote checked, table garbled). Hard (semantically similar) distractors reduce accuracy more than random ones at the same K in RL-trained 3B-8B models, with shorter prompts (SLCA-GRPO appendix, checked V5). Vendor capacity heuristics disagree (10-20, <20, 30-50) with no basis stated | Which model-visible property causes the loss: number, tokens, semantic overlap, position? Does it appear for current frontier models within their windows? Short-lived if models saturate (SKILL-USE: gap "nearly disappears for models already near saturation", checked V4) |
| **Cost and latency of exposure under caching** | Stable-prefix definitions are cached; implicit caching of large `tools=` arrays appears in one preprint (hedged); providers now document cache-preserving append/removal; cost of schemas is trajectory-dependent (same task 7-18 turns); token reduction can raise billed cost for tool outputs (checked in Stage 4). A validated two-tier cost model exists (CAPC) | Success-adjusted billed cost per exposure mechanism, including discovery turns and misses; mostly arithmetic given hit rates; findings may date quickly |
| **Exposure mechanisms (retrieval, deferral, code/programmatic, gateways, skills, partitioning)** | Large design space; shipped defaults are lexical (Anthropic regex/BM25 variants checked V3; Codex BM25 per worker, critic verified); deferral thresholds differ by vendor, but the "order of magnitude" framing was wrong (Claude Code unset = defer all MCP tools; 10% is only `auto`; MCP guide's 1-5% is an example; checked V3). Best controlled mechanism comparison found is for skills, not tools (Skill Blocks: no universal winner) | Head-to-head across families with success, usage-priced cost and repeats (bounded negative survived both critics, with named near-misses) |
| **Security of discovery and exposure** | Retrieval-stage hijacking at 9,650-tool scale (96.7% ASR, four dense retrievers; checked V4), description-driven selection shifts (ToolTweak, Tool Preferences), poisoning benchmarks, fail-closed capability exposure designs, code-execution attack surface | Does the exposure mechanism (lexical model-initiated search, stubs, dense top-k, all-visible) change attack success? No lexical or model-written-query condition in the dense-only hijacking setup (setup section checked; full paper not) |
| **Evaluation validity** | Evaluator-human disagreement 18.5% across audited benchmarks; one pipeline's 23 reruns spanned 57.9-76.8% (SD 5.4 pp per C1; spread is range not SD); single-run reporting common; "maintains performance" is never tested for equivalence (Skill Blocks states its null tests do not show equivalence) | A pre-registered non-inferiority design with power analysis; whether mechanism rankings (not only model rankings) flip across graders (no traces known) |
| **Description authoring / visible layer** | 97.1% of 856 MCP tool descriptions have a smell; augmentation raised median success 5.85 pp, steps 67.46% (median over 24 model-domain rows; three of four models compared to published baselines, not reruns: checked V3) | Marginal value of description components at catalogue scale; provider-specific residue (OpenAI keeps name+description of deferred functions visible; Anthropic only the search tool) |
| **Session working set / eviction** | MemTool, Pichay stubs, Anthropic `tool_addition`/`tool_removal` (cache-preserving) | Accumulation over realistic sessions; being absorbed by providers |
| **Query formulation in model-initiated search** | Retrieval error is the largest class in a LiveMCPBench taxonomy (Retrieve 50.00%; checked V3); rewriting roughly doubles BM25 nDCG in one setting; re-retrieval adds 26.7 points in another | Who writes the query and how good it is under real exposure policies |
| **Capacity as hard constraint** | Provider limits (10,000 deferred tools, 4 MB) and window limits; compression matters when the budget binds (TSCG 8K case is arithmetic: an ~11K block cannot fit in 8K) | Largely arithmetic except behaviour near the limit |
| **Magnitude in real use** | Anecdotal and single-user composition data (e.g. 140.2k tokens = 70.1% of a window in one PayPal deployment; one 857-session trace with internally inconsistent attributions) | No independent multi-user breakdown of definitions vs outputs vs history |
| Granularity (atomic vs composite vs code), lifecycle/drift/pinning, partitioning/memory, energy, serving-side KV reuse | Thin or training-heavy; some absorbed by providers | See rejections |

## 3. Objectives and their definedness
(After critic C2, B.3; I) Context occupancy is well defined but arithmetic. Billed cost is definable but depends on provider caching internals and changes with feature releases. Selection reliability is the best defined scientifically (clean manipulation, deterministic grading, independent of vendor pricing) but its connection to the supervisor's token objective needs a multi-turn cost arm. Security (attack success) is well defined but departs from the token objective. Latency, maintainability and user experience are poorly defined in the sources. The user's stated target (tokens with performance maintained) is well defined only for capacity and is statistically undefined for "maintained" (no equivalence testing anywhere in the corpus).

## 6. Overlooked directions the wider search surfaced
Security of discovery mechanisms (D-SEC); causal separation of overlap from tokens and count with token-matched controls (D-REL); query formulation under model-initiated search (supported by a 50% retrieve-error share in one taxonomy; not developed); multi-user magnitude of definition overhead (no data); non-inferiority methodology (D-NI). Convergence bias toward cost framings in the workers is documented (C2).

## 7. Comparison with the Stage 4 shortlist and earlier rejections (done only now)
- **RQ-A (arithmetic-baselined cost-effectiveness of exposure policies)**: independently reached by three workers (cost question) and ranked #2 by C1 and #4 by C2 behind reliability. Both critics repeat the Stage 4 objections: arithmetic determinism, provider co-training and obsolescence, power and budget. The wider space therefore **lowers** its relative standing but does not remove it; it remains the most direct test of the user's stated objective.
- **RQ-B (recall dose-response)**: not independently surfaced; sits under the "exposure completeness" factor of D-REL/D-COST. Stage 4's evidence (CAM-DF single-miss) stands. Wider space supports demoting it to a factor.
- **K-C (graded exposure policy)**: rejection confirmed by two critics (shipped practice, comparator infeasible at scale).
- **O4, O6, O5, F10**: rejections confirmed or merged. O6 (benign description reliance at scale) is distinct from the security-of-description direction D-SEC and from the visible-residue factor.
- **New relative to Stage 4**: D-REL (ranked first by both critics) and D-SEC (ranked second by C2). The Stage 4 shortlist was therefore too cost-centric: its reviewer worked from the same cost-salient corpus. This is an observation about the earlier process, not a retroactive change to its verdict.

## 8. Shortlist, justified against the wider space (not a decision)
1. **D-REL (narrowed): "Which model-visible property of a large tool catalogue degrades selection, and does hiding it recover performance at acceptable cost?"** A token-matched factorial over count, tokens, overlap and position with residue tier as a factor, plus a short multi-turn arm with usage-priced cost to connect to the user's objective. Ranked first by both critics; supported by a documented confound and conflicting prior evidence. Conditions: open-weight local compute or modest API budget; accepts null results.
2. **D-COST (reformulated RQ-A)**: remains the direct test of the stated objective; ranked second by C1 and fourth by C2. Conditions: provider API access and budget.
3. **D-SEC**: a defensible alternative objective with strong measurability; requires the user to admit security into scope.
RQ-B is retained only as a factor. D-NI is a mandatory design component of 1-3. No other family survived.

## 9. Unresolved objections
- Both critics could not assess whether the mechanism-comparison and token-matched gaps exist beyond the stored and searched surfaces.
- C1's strongest objection to D-REL: single-step selection may not answer the token-and-performance objective without a cost arm; C2's: the general-length effect may explain most of any tool-count effect and frontier models may saturate.
- C1/C2 power estimates are illustrative assumptions; no power analysis has been done.
- Vendor and unstored items remain unverified (Cursor 46.9%, Vanta 48%, issue 83756, Arcade).
- The workers' abstract-level reads of 2026 papers (CIPO, HyperTool, ReCache, ToolSearcher, SING and others) are unverified.

## 11. Corrections after the independent C3 check (added after the map was first issued; earlier text left in place)
C3 was run after sections 7-8 and its consequential objections were re-read against primary text (`audits/S4B-V6-coordinator-check-of-C3-20261013.md`). These statements above are superseded:
1. TSCG (sections 2, 4): its p > 0.10 compares JSON and TSCG formats, not tool counts; it is not evidence about count effects (synthetic tools, RAG exact match, retrieval budget shrinks with count).
2. MCPVerse (section 2): most models degrade from Oracle to Standard and all evaluable models degrade further at Max-Scale; a few agentic models gain, attributed to alternative paths.
3. ToolHijacker (section 2): 96.7% ASR is MetaTool (GPT-4o); on the 9,650-tool ToolBench library attack hit rate is 96.1-97.8% and GPT-4o ASR 88.2%.
4. "No equivalence testing anywhere" (section 3) and "no independent evaluation of provider tool search" (section 1) are too strong: informal equivalence checks and NI formulations exist (Pichay, ch-s2-0176), and one academic profiling study includes a deferred-loading client (confounded). Skill Blocks is a cache-read-discounted comparison, not tier-billed.
5. D-SEC (sections 4, 8): RACG already compares exposure methods including keyword top-k on injection success (ISR 1.00 for all tools and keyword top-10; 0.00 for RACG). The residual gap is model-initiated search and stub exposure; triviality risk is evidenced.
6. D-RECALL / RQ-B (sections 4, 7): PlanBench-XL (graded block ratio over 1,665 tools, monotone degradation) supports demotion more strongly than CAM-DF; blocked tools are replaced rather than withheld and there is no fallback toggle.
7. D-REL (section 8): count, total tokens and residue tier are algebraically linked, so a full token-matched factorial is not executable; it narrows to two or three targeted contrasts (count at fixed tokens with a pre-registered padding construct; overlap at fixed count and tokens; residue tier at fixed count). ToolMenuBench (frontier models, 25/100/250 tools, distractor-type stress tests) must be cited as closest prior art. The multi-turn cost arm inherits D-COST's power problem.
8. Section 7 process corrections: critic agreement is not independent confirmation (both critics read the same pool); the power objection applies to D-REL's applied arm as well as D-COST; C2 ranked F1 fourth and the head-to-head mechanism comparison fifth; RQ-A is not shown to be "the most direct test of the user's stated objective" until decision D-a is made, and the reformulated RQ-A's falsifier lacks an interval method and restricts the estimand to sizes where every arm is feasible.
9. C3 verdict (critic statement): one narrowed direction (D-REL, cut down) is defensible as a bounded incomplete-evaluation / control-design question, not shown to be novel; C3 does not recommend PASS for any direction as currently worded; it proposes a merged two-phase design (diagnostic contrasts, then a small confirmatory comparison with a non-inferiority margin) whose Phase 2 cannot be powered for 5 pp within plausible budgets. The user decides.
