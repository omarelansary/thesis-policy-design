### 2c. Which of Executor's documented tools the model was offered
- **Offered to the model: three provider tools, `execute`, `skills`, `resume`** (2,694 bytes as provider tools; `tools/list` sha256 `71de3966…`; protocol `2025-06-18`). Source: live-gate record section 2; pre-registration section 2. The runner and route check on every cycle that the active tool names equal this set and the provider tool count is 3 (section 3).
- **`search`, `describe`, `call` are not separate provider tools.** In the source at the pin they are helpers inside the code sandbox that `execute` runs: `tools.search({query, namespace, limit, offset})`, `tools.describe.tool({path})`, and invoking a tool by calling it on the `tools.<namespace>...` proxy. Source: upstream `packages/core/execution/src/engine.ts` lines 308-460 and `packages/core/execution/README.md`; PWD-017 says the same ("discovery by the model writing TypeScript").
- Not offered, by configuration: the artifact tools (`artifacts=false`); the per-integration `search_<integration>` tools (opt-in `?search_tools=true`, kept off); passthrough mode, which would serve `search` and `invoke` instead of `execute`/`skills`/`resume` (`?mode=passthrough`, not used). Source: upstream `tool-server.ts` lines 183-215 at the pin.
- `skills`: serves static how-to documents; with no name it lists the index (`tool-server.ts` lines 2052-2100). `resume`: continues a paused execution (elicitation or approval). The contract records that every reachable tool is pre-approved, and that a pause or an approval decline is classed as an apparatus fault (pre-registration section 2a), so `resume` was offered but not expected to be needed.

### 2d. How the 20 per-server facades were built, and what they change
- Built as `atlas_mcp_facade.py` in the adapter repository (branch `wt/executor-adapter` at the time; PWD-017 says the Executor route lives on adapter branch `g8-mech-pilot`). One MCP endpoint per MCP-Atlas server; each maps the sandbox's `/list-tools` to MCP `tools/list` and `/call-tool` to `tools/call`. Decision U3: a "mechanical protocol adapter only": no retrieval, no caching, no retries beyond the contract, no schema enrichment, no renamed descriptions "except unavoidable MCP serialization". Input schemas were not touched. (ii) Each upstream call is logged as `call_start` and `call_end`; each `tools/list` is logged with its hash. Source: live-gate sections 1, 7.

## 3. The harness

- **Runner:** `thesis-main/scripts/active_registry/run_executor_baseline.py` (not reachable). Its hashes by version are in the amendment records (v1 `641bd6f8…`, v1.1 `2fb275d3…`, v1.3 `d4213a55…`, LF basis). Modes named in the records: `pilot`, `full`, `pilot-check`, `pilot-gate`; scoring and analysis are separate scripts. Contract in force for the full run: `thesis-main/configs/executor_mcp_atlas_baseline_v1_3.json` (sha256 `1d17abf8…`); order file `configs/executor_full_run_order_v1.json` (`381e74a2…`); pilot manifest `configs/executor_pilot_manifest_v1.json` (`2490a71a…`). The runner refuses to run unless the pre-registration file is committed and unmodified (`assert_preregistration_committed`).
- **How a slot is run:** the runner sends one HTTP request per attempt to the adapter's local evaluation service. For the Executor arm the route is `run_agent_executor` (`run_executor_mcp_eval_request`): request fields model, messages, max_turns, extra_body, tool_document_shape; it refuses `activeToolNames`, `selectorId` and `toolBudget`. The route hands the loop (`run_dynamic_mcp_eval`, the comparator's host loop, unchanged) an `ExecutorSurfaceSelector` and an `ExecutorMcpClient` pointed at the toolkit endpoint. The direct arm uses the comparator route with all 126 tools. Source: v1.1 record sections 4a and 4b.
- **Messages:** the task `PROMPT` is the only user message; no system prompt (pre-registration section 2).
- **Tools array per call:** Executor arm: three tools every cycle. The runner checks per cycle `active_tool_names == EXECUTOR_SURFACE` and `provider_tool_count == 3`; any difference is an exposure violation that aborts the run (pre-registration section 7). Direct arm: the full catalogue in canonical order, checked per cycle for exposure and drift (`check_exposure`; `inventory_drift`). So "fixed within a run" is enforced by a per-cycle check, not assumed. Source: v1.1 record section 4a.
- **Caps and retries:**
  - 50 model turns; reaching it is a recorded policy outcome (`max_turns_exhausted`).
  - Provider rate-limit retries inside an attempt: up to 5, waiting to the gateway's reset (inherited from the earlier E0 runs).
  - Infrastructure retries: at most 3 complete attempts per slot; apparatus faults retried, arm behaviour never retried; status classes are in pre-registration section 2a (functions `apply_b2`, `classify_executor_attempt`).
  - Concurrency 1; paired blocks in the fixed order. Amendments v1.2 and v1.3 add resumability: a stop file that stops after the current pair, automatic recovery, and a stop on lost network or service connectivity.
- **Logged per attempt (field names):** raw record per slot (`task_id`, `condition`, status, failure, `exposure_violations`, `inventory_drift`); a run note per attempt with `block`, `arm`, `task_id`, `repeat`, `attempt`, `run_id`, `status`, `failure_code`, `attempt_windows`, `executor_faults`, `telemetry_source`, `executor_telemetry`, `cost`, `usage_cycles`, `partial_usage`, `annotations`, `exposure_violations`, `provenance`. Cost fields named in E0's design: `provider_schema_utf8_bytes` (per cycle), `prompt_tokens`, `cached_prompt_tokens`, uncached tokens (= prompt minus cached), `completion_tokens`, reasoning characters, cycles, tool calls, per-run duration (rate-limit wait separated). Token counts are the provider's reported usage, summed per cycle by the loop's own rule (`usage`, `cycles`, `reported_cycles`). **Cache-write tokens: not found** in the records read. **Provider and model id as served: not found as logged fields**; a `provenance` object exists, its contents were not shown in the records read. Facade log: `facade_calls.jsonl` (`call_start`/`call_end` lines; `list` lines with hash). Daemon log restarted per attempt; ERROR records keyed by correlation id.
