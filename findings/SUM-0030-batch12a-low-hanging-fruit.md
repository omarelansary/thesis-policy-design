## Is there a curve on one task set in which "50% free, 50% to 10% costly" could be read?

- [F] Four sources vary the reduction level on one task set: AutoTailor (pool 1,283 / 215 / 87 / 33), MCP-Zero (two pool scopes, Domain and Full), DynamicMCPBench Table 7 (curated 8, rag:4/8/16/32, hier, flat 1,168) and Bifrost (three tool-set sizes, vendor, 100% ceiling).
- [O] None shows the stated shape. AutoTailor is non-monotone (a loss at the middle point, recovered at the smallest set by usage-based adaptation). DynamicMCPBench shows accuracy rising with k and with reachability; the near-tie rag:32 vs flat (-97% of tools, -0.7 pt) is the authors' "two effects cancelling", and rag:4/8 cost 12-18 pt relative to flat. Bifrost shows no loss at all three levels but at a 100% pass rate (ceiling).
- [O] The cases where accuracy was lost at a modest reduction are: MCP-Zero multi-turn Domain (-61% prompt tokens; Claude -8.6 pt, GPT-4.1 -6.5 pt); AutoTailor with ReAct at the first filter (about -83% of tooling tokens, -4.5 pt) and without ReAct at the second (-92%, -10.2 pt); ToolMenuBench keyword top-10 (-92% visible tools, -9.7 pt); ComplexMCP RAG k=60 (-80% candidates, -17 to -28 pt).
- [I] In the sources where a loss is reported, the authors tie it to the required tool being absent from the reduced set (DynamicMCPBench reachability; ComplexMCP latent tools; AutoTailor "APIs estimated to be less frequently useful may nevertheless be essential for less common task types", L635-637), not to the percentage as such.
- [U] No stored source runs a 50% reduction by removing tools at random or by a defined rule and reports accuracy at that single level against the 100%, 10% and 25% levels on the same tasks. I searched: the literature copies listed in the file headings, EXT-0207/0208, existing steward findings SUM-0022, 0028, 0029, and this batch's reads.

## A6: verdict

**MIXED.** The stored sources report both preserved or improved accuracy at large reductions (MCP-Zero Full pool, Anthropic tool search, AIMultiple, Bifrost, AutoTailor SDR, ToolMenuBench CMTF) and losses at moderate-to-large reductions (MCP-Zero multi-turn Domain, AutoTailor ULF, ToolMenuBench keyword filters, ComplexMCP RAG, DynamicMCPBench rag:k). The "50% to 10% is the hard part" shape is not shown by any single curve in the stored set; the data suggest the accuracy change depends on whether the required tools remain in the reduced set (and, in ToolMenuBench, on the filter), rather than on the percentage. The vendor figures (Anthropic, Bifrost, AIMultiple, Speakeasy) have ceilings or no stated intervals and are not independent of the product being sold. The supervisor's remark "maybe not for MCP Atlas" is DOES NOT ADDRESS: the stored MCP-Atlas lines show a controlled set of 6-37 tools per task, 2-8 relevant, and no exposure-reduction experiment was seen.

A better-specified version, for the supervisor to accept or drop: "Reducing the visible tool set to about half preserves accuracy in the cases where the required tools stay reachable; the cost appears when the reduction drops required tools or when the filter is lexical" and "report accuracy against a reachability measure as well as against the percent reduction". This is a suggestion, not a design decision.

### A13: verdicts

- **"Filtering 100 to 60 is a safe big win" - NOT ADDRESSED IN THE SOURCES READ** at that level (no source with a 100 -> 60 step and accuracy). Nearby evidence is mixed: Tulip (100 tools, factor 2-3 cost, correctness maintained for the decomposing variants); ComplexMCP (60 of 300+, large loss with embedding top-k); AutoTailor (pool reductions of 83-98%, mixed).
- **"Giving names only to the lowest tier keeps accuracy" - NOT ADDRESSED IN THE SOURCES READ as a measured tier comparison.** The nearest are AIMultiple (names plus 60-character descriptions, 100% vs 100%, two queries, one model) and Speakeasy (names first, schemas on request, "nearly 100%" on simple tasks, complex tasks not validated). I found no stored source that compares names-only, compact-schema and full-schema tiers on one task set with accuracy.
- A better-specified version (suggestion for the supervisor to accept or drop): "In setting S, tools in the lowest tier are shown with a name and a short description; on tasks where a lowest-tier tool is required, the model reaches it through a discovery step; accuracy on those tasks is compared with the full-schema arm." The nearest numbers to cite are AIMultiple (L94-98) and DynamicMCPBench Table 7 (reachability).
