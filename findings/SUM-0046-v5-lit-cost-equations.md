## 2. Calc-script consistency (not a literature check; reading of the three scripts)

Question: after the 2026-10-27 fix, do `memory_seed.py` and `price_sensitivity.py` count in the saving of an avoided search the same two re-reads that `regime_bill.py` charges for a client-side discovery?

[F] `regime_bill.py` charges a client-side discovery (a) one extra request whose read of the core prefix p = CORE·d + SEARCH is inside `prefix = p*(W + (reqs-1)*r)` with `reqs = t + disc` (:34-35), and (b) in `per_disc`: `H*r + O*Q + K*d*(W + (t/2)*r)` (:36). So per discovery: p·r (core prefix re-read), H·r (history re-read), o·q (output), K·d·(w + (t/2)·r) (K appended definitions, written once, read on t/2 later requests).

[F] `memory_seed.py` (:26, :29-33): P = CORE·D + SEARCH = 1,550; `s = ((H + P)*r if mode == "client" else 0) + O*Q`; `saving = s + (k-1)*D*(W + (t/2)*r) - D*r*((t-1) - t/2)`. The avoided request's two re-reads (H·r and P·r) and the output o·q are both counted, and the K−1 other matches are counted at the same carry price as in `per_disc`. In server mode only o·q is counted, which matches `regime_bill` (`reqs = t`, `per_disc` without H·r).

[F] `price_sensitivity.py` (:17-21, :28-32): `deferral` uses `p*(w + (t+disc-1)*r)` and `per = H*r + o*Q + k*D_FULL*(w + (t/2)*r)`: same as `regime_bill` client mode. `hstar` uses `saving = (H + CORE*D_FULL + SEARCH)*r + o*Q + (k-1)*D_FULL*(w + (t/2)*r) - D_FULL*r*((t-1) - t/2)`: the same two re-reads as `memory_seed`. Answer: yes, both scripts now count the same two re-reads (history H and core prefix p) and the same output and K−1 carry terms [F, by reading; I did not run them].

Terms of `regime_bill.deferral` that the seed saving omits, or that all three omit [I, all small and none double-counted that I can find]:
1. The extra request also re-reads definitions appended by EARLIER discoveries in the same session (and by memory seeds); `regime_bill` reads those only on t/2 requests, and counts neither the extra requests as reads of them nor the later extra request's prefix growth. The seed saving does not charge this either, so the two are consistent; both omit it.
2. The model's search call (q output tokens, priced at o) also becomes input on every later request (written once and read afterwards); neither script adds that, so the saving of an avoided search is understated by about q·(w + (remaining requests)·r) per avoided search (q = 150 tokens in the scripts) [I].
3. `regime_bill` has an "uncached core" variant (`core_cached=False`, :35) in which the core prefix is paid fresh on every request, so the avoided extra request would save p·1 rather than p·r. `memory_seed.hstar` and `price_sensitivity.hstar` have no such variant and always price the P re-read at r [F]. It is a difference of scope, not a double count; it makes the seed saving understated when the core is below the minimum cacheable length.
4. The seed cost `D*(w + (t-1)*r)` assumes a seed enters at the first user turn and is read on T−1 requests, while a discovered tool is read on about T/2 (:16 header); consistent between the two seed scripts and the `d·r·((t−1) − t/2)` term.
5. In `regime_bill` the history H is a constant 5,000 tokens and cancels between expose-all and deferral except for the extra request (`expose_all` has no H); no growth of H over the session is modelled [O].
No double counting found: the P·r re-read is counted once (through `reqs`, or the P term in `hstar`) and the H·r re-read once (`per_disc`/`s`).

### Q4. Is B14's counterfactual list-price method a citable precedent for pricing a free or self-hosted model by a named list on a stated date?

[F] Yes, for the method as stated: `pdf-scaffold-2608.08654v1.txt` :251-255 prices "each run at the public per-token list rates published by OpenRouter ... captured on 3 August 2026", applies "one price list uniformly to every cell — including the two locally served models, which are priced counterfactually, as what renting equivalent capacity would cost", bills "Cached input ... as input, with the cache share reported as its own column", reports a 90%-cache-discount sensitivity (Table 4, :762-764), and keeps real spending out of the table (:256). Limits to cite with it: (a) a v1 preprint, no peer-review status shown; (b) it does not say which OpenRouter listing or provider supplied the rate for each locally served model [U]; (c) its models are locally served, not a free hosted university API, so applying it to a free API is an extension [I]; (d) it ignores cache-write premiums by treating cached input as input and gives no write multiplier; (e) it bills only what the paper calls "modelled cost, not a bill". Two further precedents in this batch use the same idea with a dated list: B8 (`v5-asknowuselater-2605.28108.txt` :2508-2511, "per-million-token rates posted on the inference platform at the time of the sweep") and B12 (:151, the cheapest listed provider, snapshots from the Internet Archive). Whether a named list on a stated date is acceptable for the thesis is the human's decision, not an evidence finding.
