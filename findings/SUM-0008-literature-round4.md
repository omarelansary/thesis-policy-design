## Per-source table (fixed questions 1-4)

### 1. TA Terminal Agents Suffice for Enterprise Automation, arxiv-2604.00073
1. Measured: [F] 729 single-session tasks on three platforms (ServiceNow 330, GitLab 192, ERPNext 207; TA:575-578, 863-864); four agent types (tool-use via MCP, web, terminal, hybrid) over 4 backbones in the main table (TA:288-289). Tool-use catalogues: 83 tools ServiceNow, 81 GitLab, 7 ERPNext (TA:291-295). The memory experiment (section 4.2, TA:531-558): a persistent "skills" directory the terminal agent may "store troubleshooting strategies, workflows, and other useful notes" in (TA:533-535), compared with a baseline that "starts fresh every time" (TA:529-530); "We sequentially go over the full dataset once"; "Both configurations use Sonnet 4.6" (TA:535-537). What is stored: [F] "Skills are overwhelmingly procedural, presenting step-by-step recipes for creating or modifying records via the platform API", with "pitfalls and field mappings" (TA:769-773); 38 skill files in all (11 ServiceNow, 2 GitLab, 25 ERPNext) (TA:766-767). It stores procedures and field facts, not tool definitions or tool-selection records. Cross-task: [F] yes, by design: "the skills directory is carried forward by design" (TA:1179); prompt tells the agent "Search it before each task; update it after" (TA:3951) and describes it as "persistent memory across tasks" (TA:3954). Cost: [F] "inference cost, computed from the token usage of the underlying language model" (TA:279-280). Whether cache-read tokens are priced differently is not stated in the parts I read [U]; the appendix on the pricing snapshot says only that tokens are reported instead of dollars in the appendix D re-analysis "without carrying a pricing snapshot" (TA:1915-1917).
2. Decisive sentences: TA:543-545 "On ServiceNow, the agent with memory costs 43.7% less per task on average ($0.44 vs. $0.78), and on ERPNext the reduction is 23.9% ($0.35 vs. $0.46); on GitLab, by contrast, cost rises slightly ($0.31 vs. $0.28)." Success: TA:538-542 ERPNext +5.3pp, ServiceNow +3.4pp, GitLab +1.6pp. GitLab explanation: [F] the authors do not explain the cost rise directly; they say GitLab tasks are "more straightforward API calls that the model can handle from parametric knowledge alone" (TA:541-542), that the agent "writes to its skills directory only three times, producing just two skill files" (TA:551-552), and that overhead is "modest: the agent checks the skills directory in 1-2 calls" (TA:546-548). [O] The 1-2 lookup calls per task is the only stated cost mechanism that could account for a small rise; the text does not link it to the +$0.03. Case study: TA:4281-4283 "5 tool calls at $0.34, while the baseline requires 8 tool calls at $0.51". Reduction on ServiceNow is attributed to "avoiding redundant API exploration" (TA:548).
3. Limits: [F] authors: "Since each platform is traversed once in a fixed order with a single backbone, these magnitudes depend on the sequence encountered... not as calibrated estimates of how much" (TA:556-558). [F] no repeated runs of the memory arm stated; the repeated-run analysis (3 runs) covers other comparisons (TA:1159-1168). [O] Single model (Sonnet 4.6), one pass, one ordering, no seeds for the memory arm in what I read. [O] The baseline is "no memory", not "a shorter tool list" or "documentation"; it is controlled in the sense that the same tasks and model are used, but the comparison is of one cumulative run against another cumulative run, so a lucky early skill affects all later tasks. [O] Tasks are "simple... reachable in a handful of API calls, require little exploration" (TA:850-851); the memory is about API facts (field values), not about which tool to use. [O] Per-task cost in this paper is a token-based total; whether it includes cached-input discounts is not shown in what I read. [O] Tasks are within three known platforms, not a catalogue of hundreds of tools to discover.
4. Relevance: PARTIAL (topic C). It is a cross-task persistent memory with measured per-task cost, in an agent that has a terminal rather than a tool catalogue; what is remembered is procedures and field mappings, so it bears on "exploration cost saved by persisted knowledge" but not on remembering which tools exist or on a discovery channel. The tool-use (MCP) arm with 83/81/7 tools is a separate comparison and has no memory arm in what I read.

### 2. AA AgentAbstain, arxiv-2607.10059
1. Measured: [F] 263 paired tasks (526 tasks) in 42 MCP sandbox environments exposing 541 tools in total, median 12 per environment, range 3-29 (AA:374-379); 17 models in 4 harnesses; each task once per model (AA:395); each harness "exposes the same set of MCP tools" (AA:392-393). The tool set is fixed per episode: "We assume tau is fixed throughout an episode; dynamic tool environments are left to future work" (AA:1645-1646). The agent's action space is a tool call, a clarification request ask(r), or a refusal refuse(rho) (AA:1704-1707). Abstention = "an explicit refuse or ask-clarification at termination" (AA:240-241). Eight scenarios; S5 Insufficient Tool Capability = "Available tools fundamentally cannot achieve the goal; visible from the tool inventory" (AA:286-292), made by removing/transforming a tool in tau (AA:1646-1647, 2211).
2. Search/request channel: [F] none in the sense of our setting. There is no condition where the model can search or request tools from a larger catalogue. The only "request" channel is asking the user a question (ask) or refusing. [O] Tools of kind "search" exist inside environments (AA:2128-2131) but collapse to "lookup" tools of the data kind, not tool-discovery. Abstention rates by model (the closest numbers to "decline to call when nothing fits", only for S5): Table 1 cells are "Paired Accuracy / CAR" (%), by column position S5 is the fifth pair after the model name. Lines: Haiku 4.5 79.5/89.7 (AA:441), Sonnet 4.6 86.1/100.0 (AA:449), Opus 4.7 80.0/100.0 (AA:456), GPT-4o 38.0/47.5 (AA:464), GPT-5 72.8/85.7 (AA:473), GPT-5.1 40.5/46.4 (AA:481), GPT-5.2 54.4/68.3 (AA:489), GPT-5.4 69.5/87.5 (AA:497), GPT-5.5 75.4/77.8 (AA:506), Gemini 3 Flash 50.9/52.4 (AA:515), Gemini 3.1 Pro 96.7/100.0 (AA:523), MiniMax M2.5 67.5/76.3 (AA:532), Kimi K2.5 47.7/75.2 (AA:541), GLM-5 78.8/89.3 (AA:549), DeepSeek V3.2 75.4/85.5 (AA:557), DeepSeek V4 Pro 55.6/57.2 (AA:564), GPT-OSS 120B 72.1/81.7 (AA:573). [O] Table 1 is ragged (several model rows are split across lines differently; the S3/S4 cells wrap), so column assignment is by position and should be re-checked in the image. These are paired accuracies (both the act and the abstain side correct), not the abstain-side rate alone, so they are not "rate of calling a tool when none fits". Aggregates in text: paired accuracy 33.0% (GPT-4o) to 59.5% (Gemini 3.1 Pro), mean 45.7% (AA:408); mean act accuracy 80.6% vs abstain 59.1% (AA:654); S5 paired mean 67%, easiest category (AA:716-720); "capability limitations (S5, S6; mean 61%)" (AA:722-723). Runtime vs query-level: [F] 166 pairs (63%) pre-execution, 97 (37%) runtime (AA:376-378); the authors find phase does not predict difficulty (Wilcoxon p = 0.89, AA:719-720). Post-hoc abstention failure mode (acts first, then says it should not have) is described in the abstract (AA:31-34) and Figure 1.
3. Limits: [F] authors: sandboxes of 3-29 tools; "Real-world deployments often connect agents to dozens of independent systems with hundreds of endpoints... results may not fully transfer" (AA:1576-1580); single-turn, single-run per model (AA:1589-1590, 1593); LLM judge GPT-5.4 with 4 of 200 disagreements with humans (AA:3118-3122). [O] Environments and tasks are LLM-generated (AA:354-355). [O] S5 tool-removal is only one tool in a 3-29 tool environment.
4. Relevance: PARTIAL for topic B only as an indirect indicator; NOT RELEVANT for "use of a search/request channel". It measures, with a visible and complete small tool set, whether models act or stop when the visible tools cannot do the task; it does not give any rate for using a discovery channel nor for inventing a tool.

### 3. CB CostBench, arxiv-2511.02734
1. Measured: [F] travel-planning only, six tasks, atomic tools with random costs "between 15 and 25" and composite tools with cost = sum of components plus Gaussian noise (CB:94-100, 374-375); four blocking events (cost change, ban tool, preference change, remove tools) (CB:344-350); ten LLMs (CB:253); temperature 0.0 (CB:647). Metrics include exact match ratio of the tool-call trajectory, task completion and invalid tool-use (CB:661-677). The costs are abstract numbers attached to tools, given to the agent, and the agent must choose the cheapest sequence; token cost of the agent itself is not priced.
2. Decisive sentences: CB:36-37 "even GPT-5 achieving less than 75% exact match rate on the hardest tasks"; CB:1137-1138 "GPT-5 under the hardest cost-change setting, where its Exact Match falls to merely 34.91%"; CB:1131-1135 under cost change GPT-5 EMR "drops by around 20 percentage points", Gemini-2.5-Pro "almost 40 points"; ban tool "approximately 5-10%" drop (CB:1139-1142).
3. Limits: [F] authors: travel domain only; "simulation abstracts away true API latency, resource consumption, and stochastic failures"; blocking events manually parameterized (CB:1324-1337). [O] The number of test queries per setting not found in the places read [U]. [O] Cost is a number in the tool description, not an observed bill.
4. Relevance: NOT RELEVANT to exposure or discovery cost; PARTIAL only in the narrow sense that it shows models mis-plan over priced tools when prices change mid-episode (planning over priced tools, not pricing of tool exposure). The tool set is small and fully visible; "remove tools" blocks tools after selection and does not test discovery.

### 4. IN INTENT, arxiv-2602.11541
1. Measured: [F] StableToolBench, 765 test instances (IN:626); for each query the official retriever recalls 20 related tools (IN:621-622), each assigned a synthetic per-call price from U(5, 50), budget B = 50 (IN:619-625); two backbones, GPT 4.1 mini and GPT 5 nano (IN:681-684). It prices tool calls (money per invocation), not tokens or definitions: "c(j) denotes the financial cost incurred by a single invocation of the tool" (IN:234-235). Token consumption is reported only as a ratio to the RAW baseline (IN:676-678). The market snapshot is "the subset of tools that are accessible at that moment (determined by retrieval mechanisms, user permissions, or provider status)" (IN:228-230), i.e. retrieval is upstream and fixed to 20 tools per task.
2. Decisive numbers (GPT 4.1 mini, Table 1, flattened; by column order PR, OR, WR, FR, AC, AP, Time, Lat., Tok.): Raw PR 19.1, FR 34.5, AC 102.1 (IN:741-746); Prompt PR 30.9, FR 67.2 (IN:751,754), text "violates budgets in a substantial fraction of tasks (a notable 32.8% for GPT 4.1 mini)" (IN:689-691); INTENT PR 63.8, FR 100.0, Tok 1.70x (IN:802,805,810). GPT 5 nano: Raw PR 18.1, FR 24.7 (IN:814,817); Prompt PR 48.5, FR 87.6 (IN:824,827); INTENT PR 76.0, FR 100 (IN:875,878). Price perturbation: PROMPT "highly sensitive to these price perturbations" (IN:945-947).
3. Limits: [F] the MCO oracle "relies on a single sample estimate" (IN:383). [O] Prices are synthetic and uniform random, not tied to any tool's real cost or to tokens; tool outputs come from a cache-based fallback (IN:615-617); LLM-as-judge scoring (IN:661-663); I did not find a statement of run counts or variance [U] in the parts read.
4. Relevance: NOT RELEVANT to exposure or discovery cost as such; PARTIAL as evidence that, when per-call prices are shown to a model in the prompt, it still overspends (Prompt FR 67.2 and 87.6). It plans over a priced set of 20 pre-retrieved tools; it does not price tool definitions, does not model a bill for a search channel, and does not test finding tools the model cannot see.
