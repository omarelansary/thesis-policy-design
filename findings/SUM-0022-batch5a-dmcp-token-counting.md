## Points where this differs from current wording [O]

- e9.1 calls 292k "the measured catalog size"; the governing S4G brief says "by the repo's estimate". The stored doc gives no procedure for either word.
- The paper's wording "flat exposes all 1,168 schemas at once" is not qualified by the stub behaviour in pools.py (tools outside the reference trace get `{"type": "object"}`).
- The pricing module has no cache discount, so any "bill" from this vehicle is prompt + completion tokens times a pinned two-rate table.
- The matrix cell is described in e9.1 Method as a "reproduction check", while the Reconciliation section treats the 36.7 vs 30.7 gap as two different task draws.
