## Which components depend on the turn and which on the session [I]
Steward interpretation from Tables 1-3; the vendor pages do not use the words "turn" and "session" for this split (except Managed Agents "session runtime").

Per request (turn):
- fresh input, output, reasoning/thinking tokens (Gemini: inside output; A, O [U]), cache write, cache read. "Each request is priced on its own" (A-price L222, stated for the Haiku 5.5 tier).
- provider-added tool-use system prompt (A-price L240), tool definitions in `tools`, and `tool_use` / `tool_result` blocks re-sent as part of the prompt (A-price L226-238).
- request-level multipliers: batch, fast/priority, long-context step, region uplift, tokenizer.
- per-call server tools: web search ($10 per 1,000 for A and O; $14 per 1,000 beyond a free allowance for G), O file-search calls.

Session (lifetime, gap, cold start):
- cache lifetime and refresh: a prefix is a live entry only while requests keep arriving within the TTL (A 5m or 1h; O 30m on GPT-5.6+; B 5m or 1h). That a gap longer than the TTL turns the next request into a write instead of a read follows from "Cache valid for 5 minutes" (A-price L148) and "If no cache hits occur within the TTL window, your cache expires" (B-cache); no stored page states the gap cost in these words [I].
- cold start: the first request of a session writes the prefix (A 1.25x or 2x; O 1.25x on GPT-5.6+; earlier O models no write fee; G implicit no write line).
- storage over time: Gemini explicit cache bills per million tokens per hour (G-price L1094; EXT-0089). No hourly cache-storage line found in A-price or O-price. Session-time items: Anthropic Managed Agents `running` hours ($0.08), code-execution container-hours, OpenAI container sessions per 20 minutes and file-search storage per GB-day.
- tool-set stability across a session: stable `tools` keep the cache; changed definitions invalidate it (EXT-0158, O-cache); vendor-documented deferral/append keeps the prefix, so a tool loaded mid-session adds later per-turn input but does not by documented design invalidate the cache [I from EXT-0158 and O-cache].
- reuse across sessions: OpenAI caches "are not shared across organizations" (O-cache, "Cache location"); Anthropic cross-session sharing is not stated in the passages read [U].

## Conflicting or limiting passages kept on purpose
- The cache-read multiplier is not one number: A 0.1x (0.05x, 0.025x on newer models); O 0.1x (0.05x on GPT-6.1 Sol); older O models have model-specific ratios (gpt-4.1 $0.50 vs $2.00 = 0.25x, O-price L54; gpt-4o 0.5x, L57).
- Cache write is not always a surcharge: none on older OpenAI models; 1.25x to 2x on Anthropic. Anthropic states the break-even: "caching pays off after one cache read for the 5-minute duration ..., or after two cache reads for the 1-hour duration" (A-price L152). OpenAI warns of a "minimum cacheable length cost trap" (O-cache, "Escape the minimum cacheable length cost trap").
- Vendor claims about performance in these pages (Anthropic programmatic calling, EXT-0183; OpenAI tool search "may help reduce overall token usage and cost", r4-openai-tool-search L5) are not established here.
- Several price levels have since-changed or time-limited values, so the level of any component should not be hard-coded; the structure (which lines exist) is what the pages support.
