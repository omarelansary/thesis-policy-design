# Title: The break-even hit rate h* omits the longer carry of needed seeds and charges an avoided search as a separate request, so it is too low and favours memory-informed offering

**Objection.** [O, hand arithmetic; no code-execution tool was available] D-02 sets saving = h*m*(H*r + o*q) and cost = (1-h)*m*d*(W+(T-1)*r), with the comment "the appended definition is paid in both cases" (`memory_seed.py:8-12`). Two terms are wrong or unstated.
(1) A seeded tool that is needed is carried for T-1 reads from the start of the session; the same tool discovered mid-session is carried for about T/2 reads (the lead's own assumption in `regime_bill.py:15-16`, "read on about half the remaining requests"). The difference d*((T-1) - T/2)*r per needed seed is a cost of seeding that D-02 omits.
(2) H*r charges the avoided search as an extra request re-reading the history. With the vendor search that V5 adopts (V5-R04) the search is in the same response (see CH-0076), so the saving per avoided search is o*q only (750 instead of 1,250 fresh-token equivalents).
Hand values of h* at r = 0.1, d = 250, o*q = 750, H*r = 500 (the calc prints 0.22 / 0.30 / 0.45 / 0.69 for T = 3 / 10 / 30 / 100): with (1) only 0.23 / 0.32 / 0.53 / 0.99; with (2) only 0.33 / 0.42 / 0.58 / 0.79; with both 0.33 / 0.45 / 0.72 and no break-even at T = 100 (the saving per needed seed, 750 - 1,225, is negative). The statements "about 0.22-0.30 for 3-10 requests, up to 0.69 for 100" (`04` sections 1, 5; DPR-0007 falsifier (a); HYP-0016, HYP-0017) are therefore low, and the direction favours the recommended design. Also: no materiality is given; at h = 0.5, m = 5, T = 10 the net saving by the lead's formula is 3,125 - 1,344 = about 1,800 equivalents (about 300 with both corrections), less than one fresh send of the 5,000-token history.

**Evidence.** `design/package-v5/calc/memory_seed.py:8-12, :21-25`; `calc/regime_bill.py:15-16, :26-30`; `calc/memory_seed.stdout.txt:1-5`; `L/v5-anthropic-tool-search-20261022.md:601-652`; DPR-0006:19. I could not run code, so these numbers are my own.

**What would resolve it.** Rerun `memory_seed.py` with (1) the extra carry for needed seeds, (2) a switch for in-response versus separate-request search, and (3) the per-session total bill so the net saving is a share of it; publish h* for both switches; restate every place the 0.22-0.30 / 0.69 figures appear (04 sections 1 and 5, DPR-0007, HYP-0016, HYP-0017, DPR-0008 section 4). Define the P1 threshold as h* recomputed from observed T, H and mechanism.
