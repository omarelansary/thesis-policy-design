# Title: Figure 1 has a phantom "ask" edge in the no-interface arm, an orphan turn limit, an undefined unit for the turn limit, and no edge for context overflow or non-conforming agent outputs

**Grade: SERIOUS.** (design/package-v4/02 section 2, Figure 1 and reading notes 1-3; the same figure is in the brief.)

**Objection.** I traced each configuration the text says Figure 1 expresses.
1. **No-interface (static core) arm.** Note 1 says "With no interface in `c`, B always answers 'no'". That requires the model to be able to take the exit "needed capability not visible: model writes a request" although no discovery tool exists. In real agent APIs a request for a capability is a call to a visible discovery tool; without one the model finishes (possibly with a wrong or partial answer) or hallucinates a tool call. The drawn arm therefore either (a) adds a scripted "unavailable" turn that the real no-interface arm would not have (extra tokens, extra calls against the turn limit), or (b) never uses the edge, in which case the drawing is not what is run. The token cost of that arm is defined only once one of the two is chosen. Also undefined: whether the scope statement is shown in that arm (P0 says "metadata-only scope statement", which invites requests that cannot be served).
2. **"Ask" versus "call".** In the vendor form the discovery interface is itself a visible tool; "ask" is a call to it. The figure routes "call a visible tool" to R (result, no definitions appended) and "ask" to B/P2. The distinction therefore rests on tool identity, not on the model's judgement, and should be stated. Same for the navigated hierarchy: list/describe/execute are visible meta-tools (EXT-0023 lines 54-60), so "describe" and "execute" are ordinary calls that return text; P2's "return the next level of the hierarchy" is the list call, and no definition is "appended" at all.
3. **Turn limit X is an orphan node** (no incoming edge; Mermaid `X --> E` only). The text (note 2) says only the turn limit ends a trajectory otherwise, and that "unavailable" replies continue the loop. Whether an "ask" that returns "unavailable", a failed discovery, or a P3 evaluation counts as a turn is not stated. If X counts tool calls only (the closest vehicle's budget is "12 tool calls per task", EXT-0084 line 96; EXT-0042 distinguishes "successful tool calls" from "total calls incl. failed"), the loop A -> B(no) -> A is not bounded by X; if X counts every agent step, discovery-heavy arms lose usable steps and the success side is changed by the mechanism whose tokens the criterion counts. Either way the sentence "Denied or failed discoveries are counted as tokens like any other call" does not define the trajectory.
4. **Missing exits.** (a) Context overflow: for expose-all near `n_fit`, long tool results can overflow the window mid-trajectory; Figure 2 Q1 asks whether "the whole catalogue plus working context fit" but Figure 1 has no overflow edge and X is the only system ending. (b) Output that is none of call / ask / finish: a call to a non-visible or misspelled tool, malformed arguments, several calls in one step, text-only reply that is not a finish. Where these go (to R as an error, to B as an ask, to End) changes cost and success.
5. **Duplicate retrieval.** P2 "append top-kappa definitions" does not say the ranking excludes tools already visible (core, P1). If it does not, kappa slots are wasted and counted; if it does, the ranked set depends on the visible set, which is runtime state.

**Evidence.** Figure 1 and notes 1-3 (02 lines 11-39). EXT-0023 lines 54-60 (list_tools, describe_tools, execute_tool as meta-tools). EXT-0084 line 96 ("Budget 12 tool calls per task"), EXT-0042 lines 26-39. [U] whether discovery calls count against the vehicle's 12-call budget; not found in the windows read.

**What would resolve it.** Say what "ask" is operationally (call of the discovery tool); define the no-interface arm as "no discovery tool and no scope statement" or accept the scripted reply and cost it; connect X to the agent node and state its unit and whether discovery and denied calls count; add overflow and non-conforming-output edges (or state they are folded into End with a defined cost); state the exclusion rule of P2.

**Response (lead).** ACCEPT: ask = call of the discovery tool, which exists only if the interface is in `c` (no phantom edge); call limit counts every model call incl. denied discoveries; overflow and non-conforming output end the task (X); P2 returns only definitions not already visible. [rounds used: 1 of 2]

**Round 2 (challenger, 2026-10-19): CLOSED, minor residuals.** Items 1, 2, 3 (bounded by the call limit as defined), 5 resolved. Residual R9: (a) X is still drawn with no incoming edge (acceptable as a global rule, but say so); (b) "non-conforming output ends the task as a failure" is a rule of this design, not of the vehicle: in replay a call with no recorded counterpart returns an error and the run continues (EXT-0079 lines 55-58), so the rule and the vehicle must be reconciled or the difference reported; (c) 02 section 2 says two nodes read run-time state (B, P3); P3f, P2 (the visible set) and X also do, all class R. Plus R1 (CH-0045). Vehicles whose budget counts only tool calls are flagged in note 3, which is the right place.

**Outcome.** resolved (conceded) with minor residual R9.
