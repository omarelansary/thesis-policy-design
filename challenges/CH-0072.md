# Title: The two new pilot-2 arms use a "spurious call" definition that is the opposite of correct behaviour in our setting

**Grade: SERIOUS.**

**Objection.**
1. In both sources any tool call is a failure (NTA: no tools exist; irrelevance: the tools shown cannot help). In our setting, when no visible tool fits and the target tool exists in the hidden catalogue, a **search call is the correct action**; it is spurious only if the target does not exist. `05` section 4 says "false-positive calls" with these rates as comparison, without defining the counted event. If "call" means any tool call, a search-equipped model is penalised for correct behaviour; if it means a call to a *domain* tool, the sources' numbers do not carry over (a search channel changes what a "call" is). The arm needs a pre-stated event: e.g. invoking a domain tool that does not exist / is irrelevant, versus issuing a search, versus answering directly, counted separately.
2. **No-tool-available arm as written is two arms.** (a) Nonexistent target with a search channel: tests search-and-fail behaviour (rounds wasted, how many searches before giving up), for which the Reasoning Trap has no analogue (its NTA has no channel and the user names the tool; CH-0069). (b) No channel at all: that is the source's setting, but it is not a cell of our policy comparison. Both cannot share one "published prior".
3. **Irrelevant-tools-visible arm:** in a search-equipped policy the search tool is itself a visible tool, and the "core" tools may be irrelevant to the task; so this arm is the default state of the experiment, not an extra arm. What is new is *irrelevant core + nonexistent target*, which neither source tests.
4. **Model list rule** ("at least one model with a published rate in each"): the closed frontier models with irrelevance rates (GPT-5.2, Haiku 4.5, Gemini 3 Pro, arxiv-2604.19749.txt:408-413) have no NTA/DT rate in the other paper; the models with both (Qwen2.5-7B, Llama3.1-8B, Qwen3-8B, DeepSeek-R1) are small or open. The rule cannot be satisfied by a strong closed model for both arms. Version drift (Qwen3-8B mode, prompt) makes the "published rate" a check of the harness at best.
5. Judge-based scoring (DeepSeek-R1 as judge in the Reasoning Trap, :1478) would have to be replaced by rule-based event counting in our pilot to be cheap and auditable [I].

**Evidence.** arxiv-2510.22977.txt:215-237, 1241-1256, 1478, 1519; arxiv-2604.19749.txt:408-413, 455-467.

**What would resolve it.** Definitions only (counted events, arm names) can be fixed now; the size of any false-positive rate for a search-equipped strong model needs data.
