# Title: The cards are called version-locked but most rows have no code or data pin, and several criticisms were measured on versions other than the one locked

**Objection.**
1. *Lock is claimed, not met.* The s5 heading says "version-locked"; s1.1 and CC3 require paper version, repository commit, dataset revision and date read. Rows with a pin: MCP-Atlas (HF sha, repo commit), LiveMCPBench (HF sha), Momento (HF sha), VitaBench 2.0 (HF sha), ATRBench (repo commit, via I2), tau2-bench (v2.0.0). Rows without: BFCL ("no commit pinned"), AppWorld ("repo main"), MCPMark (paper v1; "Verified" is current, no commit), MCP-Universe, MCP-Bench, MCPVerse (paper version and "data v1.1"), Toolathlon (paper v2 and a "Verified" release date, no commit), TheMCPCompany, ToolSandbox (repository page not stored, SUM-0071 B21), ETAPP, DolphinBench, MPT (anonymous repository, no revision). CC3 is a later check (s10 is empty), but the heading already asserts the lock.
2. *Criticism and locked version differ.* tau2-bench is locked at v2.0.0 (2026-10-19), which changed the scoring and the NL judge, "not comparable with 1.x", and fixed 75+ tasks over earlier releases (SUM-0070 B16, B17). The Tool-Veritas audit (11 of 112 Retail disagreements) was submitted 2026-06-30 (SUM-0077 E1), before v2.0.0; the audited version is not stated in what I read. MCPMark's 22% flip rate is computed on deprecated v1-0905 logs, "Verified is now the default" (SUM-0068 A23; the row states it). MCP-Atlas's April 2026 update changed the judge and replaced the 20-turn limit by a 100-call budget; the audit's 12-of-89 figure came from the audit's own MiniMax-M2.7 run; the judge version used is not stated in what I read. BFCL: Epoch reviewed on 2026-09-10; the locked changelog is read at 2026-11-01. A reader will read s6 as describing the s5 object; for tau2 and MCPMark it is not shown to.
3. *Staleness is two-way.* A defect list for an earlier release may be partly fixed in the locked one (tau2 v2.0.0, tau2-bench-verified, BFCL ground-truth fixes, Toolathlon-Verified), and a fix may introduce new defects (tau2 #672, #710 open on the locked release).

**Evidence.** `17` s5 L91-117, s6 L126-151; SUM-0070 B4-B5, B16-B17; SUM-0077 E1, E8, E9, E10, E12; SUM-0068 A23; SUM-0067 A9; SUM-0071 B21.
[F] the dates. [I] that the audited tau2 release predates v2.0.0 (I did not read the audit's version statement; SUM-0077 E3 does not give one). [U] the audited version of each benchmark.

**What would resolve it.** Change the heading to "pins recorded where found" and add a "pin" column with "not pinned" visible; in s6 add a column "version the criticism applies to" and a note where it is older than the locked version; do not combine audit rates with the locked-version card without it.
