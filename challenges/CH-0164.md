# Title: Licence statements in sections 7 and 9 are inconsistent with each other and with the stored sources

**Objection.**
1. *Captured MCP definitions.* s7 P5 #1 gives "real MCP schemas; MIT/CC-BY-4.0" for definitions captured from the MCP-Atlas sandbox's 20 keyless servers. MIT is Scale's code licence and CC-BY-4.0 its dataset licence (I1 1h). The schemas come from 20 third-party server packages (arxiv, context7, ddg-search, desktop-commander, fetch, git, whois ...; I1 1b), each with its own licence, which nobody read, and I1 1h found "no image terms". The H4 test in s4 ("local research use permitted and no redistribution of the material needed") has not been applied to them. If the captured schemas are quoted in the thesis or stored in the pushed repository, the licences matter.
2. *MPT.* s7 P1 rejects MPT for a "non-commercial licence". CH-0157 point 2 said the MPT data licence is not one licence (the paper is CC BY 4.0; the sources are SGD CC BY-SA 4.0, DuRecDial 2.0 CC BY-NC-SA 4.0, HomeBench no licence file; SUM-0072 C3). The s5 correction answers by saying "MPT's CC BY-NC-SA 4.0 is in the stored README (j23)", which restates the repository's statement and does not address the mixed sources. Also a non-commercial licence does not bar a master's thesis; the register treats it as a reason to reject without saying why it matters here.
3. *"Not usable without one".* s9 item 6 says Toolathlon and TheMCPCompany "have no licence file (not usable without one)". Absence of a licence file is a fact (I1 4, 5); "not usable" is a legal conclusion the register cannot support. The register also lists Toolathlon local-only as P2 rank 3 "only if its licence question is settled", so it is treated as both unusable and a candidate. Say "licence status unknown; ask the authors" once and apply it everywhere.
4. *VitaBench.* s7 P1 #2 says "MIT"; the card (L137) says "MIT (code), data not stated", and I2 item 2 says no licence in the API response. The data is what P1 would use.
5. *AppWorld derived material.* s9 item 6 says AppWorld's data must stay out of the repository. The README request covers "code or data extracted or derived from the .bundle files" (L338); V5 request logs, captured prompts and any appendix of the thesis would contain API documentation text. s9 should state that logs holding such text are excluded from the pushed repository too.

**Evidence.** [F] I1 1b, 1h, 4, 5; I2 items 2, 4; SUM-0072 C3; `v5-bm-b14` L338; register L137, L182, L195, L197, L202, L256. [I] that the licence of captured definitions is the servers', not Scale's.

**What would resolve it.** Correct the P5 licence text; apply one wording for "licence not established" across s7 and s9; restate MPT's rejection with the mixed-source fact or on construct grounds only; fix VitaBench "MIT"; extend the AppWorld caution to logs.
