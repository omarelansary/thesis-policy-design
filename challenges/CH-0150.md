# Title: Task counts in the cards are not the number of independent units; R5 names clustering and the cards do not record the cluster unit

**Objection.** R5 cites Miller (clustered standard errors "up to 3X" in a reading-comprehension example) and Kapoor (error bars), and s1.2 promises that the register will report "the pool available for a held-out set and the difference resolvable at that size". The cards report counts as if tasks were independent: 108 (Toolathlon), 127 tasks over 5 servers and 38 initial states (MCPMark), 101, 104, 231, 500 public tasks over 36 servers (MCP-Atlas), 568/284 sessions over 20 personas, 771 subtasks over 56 users. The cluster unit (server, application, initial state, persona, user, shared database) is not a field. The stored evidence shows why it matters for V5's own sample: MCPMark #272 computes that two single runs must differ by about 11 points per service (14.9 on Postgres) before the gap exceeds repetition noise, "with 21 to 30 tasks per service, most of this is sample size" (SUM-0068 A23); the paper's Table 2 prints "±0.96" to "±2.05" beside the open models' pass@1 (SUM-0068 A25; whether these are standard errors or standard deviations I did not establish), a spread far below the issue's 11-point bound, which suggests the two measure different things. Tasks within a server share state and tools; write tools act on shared SaaS state in MCP-Atlas (issue #71).
Second, R5 and s1.2 say adequacy needs a target difference and that the human decided there is no margin, so the register "reports, per candidate, ... the difference resolvable". There is no stored source giving a sample size for a bill-ratio outcome (R5 itself, "[U]"), and the one numeric anchor in the methods set (Miller: at least 1,000 questions, "fictional" parameters, SUM-0066 M24) is not mentioned in R5. The register should say which of the two outcomes (accuracy difference, bill ratio) the "resolvable difference" refers to, because the bill ratio is nearly deterministic given the requests made (`05` s1) while accuracy is not; they need different sample sizes and the pool needed is set by the larger.

**Evidence.** `17` s3 R5 L68; s1.2 L19; s5 L96-117; SUM-0068 A23, A25; SUM-0066 M21, M24; SUM-0078 E26; `05` s1.
[F] numbers and quotes. [I] the cluster structure for each benchmark (not read from data for most). [U] the intra-cluster correlation for any candidate.

**What would resolve it.** Add to every card "cluster unit and number of clusters" and "tasks per cluster"; compute the resolvable accuracy difference with and without a cluster adjustment using a stated design effect range (the range as an assumption, not a measurement); state separately for accuracy and for bill ratio; mention the Miller 1,000-question example with its limit.
