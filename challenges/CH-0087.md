# Title: P1 cannot end the question "does memory-informed offering pay for returning users" with the stated vehicle and size

**Objection.** (a) The hit rate h that P1 measures is set by how the experimenter pairs tasks for one simulated user; a benchmark with a user simulator does not produce the overlap of real returning users, so P1 estimates h of a construction. The falsifier "share stays below h*" can therefore be passed or failed by design of the pairs, and the hypothesis text speaks of "returning users". (b) Catalogue size: tau2-bench is "the closest reusable vehicle" (`05` P1; `03` row 104), but `03` does not state its tool count; if its domains are small, V5-R's own S2 chooses expose-all there and M2 never runs; enlarging the catalogue with added tools sets h again. [U] I did not find the count in the stored pages. (c) Size: about 20 pairs; the net saving that D-02 computes is of the order of a few hundred to two thousand token-equivalents per session (CH-0075), small against the variation of a multi-request session bill, so a bill difference is not detectable at this n; only h can be counted, and h alone does not show a bill benefit. (d) A "hit" must be defined as a seeded tool that is non-core and is called; otherwise tools already in the usage-derived core inflate h. (e) The threshold h* must be recomputed from the observed T, H and search mechanism, not read from the lead's table (CH-0075, CH-0076). (f) The falsifier is one-sided: h < h* drops the stage, h > h* does not establish that accuracy (stale or anchoring seeds) is nearly the same; HYP-0017's text mentions stale-memory failures but the falsifier does not carry them. (g) HYP-0016 (proposer) and HYP-0017 (lead) measure the same quantity with opposite polarity; counting both would double one result.

**Evidence.** `05-poc-loop-and-e2e.md` section 1 row P1; `hypotheses/HYP-0017.md` falsifier, HYP-0016 falsifier; `03-reuse-map.md:104, :108` (a vehicle with sessions, a gap, a large catalogue and cache fields: NONE FOUND); `calc/memory_seed.py`; `04-design.md` section 5 (M2 row).

**What would resolve it.** State what population of returning users P1 stands for, or restrict the claim to "h under constructed overlap p" and vary p; state the catalogue size of the vehicle and that it is in R-mid; define the hit; give the quantity compared (bill difference with its spread, h, accuracy) and say what P1 can end (dropping M2 when h is far below the corrected h*; nothing positive).
