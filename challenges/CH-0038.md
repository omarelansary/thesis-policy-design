# Title: correction 4 overstates "the reference cannot run", gives G the same missing anchor it faults C-A for, and overlooks estimators that the record does not exclude

**Grade: SERIOUS (the direction of the conclusion for the 10,000-tool example may stand; the argument and the asymmetry do not).**

**Objection.** (design/package-v3/01-errata-AUTH-005.md section 4; 03-comparison.md section 1 item 1 and table row "Applicable at large catalogue".)
1. **Scope of "cannot run".** The cited passage is S4G line 28: the flat catalogue (about 292k tokens by the repository's estimate) is "over the context of 2 of the 4 matrix models"; "the all-tools baseline exists only for long-context models". So on the closest vehicle the reference *can* run for two of four models. The errata generalises to "the reference run cannot be made". For the supervisor's 10,000-tool illustration the claim may hold for all current models [U], but that is a statement about context length versus a hypothetical catalogue, not about the vehicle. Say: "model-dependent; true for any model whose window is below catalogue plus working context".
2. **G has the same anchor problem and the table hides it.** F1 needs `Y_ref`. Where the reference cannot run, G's D1 says "claims relative to a named substitute" and package A (A7, line 60) already says the substitute weakens the claim and "a gold-derived pool is weaker and favours restriction". Noninferiority to a substitute that is itself a restricted arm is not "preserving end-to-end success" in the sense of AUTH-006. 03's row "Applicable at large catalogue: G yes, C-A no as specified" compares G *with the core skipped* to C-A *as specified*. C-A with its core stage skipped is search-only, which is one of G's arms and the vendor-deferral design. At large catalogue the two share the identical missing reference; G is applicable only in the sense that it declares weaker claims. The table should either give C-A the same treatment or drop the asymmetry.
3. **If the substitute is picked from the arms on dev data** (e.g. the arm with the highest dev success), the reference is a maximum of noisy estimates and the later noninferiority test is biased in favour of the substitute's neighbours (winner's curse). No rule for naming the substitute is given.
4. **"No estimator" is scoped to the record, which is fair, but three families are not considered and the errata should list them as unevaluated, not as absent:** (a) *labelled need on a disjoint split.* The v2 runtime table treats annotation-derived `p_t` as a leakage route (class P at runtime); as an **offline, disjoint-split** estimate the same annotation is class D. The errata's own "minimal missing decision" (labelled usage that is not the evaluation set) is exactly this; but it is called a missing decision, whereas a benchmark with gold tool sets and a train/dev/test split already provides it for that vehicle (limits: gold sets are annotation, not agent need). (b) *Group-level need.* `p_g` over namespaces or servers has far fewer parameters than `p_t` and is estimable with the same `N`; it changes the object (group core) but not the need for a reference run. (c) *Unseen-mass estimators* (Good-Turing and relatives) bound the total probability of never-observed tools under an iid-task assumption, which is the quantity CH-0036 point 5 shows the per-tool sum cannot give. I list these as **what would be checked**, not as a design; I have not verified their suitability and no search is authorised.
5. **The consequence "C-A cannot be the principal proposal" rests only on this regime.** For catalogues in the regime where the reference runs, A1 applies; the question "which regime is the thesis about" is the human's (Q1 and the thesis question are unset). The errata should say "not the principal proposal *if the thesis is about catalogues beyond the window*".

**Evidence.** `evidence/governing/stage-reports/S4G-SELECTION-READY-BRIEF-20261015.md` line 28 (read); `design/package/A-problem-and-objective.md` line 60 (read); 02 D1 and 03 table (read). Not checked: any context-window figure outside the vehicle's four models.

**What would resolve it.** Edit the scope sentence; treat C-A-with-core-skipped and G-with-core-skipped symmetrically in 03; state how the substitute is named and why it is not selected by the same data; list (a)-(c) as unevaluated estimators. An experiment that would resolve (a): estimate `p_t` from the disjoint annotated split of a vehicle, compare with `p_t` from reference runs where the reference fits (a smoke execution is not authorised).
