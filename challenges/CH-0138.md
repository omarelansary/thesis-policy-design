# Title: Five statements go slightly beyond the cited steward verdicts

**Objection.** (1) s4.7 and s5: "memory methods used 16% to 264% more tokens than the base agent" (D25). SUM-0062 D25: the 264% is BM25 (202,966 against 55,787), a retrieval baseline, as is Qwen3-Emb-4B; memory systems in the list range from +16% (MemOS) to about +225% (A-MEM, 181,298); the "no-memory" identity of DeepSeek-V3.2 is the scout's reading (s5 says so, s4.7 does not); and the "fall below no-memory" finding is about success at 128K, not tokens. s5 repeats "16% to 264%" as the correction.
(2) s4.4: "Copilot's 13 core tools chosen from usage statistics aggregated over users (A21)". SUM-0063 A21 line 92: "tool usage statistics and performance data"; the source population "not stated". "Aggregated over users" is an inference and is used again in PL-5.
(3) s4.3: "extraction then consolidation by a smaller model" (B10). SUM-0058 B10: Phase 1 uses the `default` model, Phase 2 `smol`; 12 h and 30 days are defaults of `minRolloutIdleHours` and `maxRolloutAgeDays`.
(4) s4.2: E22 "tools named in the file were used about 1.6 times per instance" is `uv` (a specific tool); repository-specific tools 2.5 against under 0.05 (SUM-0063). The context files are repository instruction files on Python tasks, not seed lists; developer-written files raised success 2.4% (p = 21%), not significant, and significantly outperformed generated ones (p = 3.8%) while raising steps by 3.34 and cost by up to 19%. The record gives only the generated-file half.
(5) s4.4: ETAPP (E27) "injects only the needed per-user preference categories": SUM-0063 E27: scores for "Needed" against "All" are mixed (4.16 against 4.09, 3.73 against 3.80, 1.76 against 1.62) and tokens are counted with a Llama-3.1 tokenizer on a data subset; the 2,393 against 3,444 token saving is real, the quality effect is flat or mixed.

**Evidence.** SUM-0062 D25; SUM-0063 A21, E22, E27; SUM-0058 B10.
