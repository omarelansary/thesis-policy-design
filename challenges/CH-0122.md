# Title: The absence statements carry the headline conclusions, but "the places searched" are not recorded, and the steward's own caveats on what was not stored were dropped

**Objection.** `14` s1 says the scouts' reports "are in the lead session only" and s5 says they are "not stored as files". Yet s3 rests key results on absence: "Validation-triggered schema expansion was not found in the places searched" (bold), "No stored page defines 'churn'", "No stored page shows eviction improving accuracy or cost", "No checked source prices the extra request ... together", "No checked paper reports the cost of generating the enriched text". Same defect as CH-0112 in RV-0024: no query log, so the reader cannot tell which places were searched.
(a) The EX-5 bullet gives no places at all. Scout task 3 listed the topics, but the queries run (required by the prompt, item 3) are not in the record.
(b) SUM-0049 lists what was not stored and so could not be checked, which bears directly on the BR-1 absence: "the two GitHub issue reports (anecdotal) and the BFCL multi-turn categories. A conclusion on how real agents behave when tools are removed mid-session would have needed them", and the Anthropic pages "Tool use with prompt caching" and "Mid-conversation system messages and tool changes" (Y15 note, last section). `14` s3 BR-1 drops that list; the unstored Anthropic page is the one that would say what happens to the cache when an appended tool is removed.
(c) "MCP-Zero uses dense only (Z19)" is written as a positive fact. SUM-0055: the support is "BM25 has zero matches in the file" and "rerank only in the bibliography"; it "is not an explicit statement that none is used". Same for "A no-match threshold exists ... only after calibration" (Z14), which holds for semantic-router's documentation, not for threshold-based abstention generally.
(d) "LiteLLM's tool-search page lists Anthropic-family providers only (X7, an absence in two stored pages)" is correctly flagged as absence; but the sentence sits in a list of "not usable as products on the university API", which turns an absence into a negative usability claim.

**Evidence.** `14` s1 row 1, s3, s5; SUM-0049 closing section and BR-1 "Not stored, not checked"; SUM-0055 Z19; SUM-0050 X7 ("search covered these two files only").

**What would resolve it.** Store the scouts' queries per task (the reports, or the "what you looked for" sections), cite them next to each absence; copy the SUM-0049 not-stored list into BR-1; word Z19 as "the stored MCP-Zero paper names dense retrieval only; no BM25 or reranker was found by grep"; word (d) as "not shown to be usable".
