# Title: KAIST measures abstention when only a wrong-but-similar tool is visible; it is not a prior against search initiation

**Grade: SERIOUS (05 section 2.1 draws a design-relevant "prior" from it).**

**Objection.**
1. `05` section 2.1: "KAIST suggests a prior against assuming initiation: models often attempt tools when the right one is missing." There is no search or ask channel in KAIST's setup. The implicit-variant prompt offers only "call an API or not" (steward: K:2307-2322; I did not re-read Fig. 29). A model that attempts a visible tool when none fits is making the only move the setup allows; that says nothing about whether it would use a search tool if given one. The construct is **false-positive tool calling**, not failure to search.
2. The "absent" condition is a *replacement with a similar irrelevant API* (the paper contrasts itself with work that "overlooked situations with similar but incorrect tools", K:122-124, 131-132; construction K:150-156). That is a lure, not an absent tool in a large catalogue the model cannot see.
3. The strong-model numbers in the prompted setting are high: API replacement on API-Bank F1 0-shot GPT-4 87.56, GPT-4o 86.23, GPT-4o-mini 88.41 (K:365-377; column order from the steward, consistent with the text "88.82 and 87.94" accuracies at K:584-586). "Often struggle" (abstract, K:27-30) rests mostly on small open models and on Utterance Removal (the "5.41%" at K:593-594 is utterance removal on ToolBench, not tool absence). `05`'s one-line summary "even strong models often attempt a tool when the correct tool is unavailable" is carried over from the abstract and is stronger than the strong-model F1 values for API replacement.
4. The implicit variant (the nearest thing to "unprompted") is on **3 models, one dataset** (K:781). GPT-4 F1 falls from 87.56 to 77.18 for API replacement (K:784-785; accuracy 80.50, K:732), a ten-point drop but not a collapse (F1 is not recall; the recall of "abstain" is not in the text I read), and the utterance-removal F1 barely moves (89.27 -> 86.75). The authors' own reading is that **an explicit feasibility question improves recognition** (K:786-790), which supports "prompt-dependent", not "prior against".
5. [I] If anything KAIST is evidence that when asked, strong models do recognise an unsuitable tool list; the open issue is whether the model asks itself.

**Evidence.** `evidence/literature-20261019/arxiv-2406.12307.txt` lines 13-43, 118-137, 340-390, 470-490, 584-594, 711-790. Verified: 87.56, 89.27, 77.18, 86.75, 5.41 are in the text as `05` and SUM-0005 report them. Not verified: Fig. 29 prompt; the model order of table columns (inferred).

**What would resolve it.** In `05`: state that KAIST has no search channel and a lure-style absence, report both prompted and implicit numbers, and drop "prior against assuming initiation" or relabel it [S]. State what result would move the prior: a study with a search channel and an absent target (see CH-0067 queries).
