# Title: "The pattern (append at the end, never edit the tools array) is copyable" has no stored client-side implementation on Chat Completions behind it, and proposal (d) generalises a vendor sentence the human's own probe qualifies

**Objection.**
(a) The pattern is vendor server-side machinery. Anthropic: "You still send every tool's full definition in the tools array on every request, including the deferred ones", with the cache kept because a `tool_reference` block is appended and "the prefix is untouched" (SUM-0049 Y15; `v5-xp-anthropic-tool-search-doc.txt` L244, L258). OpenAI: discovered tools "are injected at the end of the context window" by the platform (Y3). Pydantic AI says a mid-run tool is the exception "on OpenAI Responses and Anthropic, which receive it outside tools[]" (`v5-xp-pydantic-tools-advanced.txt` L988), and that on Chat Completions and OpenAI-compatible endpoints the local fallback "reveals a discovered tool by adding it to the tools array, which invalidates the cached prefix from the tool definitions onward" (L990). OpenRouter's tool search returns 400 on Chat Completions (X6). So every stored client-side implementation for the university route's API shape either breaks the cache or is unavailable. No stored page shows a model on an OpenAI-compatible endpoint calling a tool whose definition was given only in a late message. How the tool becomes callable without the tools array is the open design question, and `14` marks the pattern copyable without saying so [U].
(b) The human's second probe adds that "a tool added at the end of the list" on GLM-5.3 reused only the first 1,728 tokens and rewrote 65% of the prompt (`10-p0-university-api-reading.md` L75). So "append at the end" of the tools array also breaks the cache on this route; only appending outside the array (in a turn) is shown to keep it (L33, a plain appended user turn). `14`'s s3 phrase "append at the end, never edit the tools array" can be read as appending to the array.
(c) Proposal (d) says a plain tools-array edit breaks the cache "on an OpenAI-compatible endpoint" and cites only Pydantic AI's description. The human's probes are the better evidence and are not cited there: GLM-5.3 (and, per `STATE.md`, MiniMax-M3 after the third probe) behave as plain prefix caches, while gpt-oss-120b reported 95-100% cached after the same changes and is unexplained (`10` s7 L71-76). Pydantic's own L1035 adds that Google's implicit cache can survive tool-list changes. So the sentence holds on the probed models except gpt-oss, which is the model the university route is said to serve; as worded it is a library-documentation generalisation.

**Evidence.** As cited; `design/package-v5/04-design.md` V5-R04 and the M3 node ("neither: append the seed definitions to that turn") already assume a route that (a) leaves untested.

**What would resolve it.** Replace "copyable" with "the cache-preserving pattern is documented only for server-side deferral; whether a client can make an appended-in-message definition callable on the university route is untested"; word (d) as "adding to the tools array rewrote the prompt after the tools on the models probed (`10` s7); appending outside the array kept the cache"; keep the Pydantic line as a vendor statement.
