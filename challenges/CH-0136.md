# Title: PL-1, PL-4, PL-6 and PL-7 each rest on evidence that does not transfer as stated or does not change V5

**Objection.** (a) PL-1 "treat a drop [in the cached-token counter] as a defect": `10` L32, L50, L78 shows the university route's cached share is 59-99.7% of a prefix, partial on two models for reasons not shown, and MiniMax-M3 re-creates a 128-token block on every request. Without a baseline per model a "drop" is undefined and the rule cannot be applied or falsified. "Memory block serialized byte-identically on every request" is ambiguous between within one session (fine) and across users (contradicts V5-R06's per-user content after the prefix). B9, cited for PL-1, is a PR author's cause that a later comment disputes (SUM-0057 B9; `15` s4.1 notes it).
(b) PL-4 "keep the seed set small, name its cap as a symbol (the existing m)": `04` s7 already names m, so it proposes no change. Its evidence is about skill documents (D27: scout row says "Skills here are instruction documents, not tool definitions"), retrieved experiences (D24) and history length (D10, D11), not tool definitions; D24's own text also says a richer experience bank "consistently improves performance" (SUM-0062), and D11 has a counter-case (one model improved in later stages). D27's v1 to v4 swing (self-generated skills -1.3 to between -8.1 and -11.5; comprehensive skills -2.9 to +0.7) is presented in s5 as scout error, but SUM-0064 says the v1 text is not stored and the difference is between versions. The count of seeds that pays is what D-02 computes; the landscape gives no number for tool seeds.
(c) PL-6 extends D-04 with write ratios 2.0 and 2.5 from Anthropic's 1-hour and OpenAI's 12-hour retention. STATE and `10` say the university API serves open-weight models only, with no selectable cache lifetime and no stated write price (`11` L21: w 1.0 where no fee is listed). Whether closed-provider long-retention prices are in scope for the thesis is not stated in `15`; if not, PL-6 adds columns that no deployed route can buy. It is arithmetic only and cheap, but "a returning user's warm start is bought with exactly these" holds only where such a provider is used.
(d) PL-7 adds "no memory, seeds, oracle seeds" arms; V5 already runs an oracle-registry ablation (`04` V5-R11) and `03` names ATRBench's session design as a candidate harness. `15` s4.7 does not say what is new beyond cost-of-construction reporting and over-calling measures, and omits MERIT (F29), which defines a none / full-replay / memory condition set with cost per episode (stored `v5-ls-f20` L173).

**Evidence.** `10-p0-university-api-reading.md` L27-32, L50, L78; `11-price-ranges.md` L21; `04-design.md` L96 (V5-R11); SUM-0062 D24; SUM-0064 D27, D11; scout D row D27.

**What would resolve it.** (a) define the baseline per model before "drop"; (b) say PL-4 changes nothing and drop the skills evidence or label it as analogy; (c) one sentence on whether closed-provider prices are in scope; (d) say which of PL-7's arms already exist in `04`/`05`.
