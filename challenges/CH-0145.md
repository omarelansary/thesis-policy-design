# Title: SWE-bench Verified and Terminal-Bench are triaged out of every item for lacking a tool catalogue, but P4's construct and hard requirements do not need one

**Objection.** The triage paragraph puts "Terminal-Bench, SWE-bench Verified (no tool catalogue; SWE-bench kept as the audited reference case)" under "out of scope for every item". The reason is a catalogue requirement. The s4 P4 row asks for H1 native large tool results (measured, not padded), H2 long runs, H3 a deterministic final-state scorer, H4 a reproducible environment; none mentions a catalogue. P4 is about masking old tool output in long runs. On the register's own cards, the MCP benchmarks that meet H1 are few: MCPMark (input 64K to 1.4M tokens per task, but 12 of 28 Postgres verifiers pass without the work and the Postgres/Notion/GitHub split matters) and Toolathlon (15% to 35% of tool outputs overlong, 31 tasks local-only by the inspector's classification, no licence file). Coding-agent benchmarks have long runs, large tool outputs and deterministic test scoring.
Other records point at relevance: scout D tagged D34 SWE-bench Verified "P4, E2E" (`D-catalogues-long-runs.md` L67); `04` L60 says the masking evidence is "one coding-agent study" and that tool outputs were a small share of cost in coding agents, which is a reason to test P4 where outputs are large, not a reason that coding benchmarks cannot serve; s5 itself lists two coding benchmarks (SWE-ContextBench, Claw-SWE-Bench) as cost-reporting precedents. I did not check which benchmark the masking study used.
Against using them: Epoch rates SWE-bench Verified "Flawed" (relying on OpenAI's audit, an interested party, and a reward hack by RDI); Terminal-Bench cost and tokens were not read (scout D L70); coding tool results are less like MCP tool results. Those are scored properties, not a reason for "out of scope for every item".

**Evidence.** `17` s4 L86 and s5 L121; `05` s2 P4; `04` L60; SUM-0076 D34; SUM-0068 A20; scout D L22-23, L67, L70.
[F] the quoted lines. [I] that the triage reason does not match the P4 requirements. [U] whether coding benchmarks fit P4 (not assessed in the register).

**What would resolve it.** Triage per item: either give SWE-bench Verified and Terminal-Bench cards (tool-result size distribution, turns, scorer, licence, version) and score them for P4, or state a P4 hard requirement that excludes them (for example "tools are MCP tools") with its reason. Mark them "unassessed for P4" until then.
