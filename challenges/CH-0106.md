# Title: the "official" r and o ranges are the span of about a dozen pages the lead stored, and the stored pages contain points outside them

**Objection.** `11` s2 presents r 0.02-0.50 and o 2.1-7.5 as the range "on official pages". It is the span over the provider pages that were fetched (DeepSeek, Z.ai, MiniMax, Alibaba, Groq, Fireworks, Together, DeepInfra, Baseten, Cerebras, CoreWeave), not over the hosts of these models: AA lists 16, 26 and 12 hosts, and most have no stored official page. Stored text already holds points outside both ranges, none mentioned in `11` or `13`:
- Fireworks "other base models": one price per size class for input and output, so o = 1.0 (below 2.1) and no cache discount.
- AA's provider rows: Makora GLM-5.3 "$0.14 - $0.10 - $4.40" reads r = 0.71 and o = 31 (aa-caching L497-502); steward A15 flags the neighbouring Supernova rows as unattributed. This may be a typo for $1.40 or a real price; it is not resolved either way.
- Parasail 0.75/0.10 (o = 7.5) is an aggregator point; the 7.5 maximum on an official page is only CoreWeave's Qwen3.8-27B, a single row.
A range quoted as "official" invites reading it as a bound. The D-04 grid is built on it (o = 2.1/5/7.5; r from 0.02).

**Evidence.** `v5-lit-fireworks-pricing-20261027.txt` L90-97; `v5-lit-aa-caching-20261027.txt` L497-502, L784-800; `v5-aa-gpt-oss-120b-providers-20261027.txt` L437 (16 providers); `13` s2 table, row o.

**What would resolve it.** State in `11` s2 that the ranges are over the stored official pages (list them), name the out-of-range points (Fireworks size-based o = 1.0; the Makora row, marked unresolved), and say the grid is a convenience span, not a bound. If o = 1.0 or r = 0.71 are real, extend or footnote D-04; if the Makora row is a typo, say how that was decided.
