# Title: Four methodological risks that bear on the paired comparisons are in neither the rules nor the overlooked list

**Objection.** s1.4 lists contamination, scorer reliability, floor/ceiling, own selection bias, harness control and licences. These are missing, and each has a stored source or a result in this workspace behind it.
1. **Multiple comparisons and forking paths.** The planned set is six experiments, several cells each (P3: four cells x two prompt variants), at least two models, three regimes, several arms (`05` s2-s3), and a ranking over roughly 25 candidate benchmarks. No rule limits the number of contrasts that may be read as findings, requires an analysis plan listing them, or says what is reported when several are examined. R3 (Hofman) only says that pre-registration helps "provided it is adhered to". R9 treats selective reporting as a risk for the benchmark choice but not for within-experiment contrasts. Estimation-only reporting (R5) reduces the pass/fail temptation but does not remove the choice of which contrast to headline.
2. **Judge coupling and self-enhancement.** s1.4 mentions that a judge may be "served by the same university API". R4 cites MT-Bench for position bias only. The stored MT-Bench text also names verbosity and self-enhancement bias ("LLM judges may favor the answers generated by themselves", `m17` L100, L307-308). If the judge and an evaluated model are the same family or the same model, one arm's style (for example fewer tool rounds and a shorter final answer) can interact with the judge. R4 asks for pilot validation, not for the judge to differ from the evaluated model, to be fixed across arms, and to be run blind to arm. Published judge agreement does not transfer when the judge is replaced by a route-available open-weight judge (the MCP-Atlas judge is configurable; the tau2 NL judge is fixed in `tau2.config`, I2 item 6), so a published agreement figure (MCP-Atlas 78%, v1) cannot be used as E2E H1's "reliability known".
3. **Route drift between paired runs.** R10 quotes HAL's warning that providers "swap model weights behind the same endpoint without notice" and that prices change, but only to justify raw usage records. Paired arms run on different days on a shared university route are exposed to the same drift (and to cache lifetime differences: cold after 4 h on gpt-oss-120b only, `10` s11; a rate limit of 2 requests on GLM-5.3, `05` P0 row). No rule requires interleaving arms in time, logging model identifier and time per request, or re-running a control arm at the end. P3 has "no live drift between paired cells" (H5); the other items do not.
4. **Combining per-experiment results into one claim about V5-R.** R1 and R2 allow different benchmarks per experiment and synthesis "only for effects in a common unit". The thesis claim (the V5-R package lowers the bill with accuracy nearly the same) is a combination of P1-P5 and E2E results from different benchmarks. The register says how to avoid pooling raw scores but not what the stages' separate conclusions license for the whole; the Lottery abstract is evidence that the choice of tasks can reverse comparisons, so a stage kept on one benchmark and dropped on another is a possible outcome with no rule. A rule such as "a stage dropped on any benchmark in the confirmatory set is reported as dropped for that regime" would be the lead's reasoning; the register has none.

**Evidence.** `17` s1.4 L29-36, s3 L62-75; `m17` L100, L307-308; `10` s7, s11; `05` s2-s3; I2 item 6; SUM-0066 M27; SUM-0065 M1.
[F] stored text and STATE. [I] that 1-4 are gaps in the rule set. [U] their size.

**What would resolve it.** Add four rules, each marked as the lead's reasoning unless a stored source supports it: (1) an analysis plan listing the contrasts and the headline before the confirmatory run; (2) the judge differs from the evaluated models, is fixed across arms and validated on the route; (3) arms interleaved in time with per-request model id and timestamp logged and a control re-run; (4) how stage-level results combine into a claim about the package.
