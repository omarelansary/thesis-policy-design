# Title: PL-2's evidence column argues against its own default (append every session, store the user's task line), and the append-only headline rests on one vendor blog

**Objection.** (a) PL-2 makes W "a rule-based, append-only record per session (date, the user's task line, the S1 tools actually executed, outcome)". That is an add-all writer. D4 (cited for PL-2; checked, SUM-0059) found add-all below a fixed memory bank on all four agents and a strict writer above it, and `15` s4.3 says "Writing everything hurts; a strict writer helps". PL-2 has no gate (outcome filter, minimum session length, idle gate) although `15` s4.3 lists the vendors' gates (A22 skip active or short sessions; A24 three hours idle and 10 user messages). D4 is about stored task executions retrieved by similarity, so the transfer to tool names is not shown; but the record cites it as support rather than as a caution.
(b) PL-2 stores "the user's task line" verbatim. The security evidence `15` itself gathers (G5: untrusted content seen in a benign session is stored and later acts as instruction; G10: a write-time screen refused 0 of 360 poisoned memories) is about exactly this write path. PL-2 cites G10 as support for rule-based writing, but G10 is evidence that content is hard to screen, which argues against storing raw user text, not for a rule that stores it.
(c) The headline "Rewriting memory destroyed information; appending did not" is Mem0's own blog about its own pipeline (C3, [C] = the page says it). The page says "sometimes" and also claims the change "produces better memories"; it says old and new facts "both survive" (SUM-0058/0059 notes), i.e. append-only keeps contradicting facts, which is the staleness problem PL-3 then has to handle. D5 (checked) shows deletion shrank the bank with mixed effects (RegAgent success fell 70.95 to 66.58 under combined deletion; EHRAgent rose), so "appending did not [destroy]" is not a tested contrast.
(d) The cost evidence for "one cheap call is risky" (F27, F28) concerns pipelines that ingest every 10 turns or per message (F27 Table 8, SUM-0059) and one conversation (F28). V5's W is one call per session. The record does not say the cost shape differs.
(e) PL-2 removes the "short summary" from W's default. V5-R05 and REQ-O21-03 (REGISTER L76: memory holds tool question-answer pairs and a short summary of past interaction) include it. `15` s3 says no requirement is changed, but PL-2 does not mention REQ-O21-03. D1/D2 (MEMDRIFT) tested deliberately biased, synthetic, personality-driven memories, not summaries a model wrote, so "no model-written free text" extrapolates beyond the tested case.

**Evidence.** SUM-0059 D4, D5, F27, F28, C3; SUM-0058 A22, A24; SUM-0060 G5; SUM-0061 G10, D1, D2; `requirements/REGISTER.md` L76; `04-design.md` L45, L90 (V5-R05).

**What would resolve it.** In PL-2: add a write gate or say none is proposed and why; replace the raw task line with a derived or hashed key, or state the injection risk explicitly; name REQ-O21-03 and say PL-2 proposes a default different from the supervisor's example; reword the s4.3 headline to "one vendor reports ... for its own pipeline"; state that F27/F28 concern per-turn ingestion.
