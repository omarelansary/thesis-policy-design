# Title: Provenance labels are applied by two different standards, and several "I" and "X" labels go beyond what the stored pages show

**Objection.** s3 defines I as "no stake shown" and X as "interested party (named)". The register uses the absence of a shown tie to assign I, but uses outside knowledge to assign X. The stewards flagged most of the cases below; the register carried the label anyway.
1. **amazon-agi, tau2-bench-verified: X "a model developer; the page shows only the organisation name".** SUM-0077 E7: "'Amazon runs models' is not on the page"; SUM-0070 B18 same. The label X rests on the lead's knowledge of the organisation, not on the page. Compare Epoch, labelled I because "no tie to the authors [is] shown", and SUM-0070 B8 adds "not searched further". Same absence of evidence, opposite labels.
2. **GitHub issue reporters: I.** SUM-0077 E10 and E17: the reporters of tau2 #710 and MCPMark #272 link their own repositories (whose-noise; evidence-manifest), so I = "no stake in the benchmark", not "no stake shown". tau2 #672 states it was "found while auditing public RL environments" (E9). The s6 note "a GitHub username is taken as a third party, which the page cannot prove" is honest, but I as "no stake shown" overstates it. For MCP-Atlas #71 the only reply comes from an unlabelled account that argues without citing code (SUM-0078 E26).
3. **LoCoMo audit: I.** The README gives no author and calls itself an "Independent audit"; "independent" is self-description (SUM-0074 C36). I is not "no stake shown" for an anonymous source; it is unknown.
4. **Miller (m01): X "the author is at Anthropic, a model vendor".** The affiliation is on the page (SUM-0066 M21), but the paper is a statistics-of-evals note on error bars; no stake in the recommendation is shown. Labelling it X while Princeton authors of "AI agents that matter" (who later built HAL) and Ndzomga (HAL author) are A/I dilutes the label.
5. **Leaderboard Illusion: "Cohere-affiliated authors studying competitors".** The page shows Cohere affiliations (SUM-0066 M30); "studying competitors" is not shown by the SUM.
6. **MCP-Atlas: README = A, leaderboard = X.** Both are Scale's pages. One party, two labels.
7. **Tool-Veritas (X) is applied correctly,** but the same authors' per-benchmark figures are used as the main evidence in s6 with no second source for MCP-Atlas or LiveMCPBench except the benchmarks' own pages.

**Evidence.** SUM-0077 E7, E9, E10, E17; SUM-0070 B8, B18; SUM-0074 C36; SUM-0066 M21, M30; SUM-0078 E26; `17` s3 L60 and s6 L124.
[F] the stewards' notes. [I] that the label standard is inconsistent. [U] real affiliations behind usernames.

**What would resolve it.** Add a fourth label U ("tie not shown and not looked for") and use I only where a tie was looked for and none found. Label by what the page shows; where the lead adds outside knowledge, say so in the cell. Apply the same standard to Epoch, amazon-agi and the issue reporters.
