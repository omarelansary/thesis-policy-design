# Title: the search log cannot serve as "the only support for any not found" in its present form

**Objection.** The log (L3) calls itself the only support for every "not found" in the package. As written it records:
- queries "verbatim as reported" by the scouts, but several are truncated with "..." (L8, L9: "MemTool short-term memory tool selection...", "Letta filesystem agent LoCoMo...", "Anthropic advanced tool use programmatic tool calling...", "Cursor dynamic context discovery...", "JetBrains complexity trap...", "MCPVerse...", "LiveMCPBench...", "TheMCPCompany..."); many are named-item queries (the item was already known), not discovery queries for a negative;
- counts as "About 38 / 41 / 42 / 38 searches and fetches" (about 159) with no per-query result, no hits-rejected list, no date or time per query;
- scout reports that are "model output (WebFetch summarises pages with a small model) and are not cited" (L3), so the log is the lead's transcription of an unaudited self-report; the scouts' tool logs were not inspected;
- no list of the places an absence was checked per topic (the map's "not found in the places listed in `inputs/search-log`" at 03 L5 therefore points to a list that is per scout group, not per topic);
- a Gemini page stored as a 29-line stub (L14), which the map and 02 do not carry as a gap.
The "Pages stored by the lead" section (L13-L17) is a list of what was fetched, which shows what was read, not what was looked for.

**Evidence.** Search log L3, L6-L9, L11, L14, L20; 03 L5.

**What would resolve it.** For each NONE FOUND row (CH-0090), add a short per-topic block: topic, queries run (full text), engine, date, top hits examined, stored or rejected with reason. State that the scouts' tool logs were not audited. List the Gemini refetch as an open item in 03 section 10 or the ledger.
