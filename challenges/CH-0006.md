# Title: smaller defects in DPR-0001 (labelling, token measurement, the cost of deciding, missing "legitimate inference")

**Objection.** Four items, each small, grouped to save a message.
1. **Label.** Section 5 "Caching" bullet is labelled "[F]" but is "per the lead's seed rows ... (not yet read by me at original passage ...)". By the workspace's own labels [F] is a fact in a cited source; this is a [U] until the steward returns the passage. The "Evidence it uses" section is correct (it says the seed rows stay [U]); the bullet contradicts it. Also, the ledger records these rows as vendor assertions, "not measurements" (C3-03b limits).
2. **Token length `L(t)` treated as a property of the tool.** It depends on the tokenizer of the model and on how the provider renders the tools block. The ledger notes tiktoken counts "are not Claude-billed tokens (new tokenizer about +30%)" (C3-07 limits) and that Anthropic's pricing counts the `tools` parameter plus a tool-use system prompt. So `c_vis` as `sum L_g(t)` is a convention, not an observable, and a cross-model comparison needs it stated (the S4D addendum says token counts are "treated as equal with no cross-model convention").
3. **The cost of deciding is not a function of what the decider reads.** Section 5 writes `decide(pi)` as one term. For a selector that reads candidates (an LLM scoring relevance, a reranker) the cost scales with the number of candidates read and the length of what it reads; that dependence is what any multi-stage argument turns on (stage 1 reading `n` tools versus stage 2 reading a few), and it should be in the cost model before DPR-0002/0003 use it. Likewise there is no term for the effect of exposure on behaviour (distraction by the presence of other tools) in `P(pi)`; `P` is written as a function of `pi` only, but depends on `E_s` and model.
4. **"What it can legitimately infer".** AUTH-004 asks for what is available, what can legitimately be inferred, and what exists only after execution. The register lists signals; inferences (task category from `q`, required capability, session length from `q`, whether a missing tool exists in `K`) are only implicit in S11. A short list of inferences with their input signals and error costs would close this.
Also (citation precision, trivial): section 2 D4 cites "S4I section 5" for the open session horizon; S4I section 5 does not list horizon (S4I section 6 item 3 and S4G L74 do).

**Evidence.** DPR-0001 sections 2, 5, 6, "Evidence it uses"; ledger lines cited; S4D addendum L31; S4I decision sheet L64 (regime: trajectory versus session horizon) and S4G L74 (session length not available on the vehicle).

**What would resolve it.** Edits; no experiment.
