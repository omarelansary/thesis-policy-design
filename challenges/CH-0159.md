# Title: Stored pages hold AppWorld facts that the register omits or contradicts, and AppWorld is ranked first on five experiments

**Objection.** AppWorld was never downloaded or measured by the inspectors (I1 item 6: "not downloaded; size unmeasured"), but its authors' paper and README are stored and say more than the register uses. Six points, each checkable in the stored files:

1. *Definition tokens.* s7 L203 says the 457 definitions "may be about 114k tokens [I, unmeasured]", and s10 lists tokens as unmeasured. The stored paper says: "the full documentation is large (~142K tokens)" (`v5-bm-b13-arxiv-pdf-2407.18901.txt` L814-816) and that its agents therefore use an API predictor to select the relevant APIs (L816-820; the code in `v5-bm-i24` L101-121 fixes up to 20). 142K is the documentation, not necessarily the function-calling JSON, but it is the only measurement on any stored page, about 311 tokens per API against D-01's d = 250 (25% above the register's figure). If a route model's window is 128k the full block does not fit [U: no route window found in `10-p0-university-api-reading.md`, `04` or the scads files I searched]. "All 457 declared" (P2, E2E R-mid) is therefore V5's extension, not a native configuration of any AppWorld agent.
2. *Scenario structure.* s10 lists AppWorld's "scenario structure" as unchecked, and DPR-0010 marks it "[U: from memory]". The stored paper says "250 task scenarios with 3 tasks each ... Train (105), Dev (60), Test-N (168), Test-C (417)" (L713-715) and that task scores fall 30-50% when all three variants of a scenario are required (L865-867). So train+dev (165 tasks) is 55 scenarios and Test-N is 56. See CH-0161.
3. *"Not MCP".* s7 L188 ("except that it is not MCP"), DPR-0010 s0 ("Python-style API definitions ... not MCP servers"). The stored README says: "AppWorld has first-class support for Model Context Protocol (MCP) now ... all AppWorld APIs are now accessible via this unified protocol" (`v5-bm-b14` L1115-1121). The scout listed it (B23) and the steward CONFIRMED B23 (SUM-0071). It is not in the register. It does not make the apps real, but it changes the fidelity argument (E2E-2 and P5-3 are justified by "real MCP schemas") and offers a route for P5 that needs neither Docker nor a format conversion.
4. *Open-weight scores.* s5 L132 says "open models in the paper". The stored paper gives the best open model (LLaMA3 + FullCodeRefl) 24.4 task completion on Test-N and 7.0 on Test-C, and says open models "currently struggle with Test-C" (L766, L869-872). These are 2024 models and are not the route's, so they are context only (as s5 treats the other rows), but the cell hides the one figure that bears on a floor for the 417-task Test-C set that E2E-1 and P2-1 name as the "confirmatory reserve". Scout B found no open-weight score of a newer model ("open-weight not found", B24).
5. *Reset and evaluator defects.* s5 says "reset per task". Scout E32 lists issue #203 titled "state reset" and #229 ("every amazon place_order fails"); register s6 L171 reads titles only. The reset claim is not checked.
6. *Planned hidden test set.* The README (B23) says a "completely hidden test set with new apps" is planned; the test split used as a reserve may change.

*Asymmetric scrutiny.* s6's closing reading says that missing criticism for the youngest benchmarks is "absence of scrutiny, not evidence of quality". AppWorld has an issue list read by titles only, no independent audit, and scout E's claim "no Epoch review ... AppWorld" is itself NOT found on the stored page (SUM-0077 L39). DPR-0010 s5 calls it "the best-scrutinised deterministic scorer here", which is an inference from absence. MCP-Atlas, MCPMark and BFCL were inspected more and show more defects, so more inspection lowers their standing. s7 does not say so.

**Evidence.** [F] as cited above (stored paper, README, code, SUM-0071, SUM-0077, scout E and B reports). [I] the reading of asymmetric scrutiny.

**What would resolve it.** Put points 1-6 into the AppWorld card and s7; replace "about 114k tokens [unmeasured]" by the stored 142K with its caveat; replace "not MCP" by what the README says and mark whether it was tested; read issue #203 and #229 bodies or mark them unread; state in s7 that AppWorld's rank rests on properties not measured by anyone in this workspace (floor on the route, tokens in function-calling format, window fit) and make the AppWorld ranks conditional on a pilot, as MCPMark's rejection is conditional on a reported floor. Until then s7's rank 1 for P2, P3, E2E should not be offered to the human as a settled ranking. (Blocking because it affects five of six experiments, and the omitted facts are in files already stored.)
