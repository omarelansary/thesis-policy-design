# Title: node-by-node audit of G finds open slots, an input that does not exist (R6 to R5), an undefined imported inequality, a missing no-recovery arm and an incomplete recovery-assumption set

**Grade: SERIOUS.** None of these is decisive alone; together they contradict section 7 of 02 ("Not a family with open slots either").

**Objection.** (design/package-v3/02-supervisor-decision-graph.md; classes R/D/X/P as defined there.)
- **D1.** Both outgoing edges go to D2; D1 labels a regime and decides nothing. "Fits" is not binary: it depends on the working context (trajectory length), which is unknown at design time. Provider limits other than window length (a maximum number of tools per request) are not mentioned [U: not checked].
- **D2.** "Rank tools by incremental token saving per unit of estimated miss mass" is `s_t / m_t`; the errata's index is its reciprocal `m_t / (keep_t - disc_t)` with the *largest first* moved to the core. Whether the core is cut from the head or the tail of D2's ranking is not stated: a one-word ambiguity, but the sweep in D2/D3 runs along this ordering. D2's "dev runs of a feasible reference" does not exist in the D1-no branch that D2 is routed from.
- **D3.** The arm list is not defined: "static no-removal sweep" is unclear (static core with no search? add-only?). A **static core without any recovery** is not clearly an arm, yet the errata's admissibility analysis (correction 1) is entirely about a *no-recovery arm*. If it is absent, the need for any reintroduction is assumed rather than tested; if present, D4 will choose it whenever the tail mass lost is below `delta` (see CH-0042 point 1) and G then has no reintroduction. 02 does not say which.
- **R2.** Selector type "unset (rule, embedding model, or LLM)". An LLM selector reading the whole deferred catalogue costs `a_1 n_0` input tokens per request (DPR-0002 section D), which under the token criterion (no cache) exceeds expose-all; only non-LLM selectors can win, and their costs (index, embedding) are not tokens. The level-2 condition `b_1 + a_1 n_0 < a_2 (n_0 - n_1)` is imported from DPR-0002 section D with **its symbols undefined in G**, and DPR-0002 states it together with the recall condition `(1 - r_1) V < saving`, which G drops. G also calls it "a measured cost condition", but it is an analytic inequality in unmeasured parameters from a `proposed` record (DPR-0002 itself says the record "does not discriminate").
- **R5 and R6.** R5's information is "the model's query". R6 transitions to R5 but R6 has no model query: R6 would have to compose one from context, which is an unspecified function. The dashed edge R3 to R6 does not say *when* R6 runs: after every step (an extra decider call per turn that re-reads the trajectory, at least doubling input tokens) or at termination (a signal that, to detect "unmet need", needs knowledge of failure that is class X). 02 itself rates R6 "class R if zero-shot, D if tuned" without saying which signal the zero-shot classifier sees.
- **R4 and scope statement.** A "metadata-only scope statement" for a 10,000-tool catalogue cannot enumerate; it is a summary whose authorship (operator, an LLM) and size are an unlisted stage; its tokens recur every turn (the errata's `L_S + sigma`).
- **Evidence labelled "bounds only".** EXT-0063/0064 (PlanBench-XL): enforced exploration inserts a continuation message when the agent terminates "with an incorrect answer" (EXT-0063 l.24-26), gains "less than 5 percentage points" for most models. It adds *turns*, not a missing capability; it is not a bound on the value of restoring a missing tool. "Bounds only" overstates; 03 says "the only trigger-like result", which is right.
- **Information from a benchmark vehicle.** R5's "ranker recall measured on scripted queries" (02 table) is the only place a benchmark artefact enters G's run-time path; scripted queries made from gold tool descriptions would leak. Not stated how they are made.
- **Recovery assumptions RA1-RA5: missing.** (RA6) the model's query shares vocabulary with the deferred definitions (the model cannot know tool names; the ranker is lexical or embedding); (RA7) the model can issue a correct call from an appended schema it did not see before (argument errors, listed in the errata's `I`); (RA8) the provider allows changing the tool set mid-trajectory (package-v2's A0 applicability check has no counterpart in G); (RA9) the scope statement is accurate and does not mislead the model into not searching or searching needlessly; (RA10) R2's recall, as an assumption for the cut tools; (RA11) the search budget `B_s` is sufficient for multi-tool tasks (RA4 covers turns, not searches).

**Evidence.** 02 read in full; DPR-0002 section D (read, lines 56-66); EXT-0063 l.22-39 and EXT-0064 (read); EXT-0065 (read: FitText prescribes `{BEGIN}...{END}` by prompt with "Finish" the only visible function); EXT-0009 (read). I did not read DPR-0003 or the 2026-10-14 excerpts beyond the REGISTER rows.

**What would resolve it.** Edit 02: define the arms and each open symbol or list them as open slots and delete the "not a family with open slots" sentence; give R6 a trigger time and a query source; define or drop the level-2 inequality; list the missing RAs.

**Response (lead, round 2).** 02 revised: R6 builds its query from the transcript (edge R6 to R5 labelled); level-2 inequality with symbols defined and marked "necessary, not sufficient"; a static no-recovery arm added to D3; "bounds only" replaced by a statement that EXT-0063/0064 concern extra turns; RA6-RA11 added; the "not a family with open slots" sentence replaced. **Round 2 (challenger): DOWNGRADE to minor; mostly resolved.** Checked: the inequality `b_1 + a_1 n_0 < a_2 (n_0 - n_1)` is exactly the condition that the two-level reading cost (`b_1 + a_1 n_0 + b_2 + a_2 n_1`) is below the single-stage cost (`b_2 + a_2 n_0`), so "necessary, not sufficient" for end-to-end benefit is right. The R6 evidence-status wording now matches EXT-0063 l.24-26 (insertion after an incorrect termination). EXT-0026 (ComplexMCP Table 3 text: vector-retrieval RAG "still do not match the performance of the full-context method") and EXT-0028 (ToolMenuBench Table I: keyword top-5 22.1% against all-tools 32.1%) support "below full exposure" as 02/03 state; note the same ToolMenuBench table reports 3,200 against 56,062 tokens, i.e. the token saving is large at a 10-point loss; vehicle is synthetic. Residuals: (i) R6 still does not say *when* it fires (after every call, which would add a classifier call per call, or only at termination); (ii) "scripted queries" for ranker recall: provenance not stated; (iii) RA list still lacks (a) the provider allowing the tool set to change mid-trajectory (v2's A0 has no counterpart) and (b) query-to-definition vocabulary mismatch (partly RA2); (iv) the scope statement's authorship and size at 10,000 tools; (v) selector type, `kappa`, `B_s` remain unset, which is why CH-0040 (a) matters; the new sentence in 02 section 7 ("not a policy family without a rule") does not say there are no open slots, which is correct.

**Outcome.** partly resolved (conceded); residuals (i)-(v) minor.
