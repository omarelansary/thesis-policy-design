# Title: Reframing pilot 2 as "with the discovery tool and our scope statement" is defensible, but as written it demotes the unprompted cell, treats the statement as free, and invites tuning

**Grade: SERIOUS on constraints (i)-(iii); the reframing itself is largely sound (see "what I tried").**

**Objection.**
1. It is not new. v3 `04` E2 already read "Remove one needed tool per task, scope statement on and off, several models", and `01` line 102 repeats it. So `05` section 2.1 ("The relevant condition is not 'unprompted' but ...") is a re-emphasis presented as a correction. The risk is the sentence itself: it declares the unprompted cell irrelevant. RA1's falsifier (`01` line 102: "initiation rates too low for any discovery arm to be noninferior") needs a primary cell. If "scope statement absent, search tool present, no hint" is not the primary cell, a pass in the "catalogue-specific statement" cell can be read as RA1 holding, although the deployment may not carry such a statement.
2. "Unprompted" has no clean meaning here: the search tool's own description and, on OpenAI, the visible names and descriptions of searchable namespaces (EXT-0010 line 51) are already prompts. The honest statement is a ladder: tool description only / generic statement / catalogue-specific statement / explicit hint. `05` lists these factors; it should say which one is the RA1 test and pre-commit it.
3. The scope statement is **not free**. Its tokens are billed on every call (in the prefix, so at cache-read price if cached), and a catalogue-specific statement that names the missing tool's domain is partly an exposure of the catalogue (an information leak that makes the "hidden" tool less hidden). Cost accounting (`01` criterion) and the information-class bookkeeping (`02`) must count it, or the arm's cost is understated.
4. LOMEKWI shows one added sentence moved a measure from 0.02 to 0.60 (LOM:783-785). Applying that lesson, a scope statement written by the authors is a researcher degree of freedom: results would measure the wording. It needs a pre-registered set of statements (few variants), a held-out catalogue or task set, and the statement text reported.
5. Positive result in the best statement cell establishes only that **some** statement works for the tested models; it does not establish that a deployer can write one without catalogue knowledge, which is the large-catalogue difficulty.

**Evidence.** v3 `04` line 38; `01` lines 102, 105; `05` section 2.1; EXT-0010 line 51; LOM:783-785.

**What would resolve it.** Name the primary RA1 cell (tool description only), keep it in the pilot, charge statement tokens, report statement text, limit variants in advance. Answerable now; rates need data.
