# Title: The minimum cacheable length is applied to "the tool block" in the regime table, but the vendor rule is about the whole prefix, and the calc ignores it for the deferral prefix

**Objection.** `04` section 2 defines R-small as "Tool block below the model's minimum cacheable length (512-4,096 tokens)". The vendor text says the minimum applies to the prompt to be cached ("minimum cacheable prompt length ... Any requests to cache fewer than this number of tokens are processed without caching"; OpenAI: "A prompt prefix must meet the model's minimum cacheable token length"). A system prompt counts toward it, so a small tool block caches whenever the system prompt plus tools reach the minimum (the multi-turn study used a 10,000-token system prompt, `03` row 17). The script has no uncached branch at all (`regime_bill.py:21-30`): the deferral prefix (5 tools plus search = 800 tokens at d = 100, 1,550 at d = 250) always receives the write and read prices, although for models with a 1,024, 2,048 or 4,096-token minimum it may not cache. [O, hand] With the deferral prefix uncached and expose-all cached (T = 10, D = 1, d = 250, r = 0.1), break-even n* is about 37 instead of 12. Direction: the calc favours deferral at small catalogues; the regime table's R-small boundary is stated on the wrong quantity.

**Evidence.** `design/package-v5/04-design.md` section 2 (R-small row); `calc/regime_bill.py:18-30`; `L/v5-anthropic-prompt-caching-20261022.md:593-604` (minimums by model: 512 for the newest, 1,024, 2,048, 4,096 for others); `L/v5-openai-prompt-caching-20261022.md:69, :587-593`.

**What would resolve it.** State the minimum on the total cached prefix (system prompt plus declared tools), add an uncached branch to both designs, and print n* for a 512-token and a 4,096-token minimum with a stated system-prompt length; rewrite R-small in terms of that.
