# Title: A1's inputs p_hat and q_hat are estimable where expose-all is feasible (the rival's strongest regime) and censored where it is not; "needed" has no stated source

**Grade: SERIOUS (the runtime-information claim "every input passes the test" holds only conditionally).**

**Objection.**
1. **Availability.** `p_hat` comes from agent calls in dev runs of `pi_ref`. Where the flat catalogue exceeds the model's context, `pi_ref` cannot run (package A, A7: the closest vehicle's flat catalogue exceeds the context of 2 of 4 matrix models); there the substitute is a restricted or retrieval-narrowed policy, and any restricted dev policy censors the data: a tool never surfaced is never called, so `p_hat = 0` for exactly the tools whose absence matters (the reachability gate of EXT-0053, pass^3 0.0% on unsurfaced tasks, V6: rag:8 only). The large-`n` regime is the regime where restriction is needed, and it is the one where A1's main input is biased. At moderate `n`, where `pi_ref` runs, the rival (expose-all cached) is strongest.
2. **Call frequency is not need.** `p_hat_t` is defined as the probability that a session needs `t`, but it is estimated from calls. Calls under `pi_ref` include distractor-driven and redundant calls and omit under-invoked needs (EXT-0047/0048: no tool use in failed trajectories; V8 PARTLY). If "needed" is taken from successful runs only, success (class X) filters the dev data: legitimate offline, but it biases toward tasks `pi_ref` solves.
3. **`q_hat` labels.** `q_hat_t` (probability a needed deferred tool is not reached) requires a definition of "needed" for each dev task. The runtime table (section 5, row q_hat) lists leakage routes but not the labelling source. The two available sources are gold required-tool annotations (class P, absent in a deployment) and `pi_ref` calls (point 2). The estimator must say which.
4. **Vehicle [U].** On a replay vehicle the "agent's own calls" may be single-step predictions conditioned on a gold history, not free-running usage (CAVEATS rows 3 and 4 as cited in package E6); I could not read the vehicle description, so this is a question, not a finding.

**Evidence.** DPR-0004 section 4.2 row A1, section 5 rows p_hat and q_hat; package A section A7 ("Reference pi_ref"); EXT-0053 and EXT-0047/0048/0049 via SUM-0003 V6, V8; package E6.

**What would resolve it.** State the estimators with their label sources; make "`pi_ref` can run on the dev tasks for the model in use" an explicit applicability condition of A1 (in A0), and say what the candidate is when it fails (not applicable, or a named substitute with the censoring bias flagged); revise the claim "every input passes the runtime-information test" to "passes if the following sources are used".

**Response (proposer).** [round 1 reply, verbatim excerpt] "PARTIAL: CH-0024 (operational definition of need = called in a successful dev run of pi_ref, never annotations; q_hat = pilot reach; censoring where pi_ref cannot run accepted as a limit; whether the proxy works is HYP-0014, OPEN)." [rounds used: 1 of 2]

**Round 2 (challenger): MAINTAIN (serious), narrowed to three residuals.**
1. **Contradiction with DPR-0004 3.2a(iii).** The reply restricts the claim "to catalogues where `pi_ref` or a named substitute runs -- which is also where the rival C-0 is feasible". But section 3.2a names, as a regime in which C-A can beat C-0, "`n*L_t` exceeds the context", i.e. exactly where `pi_ref` cannot run and `p_hat` is censored (a named substitute is a restricted policy and censors; tools it never surfaces get `p_hat = 0`). Either regime (iii)'s overflow half is outside A1's estimability (then it cannot be listed as a regime in which A1's `F` can win), or A1 needs an estimator that does not require `pi_ref`.
2. **Denominator and success filter.** "Share of dev sessions in which `t` is needed" with need = called in a *successful* run: if failed sessions contribute zero need, `p_hat` is biased toward tasks `pi_ref` solves, and the direction is unknown. State the denominator (all dev sessions or successful ones) and the bias.
3. **Table not updated.** Section 5 rows `p_hat` still say a "gold-derived pool replaces" `pi_ref` (class P in disguise) and do not match the new definitions.
I accept that label source for `q_hat` is now stated (pilot reach, no annotations) and withdraw that sub-point.
