# Title: Verdict labels and small quotation defects

**Grade: MINOR.**

**Objection.**
1. **Verdict scale.** All three topics get PARTLY. For the exact question asked (a measurement of the rate at which a model requests a tool when none visible fits; memory of tool use across sessions in a large catalogue) the answer is NO in the stored texts, with adjacent evidence. PARTLY for B and C is a label for "neighbouring measurements exist", which a reader will take as "half answered". Suggested split: "answers the exact question? NO / adjacent evidence: (list)". Topic A is genuinely PARTLY (mechanism documented, third-party number absent; CH-0065).
2. **MCP-Zero "instructed"** is supported in `05` by the cookbook sentence (EXT-0101 lines 93-100), which is advice to adopters. The experiment-level support is EXT-0101 lines 71-72 (required to retrieve the target) and 140-142 (base prompt says "output the server and tool you need"). Cite those.
3. **SING** "Table 1 read by position" is used to reproduce the differences 8.1/10.1/6.8/4.8; they reproduce arithmetically (47.1-39.0, 45.1-35.0, 47.1-40.3, 45.1-40.3). Fine; but `05` does not mention SING's Default setting as the no-discovery reference (SING:953-956), which is exactly the comparison relevant to our reference policy.
4. **Line citations in SUM-0005 for Slite are off by one:** "-23% cost per question, and -12% response time" is at SL line 158 (steward SL:159); 17 tools at 156, 65+ at 157. Harmless, but the steward's citations are the verification instrument.
5. `05` says the Apple public study was "single runs" and "failures were formatting specifications"; both correct (arXiv 2607.09493 lines 43-46, 555 per steward). The statement "0/12 with no memory" omits that the task is built so that the specification is withheld, i.e. the no-memory arm fails by design (lines 29-31).
