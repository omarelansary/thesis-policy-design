# Title: the correction-2 bound is correct but is an assumption-free decomposition; assumptions A1-A6 mix validity, slack and estimability, and the estimator of M(F) does not target the event in the bound

**Grade: SERIOUS (the stated conclusions, withdrawal of `epsilon := delta` and end-to-end noninferiority, are right; the reasoning around them is not).**

**Objection.** (design/package-v3/01-errata-AUTH-005.md section 2.)
1. **The inequality needs none of A1-A6.** `Y_ref - Y_CA = P(Y_ref=1, Y_CA=0) - P(Y_ref=0, Y_CA=1) <= P(Y_ref=1, Y_CA=0)`. Split the event on "some needed deferred tool was not reached": the first part is contained in the union over `t` of `{R_t, t unreached}`, with probability at most `sum p_t q_t` by the union bound (true for any dependence, because `R_t` implies a successful reference run); the second part is `I` by definition. So `Y_ref - Y_CA <= M(F) + I` holds for *any* definitions of `p_t`, `q_t`, `R_t` consistent with the conditioning, and "only under assumptions A1-A6" is wrong as a statement about validity. A2 and A6 only describe where the bound is *loose*; A5 is the proof step; A3 and A4 concern **estimating** `M(F)`, not the inequality. The errata should say so: otherwise a reader thinks the bound is conditional on six checkable things, when its only content is that `I` absorbs everything else.
2. **Because `I` is unbounded, the inequality has no use as a design criterion.** It is a decomposition, not a guarantee. The errata concludes this correctly in the consequences paragraph but still presents A1-A6 as the conditions "for the bound".
3. **`I` is mislabelled.** `I` is defined relative to the *reference run's* needed set. A C-A trajectory that fails because it needs a tool `t'` that the reference run did not call, and `t'` is unreached, lies in `I`. So `I` contains coverage failures on non-reference-needed tools, not only "interference (contract tokens, turn budget, distraction, argument errors)". The parenthetical in the errata under-describes `I`, and the claim that `M(F)` "bounds only the coverage-attributable part" is true only for reference-needed tools.
4. **Estimator versus event (missing assumption).** The event in the bound is "t is not reached by C-A in its actual run", which includes (a) ranker miss, (b) model non-initiation, (c) search budget exhausted. v2 defines `q_t` from "a pilot of the search path" and lists ranker recall on *scripted queries* as the test (`package-v2/01` section 7, row A3; section 4, `q_t`). A pilot with scripted queries estimates (a) only. Non-initiation is the risk DPR-0004 itself calls dominant (HYP-0010, unmeasured). If `q_hat` omits (b) and (c), `M_hat < M` by an unknown amount. Neither A1-A6 nor the token form says which `q` is meant. The token form uses `(1 - q_t)` as the probability that a needed tool is discovered; there too `q` must include initiation.
5. **A3 in the large-catalogue regime is vacuous by arithmetic.** "Sample estimates need upper confidence bounds." For a deferred tool never seen as needed in `N` dev tasks, the usual 95% upper bound on `p_t` is about `3/N` (rule of three), with `q_t <= 1`. Summed over `n_u` such tools: `3 n_u / N`. [illustration, S: `n_u` 9,000 unseen tools, `N` 1,000 dev tasks gives 27.] A per-tool sum is the wrong object; the quantity that matters is the unseen *mass*, which needs a joint estimator (see CH-0038) and its own sampling assumption (iid tasks). This is the same point as Correction 4 seen from the other side and should be cross-referenced there.
6. **A4 is listed as an assumption and contradicted in the same line** ("`q_t` does not depend on the surface (see correction 3: it does)"). It should be stated as known false, with the direction known only for fixed-score rankers (which the errata does give).

**Evidence.** Errata section 2 read in full; `package-v2/01-policy-candidate.md` sections 4 and 7; DPR-0004 as quoted there. No extract bears on the logic; the point is internal. I could not run any numeric check (no Bash); the arithmetic in 5 is by hand.

**What would resolve it.** Rewrite section 2: (i) state the inequality as an assumption-free decomposition and say what each of A2, A6 loosen; (ii) move A3, A4 to an "estimability" list and add A7 "the estimator of `q_t` targets the actual-run non-reach event, including initiation and budget exhaustion"; (iii) relabel `I`; (iv) mark the sum of per-tool upper bounds as vacuous beyond a stated `n_u / N`.
