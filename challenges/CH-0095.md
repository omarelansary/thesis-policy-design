# Title: slot 2 describes OpenAI offering by `allowed_tools` only, omits `additional_tools`, and does not tie the "two providers" headline to the student's API

**Objection.**
1. Slot 2 (03 L28) gives OpenAI one offering mechanism, `allowed_tools` with `tools` held stable. The stored OpenAI pages also document a developer-role `additional_tools` input item that makes tools available "at a specific point in the conversation", with the instruction to preserve its position (L/v5-openai-tool-search L870-L899; L/v5-openai-prompt-caching L443), and a limit: "`additional_tools` input items do not currently accept `prompt_cache_breakpoint`" (prompt-caching L95). That is OpenAI's counterpart of `tool_addition`, and its cache constraint is relevant to M3. 04 M3 says "OpenAI: allowed_tools or preloaded search output". `allowed_tools` restricts which tools are callable but all definitions stay in the prefix, so it cannot "offer a seed set" of deferred tools. The map has no row for the mechanism that could.
2. 04 section 1 sentence 2 (L7) and 01 L32 use "two providers now let a policy change what is offered per turn" as the premise of the V5 design. The Anthropic mechanism is beta, listed models only (midconv L18-L20, in the map as "model- and platform-limited"); mid-conversation system messages are "not available on Claude Sonnet 5". The student's API is a free university API with several models (REQ-U21-01) and the map says nothing on whether it exposes either mechanism, or even native tool search. The map's item 1 in section 10 (university API cache fields) covers cache fields only. If the university API offers neither, V5-R's M3 and P0b reduce to client-side appended search and "restrict by prompt", which is not what the map's REUSE verdicts describe.

**Evidence.** Files and lines above; REGISTER REQ-U21-01 (L101); 03 L28-L29, L111.

**What would resolve it.** Add an `additional_tools` row (REUSE+CHANGE, with the breakpoint limit). In section 10 add "which of the vendor mechanisms (deferral, search, offering) the university API passes through" as the first PoC reading, and mark the slot-2 and slot-3 REUSE verdicts "if the API supports it".
