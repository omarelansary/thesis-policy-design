# Title: C11 and C12 are cited against vector memory but both use vector retrieval, and "nothing found argues for" a memory service leaves out the scouts' contrary rows

**Objection.** (a) `15` s7 says C11 and C12 support "plain Markdown memory, no vector, graph or SaaS memory service", and s4.2 offers C12 as "a plain file is a reasonable baseline". The stored pages say otherwise on the "no vector" part. C12 (Letta blog): "Files in Letta are automatically parsed and embedded to enable semantic (vector) search over their contents. The agent is given tools for semantic search (search_files), text matching (grep), and answering questions" (`v5-ls-c09-letta-blog-benchmarking-ai-agent-memory.txt` L22; SUM-0063 C12 notes the same). C11 (independent testbed): "Vector embeddings for mem0, Graphiti, cognee, and the RAG baseline are produced by OpenAI's text-embedding-3-small" (`v5-ls-c03-arxiv-pdf-2601.07978.txt` L481-482); mem0 is "a vector-based system" (L285) and it scored highest on accuracy (81.08 against RAG 78.31). So both results support "plain retrieval baseline matches memory services at lower cost" and "graph did worse", not "no vector". The V5 rule (plain Markdown, REQ-O21-09) does not need them, but the record claims they support it.
(b) "Nothing found argues for adopting Mem0, Zep, Letta, Hindsight or similar" is unqualified. Rows in scout C and F that point the other way are unchecked and unmentioned: C6 (Zep: on a 115k-token LongMemEval history, full context 60.2% against Zep 71.2%, context 115k to 1.6k tokens); C20 (Hindsight: full-context OSS-20B 39.0 against 83.6, vendor-authored); C24 (Supermemory file-based: "cuts cumulative token usage by 3x", no baseline stated, vendor); F26 (Mem0: more than 90% token cost saving, vendor table; accuracy below full context); F29 MERIT (stored `v5-ls-f20-arxiv-pdf-2609.05441.txt` L27-28 and L379: "full replay is never economical", which conflicts with the F27/F28 reading `15` s4.3 uses); E25 (DreamBench-SWE, stored `v5-ls-e08-arxiv-pdf-2608.20664.txt` L16-17: a plain verbatim event memory scored 82/180 against 97/180 for one pinned hosted Mem0 configuration). Several of these are long-history or vendor results and may not transfer to V5's regime; that is an argument to state, not to omit.
(c) The sentence is true only if scoped to "for choosing which tools to offer" (which scout C's absence supports, unchecked); it is not true of conversational recall, which the human and supervisor include in V5 (short summary).

**Evidence** as cited; SUM-0063 C12; SUM-0062 C11; `inputs/scout-reports-landscape-20261028/C-memory-frameworks.md` rows C6, C20, C24; `F-cost-caching.md` rows F26, F29; `E-evaluation.md` E25.

**What would resolve it.** Replace "(C11 and C12 support this)" with what they show (retrieval baseline cheaper than memory services; graph worse; neither tested without vectors); scope the "nothing found" sentence to tool offering and add one sentence naming the long-history and cost-favourable rows and why they may not apply (history length, vendor source, no tool task); check or label C6, C24, F26, F29, E25.
