# Title: A1 assumes deferred definitions cost nothing per turn, which is the same unknown that kept withdrawal out of the candidate

**Grade: SERIOUS (if the assumption is false on a provider, A1's output is wrong there; fixable by an explicit applicability condition).**

**Objection.** A1 Step 1 prices a kept tool at `r*L_t*T_bar` and a deferred tool at zero unless needed. That is valid only if deferred definitions contribute nothing to billed or model-visible tokens per turn. DPR-0005 section 4 rightly keeps by-reference withdrawal out of the candidate because "no passage says whether withheld/withdrawn definitions count toward input tokens" (steward V2 CANNOT DETERMINE; ledger row 5 UNSUPPORTED). The same passage (EXT-0058) names `defer_loading: true` as "withheld"; EXT-0009 says every deferred definition is still sent in the `tools` array on every request and only says the API "excludes deferred tools from the system-prompt prefix". So the billing of deferred definitions is exactly the unestablished quantity, yet the candidate's core cost model depends on it while the withdrawal arm is excluded for it: inconsistent treatment. It is also provider-dependent: on OpenAI's default the model "still sees the name and description" of a deferred function (EXT-0010), so deferred is not "not listed" there, which makes the C-A grade set (full / not listed) impossible to realise natively; a custom search tool with appended definitions has no documented cache-preserving mechanism outside the vendor features (A0 asks for it but cannot verify it).

**Evidence.** DPR-0004 section 4.2 A1 and section 4.3 ("Two [grades]: full and deferred (not listed)"); EXT-0009 l.27, l.37; EXT-0010 l.51; EXT-0058 l.31; SUM-0003 V2; DPR-0004 ledger rows 5 and 6.

**What would resolve it.** (i) List "deferred definitions add zero billed and zero model-visible tokens per turn" as an explicit assumption of A1 and of the cost claim; (ii) A0 must include a billed-token probe (same request with and without deferral, read the provider's token counts), and a probe that an appended definition does not change the cache-read count of the prefix (the current probe, a repeated identical request, does not test append); (iii) or add a per-deferred-tool listing term `ell_t` to Step 1 and call the OpenAI-default shape a different arm.

**Response (proposer).** [round 1 reply, verbatim excerpt] "CONCEDE: CH-0021 (c_def is an A1 input and A0 measurement; if deferred definitions are billed in full A1 returns F=K)." [rounds used: 1 of 2]

**Round 2 (challenger): WITHDRAW.** Checked: A0 now measures `c_def` from usage fields and A1 uses `(L_t - c_def,t)`; with `c_def = L_t` Step 1 keeps everything. Note (minor): the section 5 runtime table rows for A0 and A1 do not yet list `c_def`.

**Outcome.** resolved (conceded).
