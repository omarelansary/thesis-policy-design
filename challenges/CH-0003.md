# Title: for a tool that has been removed, none of the register's legitimate observables can indicate it was needed except the model's own request, which the draft calls unmeasured

**Objection.** DPR-0001's rule for S13 ("this tool turned out relevant") is that it is usable "only through a named observable: a call (S6), a result (S7), or the model's request (S8)", with the rule that a call counts only if "the tool was reachable (not removed) when the call was attempted". Combine the two:
1. For a tool that has been removed (the case REQ-O14-15 describes: "filtered out a tool at stage four ... at stage five ... you can go back"), S6 and S7 cannot occur for that tool by the draft's own reachability rule (and by the vehicle: unexposed tools are rejected; the unknown-tool error lists names from the exposed surface, so it "cannot reveal an omitted tool"). So the only remaining route is S8, the model asking. The draft itself records that initiation failures are observed in stored sources and unmeasured as a variable (S8 row). Therefore the register supplies no legitimate observable for "a removed tool was needed" that does not depend on the model initiating a search. This is not stated as a conclusion in the draft; the table lists S13 as if it were reachable.
2. The register omits signals a system-initiated trigger would actually have to use, and each carries its own error cost: (a) the model's text expressing inability or asking for a missing capability (a derived reading of S5, needing a classifier, i.e. an S11-type judgement with false positives and false negatives); (b) the termination event (the model ends the turn or issues a final answer without success evidence), which is a decision point not in the D0-D4 list: PlanBench-XL and TheMCPCompany report agents that "acknowledge and terminate" or fail to recover even when a useful tool reappears, so the trigger must live at termination, where success is X; (c) no-progress or repeated-failure patterns over S6/S7 of other tools; (d) system re-ranking of `K` using `h_s` at D1 (R by construction; its reliability is exactly what is untested). None of (a)-(d) is named in the register. [I] I do not claim the draft's falsifier ("a plausible policy whose behaviour cannot be placed at some D-point with a signal from the register") is strictly met: (d) uses S1, S2 and S5, which are registered, and a termination turn can be read as a D1 point. The defect is narrower: the register does not say that each of (a)-(d) is a derived reading of R signals whose classifier error is a cost, so the cost of a wrong trigger is invisible in sections 4-5.
3. Cost when nothing was missed is determined by the false-positive rate of whichever observable is used; the draft's section 5 has a `recover(pi)` term but no link from trigger error to cost.
