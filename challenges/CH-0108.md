# Title: derived or inferred values sit under an [F] header in the reference-case table

**Objection.** `11` s4 is headed "per 1M tokens, [F]". Some cells are not stated by a page:
- RC-5 cache read 0.10 for Qwen3.8-27B (Alibaba). The model-pricing page prints no cached price for qwen3.8-27b (only the words "context caching discount", L2998-3007). The 20% comes from the implicit-cache sentence that applies to every model not named in an exception list (context-cache L1135), so it is an inference by exclusion [I]; the same page says "The discount rate for these tokens varies by model" (L1133). FND-0043 A7 says the same. `11` s1 P4 also lists the explicit-mode 10% / 125% as fact; the page says "typically" (L43, L56, L60) and exempts qwen3.8-max, 2.4t and flash (L516-518); whether qwen3.8-27b supports explicit mode is not shown in the lines checked (L127, L134 list models for the feature, not the mode).
- "No write fee" for DeepSeek, Groq, Fireworks, Z.ai in P1 and the w row is an absence on the page, not a printed statement (Groq prints "no additional fees"; the others do not).
- o values (5.7, 4.2, 3.3, 3.1) and r values are the lead's division [D], which the s2 header says, but s4 does not.

**Evidence.** `v5-lit-alibaba-model-pricing-20261027.txt` L2998-3007; `v5-lit-alibaba-context-cache-20261027.txt` L43, L56-61, L1133-1135, L516-518; FND-0043 A1, A7, A8.

**What would resolve it.** Mark RC-5's cache price [I] with the reason, mark "typically" ratios as such, and mark "no write fee" as "none listed". No number changes.
