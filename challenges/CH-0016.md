# Title: smaller points: a requirement is used as the reason to include recovery, the P-class "demonstration" test is not operational, and wording on the 2026-10-02 reading

**Objection.**
1. **Requirement-driven inclusion (the proposer's question 3).** DPR-0002 section E says the fallback is treated "as an input and tests its price, not as proof it is worth it". DPR-0003 Card D, J says "Include a minimal append-only re-add path because REQ-S2 lists a fallback as Required (earlier reading)". These differ: one tests, the other includes by authority. REQ-S2 is the earlier researchers' classification of a 2026-10-02 statement (REGISTER section B: "authority: supervisor; reading: researcher"); REGISTER G.3 Q4 (does "each step saves tokens" still bind a design that re-adds) and Q6 (does the 2026-10-21 deliverable replace the 2026-10-02 one) are open and E8 is permissive ("you can go back"). The same quote (EXT-0002 s1.2: "some way for the LM to query the tools that is in the passive registry") describes a model-initiated path; it does not require a system-initiated N4. My position: treating the 2026-10-02 reading as an input that the design must address is fine; using it as the reason for any node is not, and it can justify at most one path (N3). If the human later drops the requirement, the card's J disappears. This is a wording and structure issue, answerable now.
2. **P-class demonstration test (question 1).** DPR-0001 R5: a P-class signal is legitimate if it "is shown to exist at decision time in a described deployment without the benchmark's annotation ... and its production does not depend on the reference solution". It can fail in principle (if the signal cannot be produced without gold) but as written it is judged by narrative: "described deployment", "no access". It is not unfalsifiable but it is not operational. A checkable form is an information-flow test: the component run with the benchmark's annotation fields removed or permuted yields the same output. Also the test admits a signal "produced by a component that would exist outside the benchmark" without requiring that the benchmark run use that component at its real error rate rather than the annotation as a stand-in; the second clause covers this but the example does not show it. Answerable now.
3. **Class of derived signals.** S19 and S16/S17 are labelled "R input, derived output" in a column titled "Class". The class of a derived signal is the strictest class of its inputs and of its model's training data (see CH-0011 items 2-3). The register should say that rule once.
4. **Stage-five example.** The Mermaid N4 box and the node table follow the supervisor's E8 shape (a later stage re-adds). The DPR says E8 is not used as evidence, and HYP-0006 gives a separate basis. Agreed; but the basis is the confounded FitText contrast (CH-0012), so at present the only support for the shape of N4 is the supervisor example. This should be said in Card D, C or J.

**Evidence.** DPR-0002 section E; DPR-0003 Card D; DPR-0001 R5; REGISTER G.3 Q4, Q6 and section B; EXT-0002 s1.2; INT-T-001 E8 (read).
