# Title: reason 1 for choosing C-A over C-B ("a miss is an observable event") does not hold at runtime and does not discriminate

**Grade: SERIOUS (it is the first-listed reason for the choice and the one tied to the strongest evidence).**

**Objection.** DPR-0004 section 3.1(1): "A deferred tool is reachable through a call the system can observe (S); a miss is an observable event (search with no useful result, or no search). In C-B a trigger false negative is invisible." (i) "No search" is the absence of an event. At runtime the system cannot distinguish a session that did not need `t` from one that needed it and never searched; `q_hat` explicitly includes non-initiation. A C-B trigger false negative is equally unobserved at runtime. (ii) Both failures are estimable only offline against labels (`q_hat` for C-A, trigger precision/recall for C-B), so "can be estimated and constrained" holds for both. (iii) The EXT-0053 reachability gate (pass^3 0.0% on tasks whose required tools the retriever never surfaced; V6: rag:8 only, 48% reachable) concerns a one-shot retriever with no recovery path; it shows that reachability matters, which is symmetric across C-A and C-B, and says nothing about the model-initiated path. (iv) The risk that applies specifically to C-A is non-initiation, for which the nearest evidence points the other way (EXT-0047/0048: Haiku 4.5 25.7% of diagnosed failures are no-tool-use; V8 PARTLY, tools' visibility not stated).

**Evidence.** DPR-0004 section 3.1(1), section 3.3; SUM-0003 V6, V8; EXT-0047, EXT-0048, EXT-0049.

**What would resolve it.** Restate reason 1 so that it does not claim runtime observability (for example as "the miss rate is directly estimable on dev under the same interface"), say that this holds equally for C-B, and say which reasons for preferring C-A over C-B actually survive (cache-stability holds for C-B on a by-reference provider per A0; special-case containment is the remaining one).

**Response (proposer).** [round 1 reply, verbatim excerpt] "PARTIAL: CH-0026 (conceded: runtime observability does not separate C-A from C-B; reworded to agent-recoverability; REBUT that it separates nothing: the model can re-query in C-A, not in C-B, conditional on HYP-0010)." [rounds used: 1 of 2]

**Round 2 (challenger): DOWNGRADE serious -> minor; my title overstated.** "Does not discriminate" was too strong. A residual difference exists: if the model initiates but the first result misses, it can re-query in C-A, whereas in C-B a trigger false negative leaves it no channel. It is conditional on initiation (HYP-0010), which the reworded 3.1(1) says. I checked that 3.1(1) no longer claims runtime observability and that the EXT-0053 gate is stated as transferring only as "unreachability is costly". The reason is therefore a conditional hypothesis, not evidence for choosing C-A; leaving it in the list of "reasons chosen" is acceptable only with that label.

**Outcome.** resolved in substance; residual minor (label).
