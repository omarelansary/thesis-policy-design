# Title: Observation masking (H) stays in the default on one coding-agent study, against evidence in the same reuse map, and its beta status is not stated

**Objection.** `04` section 1 point 3 lists observation masking among the "established parts ... adopted as they are". The only support is one study of coding agents whose cost was API-reported for one model and priced post hoc, without a cache-hit distinction, for another (`03` row 75). The same map holds the opposite weighting: tool outputs were about 3.3% of cost; a 38.4% cut in tool-output tokens was about 1.3% of total cost and raised paired cost 6.8% (`03` row 80); context editing "Invalidates cached prompt prefixes" and each clear incurs a cache write (`03` row 76). DPR-0008 section 4 rejects H with these numbers; `04` does not answer them. `04` section 5 lists when H fails but not why it should be in the default at all. Context editing is a beta feature (`context-management-2025-06-27`), but `04` section 8 names only the offering mechanism as beta. The V5 hypothesis HYP-0021 does test it, so H could be an arm instead of a default stage.

**Evidence.** `04-design.md` section 1 point 3, section 3 (H node), section 5 (H row), V5-R08, section 8; `03-reuse-map.md:75, :76, :80`; `L/v5-anthropic-context-editing-20261022.md:31, :71`; `design/proposals/DPR-0008.md` section 4 (last bullet), section 7 E.

**What would resolve it.** Either move H out of the default and keep it as P4's arm, or state why 3.3% / 1.3% do not apply (workload with large tool results) and add the beta flag and provider dependence to section 8; reconcile `03` rows 75 and 80 in one sentence.
