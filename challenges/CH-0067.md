# Title: The check is a convenience sample of three queries; obvious literature is named inside the stored texts themselves and was not read

**Grade: SERIOUS for B and C (the verdicts "PARTLY" and "real gap" depend on absence), minor for A.** `05` section 3 already says "not systematic"; the objection is that the sample is not only unsystematic but misses items that the stored texts point to, and that "a real gap" in `05` section 2 is stated more firmly than that disclaimer allows.

**Objection.**
1. **Named in the stored texts, not read.** KAIST says "related works such as BFCL V3 (Patil et al. 2025) and When2Call (Ross, Mahabaleshwarkar, and Suhara 2025) explore similar challenges" (K:75-80; see also K:125-128, 690-693 with ToolSandbox, Lu et al. 2025). [S] From my background knowledge (not from the workspace) When2Call concerns whether to call a tool, ask a follow-up or say it cannot, and BFCL has an irrelevance category; if so they measure how often models call a tool when none fits, over many models, and would be closer to B than KAIST's own data. Unverified; this is a reason to read them, not a finding. The cache study (EXT-0104 lines 70-83) bases its dynamic-function-calling statement on Lumer et al. 2024/2025b and Ji 2025, which are not read; if Lumer is the ScaleMCP/MemTool group (reference list not read, so [U]), the support may be sitting in the stored set.
2. **Families the three queries could not return.** For C: procedural or skill memory for agents (skill libraries, workflow memory, experience stores) persist which actions or tools worked across sessions; the lead's wording "no stored source" is about the stored set, but `05` section 2 item 4 turns it into "each [gap] has a named closest paper" and "memory of discovery in a large catalogue" as a gap. [S] My background knowledge, not evidence, says several such systems exist; I cannot name verified ones from the workspace. For B: adaptive-retrieval and "when to search" literature in RAG, and tool over/under-use calibration work. For A: third-party measurements of vendor tool search, KV-cache reuse for agent prefixes.
3. **Search design.** Three queries phrased by the lead around its own terms; results ranked by a search engine and read through snippets; hit rate on 2026 arXiv ids suggests recency bias; papers using different vocabulary ("function hallucination", "irrelevance", "skill library", "procedural memory", "tool retrieval agent-driven") would not surface.

**Queries I would run (names only; I have no web tools).** Of the 12 searches left:
1. When2Call tool-calling benchmark: follow-up question versus tool call versus unable to answer.
2. Berkeley Function Calling Leaderboard irrelevance detection / live irrelevance (rate of calling a function when none is relevant).
3. ToolSandbox insufficient-information scenarios.
4. Agent-driven tool retrieval evaluation: LiveMCPBench, MCP-Universe, MCP-Atlas, MCPVerse "model decides when to call the retrieval tool".
5. Independent evaluation of Anthropic tool search tool / OpenAI tool_search (accuracy, search-call counts, cache fields).
6. Tool over-use and under-use calibration (agents deciding whether to use a tool at all; self-aware tool use).
7. Agentic search-initiation rate in RAG (search-augmented RL agents, "adaptive retrieval when to search") as an analogue for B.
8. Procedural memory / skill library / workflow memory for agents across sessions (which tools or skills were useful before).
9. Personalised tool selection from user history (PEToolBench neighbours) with catalogue size.
10. Prompt caching with dynamic tool sets: KV-cache reuse for agent prefixes; position-independent caching.
Fetches (of 5 left): the arXiv 2601.06007 reference list (Lumer, Ji, Wang entries); the When2Call paper; the full OpenAI tool-search page (EXT-0010 is a partial navigation-heavy window); the Anthropic internal-evaluation description behind "49% to 74%"; the rest of `r3-anthropic-midconv` is already stored (753 lines, no fetch needed, read with the sanctioned tool).

**What would favour the opposite conclusions.** To overturn "initiation is a real gap": a paper reporting the rate at which models call a retrieval/search tool when the target is not in view, without instruction. To overturn "no cross-session tool memory in a large catalogue": any skill/procedural-memory study with a large tool set and success or cost across sessions. To overturn "append preserves the cache": a provider-side measurement showing cache misses on appended definitions (the documented exceptions in EXT-0066 are the first place to look).

**What would resolve it.** Human decision whether to spend the remaining AUTH-011 searches; if not, `05` should say "closest papers found" instead of "each has a named closest paper" and soften "real gap" to "gap in the texts read".
