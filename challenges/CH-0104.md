# Title: rows that rest on origin-derived records are not marked, so independence from the earlier work cannot be judged

**Objection.** REQ-U21-02 and the REGISTER L126 relation say earlier work enters only when the human places it explicitly and it is verified. The map's change log (03 L121) shows care on one point (the two-stage router sentence was removed). Other rows rely on origin-derived records without saying so: EXT-0228 (source `r4-github-copilot-fewer-tools`, retrieved 2026-10-11 by the earlier project, extracted via the origin tool); FND-0037 row C-S08/UNINSTR, which in turn quotes "ledger, FND-0016" (SUM-0039 L44); FND-0037 Q8 and EXT-0150, EXT-0142 for minimum cacheable length (03 L16); the Spring AI row (origin `r4-spring-tool-search-blog`, 03 L44). The Copilot blog is a public vendor page and is not retrieval work, so I do not claim contamination. The point is that the map does not mark which verdicts depend on the origin repository's earlier selection of sources and earlier negatives (for example "uninstructed search initiation: NONE FOUND" is the origin ledger's statement, not a V5 search), and the blind instances' independence check rests on their own path lists (01 L18).

**Evidence.** EXT-0228 front matter (source_id `r4-github-copilot-fewer-tools`, origin_head `67e5eeec...`); SUM-0039 L44; 03 L16, L44, L90, L121; 01 L18.

**What would resolve it.** Add a column or tag "origin-derived" to the rows above, and state for each NONE FOUND that comes from an origin record whether V5 re-searched it. This is a labelling fix.
