# Title: the Executor baseline is described by a README that shows intent search only as a CLI command

**Objection.** 03 L54 and 01 C11 (L49) say Executor offers "tool search by intent [F]", citing README L5-L7, L27-L32, L123. L5-L7 and L27-L32 describe a shared catalogue and per-tool policy ("allowed, gated behind approval, or blocked"). The only search text is the CLI example `executor tools search "send email"      # find tools by intent` at L123. Nothing in the stored README says that intent search is offered to a connected agent over MCP. The map says the MCP surface is scout-reported only, and 04 L69 repeats "to be read from its own MCP surface before the arm is defined". So the [F] on "tool search by intent" is true for the CLI, and the baseline's mechanism as a model-facing arm is [U]. REQ-O02-06 makes Executor a required baseline, and the supervisor says it "is doing the same thing" (REQ-O02-05). Until the surface is read, the map cannot say what the arm exposes to the model, and 02 L31-L32 (AS-09, AS-07) cannot be rated beyond "not addressed".
The numbers I checked (4,235 stars, MIT) were not re-read from the API JSON; I did not open that file.

**Evidence.** L/v5-executor-readme-20261022.md L5-L7, L27-L32, L123; 03 L54; 04 L69; 02 L31-L32.

**What would resolve it.** Qualify the [F] ("intent search from the CLI"), and list "read Executor's MCP tool listing" as the first step of defining the arm (already implied; make it a numbered item in 03 section 10).
