# Title: A2/A4 are the only runtime decisions and have no stated rule; the model is not given the information its decision needs

**Grade: SERIOUS (checklist items 1 and 7).**

**Objection.**
1. **No rule.** For A2 and A4 the actor is the agent model and the rule form is "none specified for the model; the instruction says to call S when no visible tool fits". The instruction text is deferred ("to be fixed on dev data", section 3.4(v)). HYP-0010 itself shows that prompted and unprompted search are different claims, so the instruction is the principal runtime lever and it is unwritten. That is acceptable as "the model's policy; the instruction is the rule" only if the instruction's content is a stated decision, not a dev-tuning detail.
2. **Awareness.** A2's question, "does a visible tool fit; if not, is a capability missing?", needs the model to know that a deferred capability may exist and roughly what kind. Section 4.3 sets the deferred grade to "not listed". The section 5 inputs for A2 (request, transcript, surface, instruction) do not say what tells the model that `D` is non-empty or what it covers. A one-bit statement ("more tools exist, search for them") leaves the model unable to tell when a visible tool is a poor approximation (the "latent" intermediate tools of EXT-0026); a coverage statement is a listing whose size grows with `n`, i.e. the listed grade the candidate excludes. This is information the actor needs and the table does not supply or cost.
3. **Which evidence applies.** FitText's prompt (EXT-0065, V5) makes retrieval mandatory and leaves "Finish" as the only starting function; vendor tool search is described as trained-in behaviour (EXT-0010: "Our models have primarily been trained to search those surfaces"). Neither is C-A's custom instruction on a mixed surface; HYP-0010 already says so, but DPR-0004 section 5 treats A2 as a clean row.

**Evidence.** DPR-0004 sections 3.4(v), 4.2 rows A2/A4, 4.3, 5; HYP-0010; EXT-0010 l.47; EXT-0026 (via the evidence map); EXT-0065 and SUM-0003 V5.

**What would resolve it.** Add to the runtime table a row for the instruction: its information content about `D` (existence only, or coverage), its token cost (in `F`), and the rule by which the model is to decide; list it among the missing decisions with the same status as `epsilon`.

**Response (proposer).** [round 1 reply, verbatim excerpt] "PARTIAL: CH-0027 (interface contract specified by content; scope statement counted as exposure; REBUT the demand for a rule at A2/A4: the actor is the model, its behaviour is the measured variable)." [rounds used: 1 of 2]

**Round 2 (challenger): DOWNGRADE serious -> minor; my point 1 was partly overstated.** Demanding a decision rule at an agent-model node was a category stretch: for a model actor the rule is the contract plus the measured behaviour, and DPR-0004 4.2 now specifies the contract's content (subset statement, scope statement counted as exposure, search before answering without tools, budget `B_s`). That answers the awareness gap (my point 2) at the level of content. Residuals: (i) the scope statement `varsigma` is a coarse listing whose size depends on the composition of `D`; it is counted as exposure but is not a term in A1's keep/defer comparison, and section 4.3 still says deferred = "not listed"; (ii) the section 5 table row A2 still lists only "instruction" and has no row for the scope statement.

**Outcome.** resolved in substance; residual minor.
