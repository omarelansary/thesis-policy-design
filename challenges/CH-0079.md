# Title: D-01 assumes deferred tools cost nothing after the core; a stored user report to the contrary, flagged by blind B, is not weighed

**Objection.** D-01 prices the deferred catalogue at zero (`deferral`: prefix = core + search only). A stored Claude Code issue reports ~103k tokens of "deferred" MCP and system-tool schemas "loaded into the cache and re-read on every API call" in a long session (`L/lit-ccissue-59650-deferred-cache-reads.txt:21-41`). Blind B listed it as a reported problem and marked the contradiction with the vendor's "prefix untouched" statement [U] (`inputs/blind-output-B-20261022.md:104`). `03`, `04` and DPR-0007 do not mention it. It is one uncontrolled report, closed "not planned", and the figures may be a display of names or of loaded definitions [U]; but if it holds on the user's route, the deferral/expose-all ratio in the regime table for the deferred share goes toward 1 and the regime boundary and the whole "above a few dozen tools the question is accuracy" conclusion (`04` section 1 point 1) fall. The only check is P5, which is last in `05` and absent from V5-R09. `03` row 40 also records that `defer_loading` with `cache_control` is rejected on one tool; the consequence for the cached core is not discussed.

**Evidence.** `L/lit-ccissue-59650-deferred-cache-reads.txt:21-41`; `design/package-v5/inputs/blind-output-B-20261022.md:104`; `L/v5-anthropic-tool-use-caching-20261022.md:49` (vendor statement that the prefix is untouched); `04-design.md` section 1 point 1, section 6 V5-R09; `05` P5.

**What would resolve it.** Read the usage record (cache read tokens, input tokens) of one deferral request with a known deferred catalogue, before and after one search, on the provider to be used; move that reading to P0 (it costs a few requests) and mention the report in `03`/`04` as a counter-lead.
