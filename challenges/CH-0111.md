# Title: "V5's design conclusions do not depend on which model or host is chosen" is stronger than a grid over r, w, o can show, and `11` s3 lists the host-dependent quantities that the grid omits

**Objection.** `11` s5: "V5's design conclusions ... do not depend on which model or host is chosen. They depend on the measured number of searches per session, matches per search and session length." D-04 varies only three ratios (r, w, o) with everything else fixed in the script header: core = 5 tools + 300-token search tool (1,550 tokens), d = 250, H = 5,000, q = 150, cache always hit, cache always warm. Several of those are host or model properties, as `11` s3 itself says:
- minimum cacheable length (Groq 128-1,024, MiniMax 512, Alibaba 1,024, Anthropic up to 4,096): whether the 1,550-token core is cached at all differs by host. The uncached-core variant was computed earlier (D-01) and is not in D-04. In RV-0023 (CH-0080 row) I computed by hand an uncached-core n* of about 196-231 for d = 100, D = 10, above the cached-core figures; the grid in D-04 cannot show that.
- lifetime: Alibaba explicit 5 minutes, Groq 2 hours, the university models between 75 minutes and 5 hours (`10` s9). A returning user after a gap (the supervisor's horizon) meets a cold cache on some models; the scripts assume a warm one.
- d and q depend on the tokenizer and the tool-call template (d = 250 is not model-specific in the script header; no source in `13` gives per-model token counts for the same schema).
- hit rate is "a measured quantity per provider" (`11` s3, AA; 2607.15516 gives rho 0.83 to 1.00 by prompt size).
So the supported statement is: "over r 0.02-1.0, w 1.0-1.25, o 2.1-7.5, with a warm cache that always hits and the core above the minimum length, the break-evens move with D, T and K more than with the price ratios (T = 10 only, see CH-0109/0110)". Model independence also needs minimum length, lifetime, d and hit rate, none of which D-04 varies. `13` s1 bullet 2 "break-even conclusions did not change in kind" repeats the point for ratios only, which is accurate; the `11` Consequence extends it.

**Evidence.** `calc/price_sensitivity.py` L1-10 (fixed assumptions); `11` s3 bullets 1-4 and s5 Consequence; `13` s3 last paragraph ("not in the first-order arithmetic ... except through its 'uncached core' variant"); `10` s9 (lifetimes); RV-0023 CH-0080 row.

**What would resolve it.** Reword the Consequence to name what was varied and what was not; or add to D-04 an uncached-core column and a cold-cache (first request of every session) column and report n* for them. Do not claim model independence until those are shown or the human accepts the narrower wording.
