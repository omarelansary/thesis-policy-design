# Title: DPR-0002 section A and F omit the nearest direct measurements and shipped mechanisms in the governing record, and state a cache rule as general that the record shows is provider-specific

**Objection.** (Answers the proposer's question 5.)
1. **Toollery is the nearest measurement of the cost-versus-accuracy question and is not used.** DPR-0002 section A says "No stored source measures billed cost of catalogue filtering together with task success (map, bounded negative: ledger C3-19, not re-read here)". The S4I governing erratum Q-1 (2026-10-16, which governs wording over the earlier records) adds Toollery: full library vs top-10 retrieval, "hit rate .989 (full library) versus .144 (retrieval) in the natural regime; input tokens -97.5%; billed-input-cost difference 'inconclusive' (95% CI [-$0.000524, +$0.000462]); -97.5% billed input with caching suppressed" (erratum L14), across natural, cache-suppressed and forced-warm regimes (L13). It measures selection hit rate, not task success; it is single-step; run by the method's authors; its Table 4 uses different selectors for the two arms (erratum L22). With those limits it is the direct instance for HYP-0005 (tokens -97.5%, billed cost inconclusive when cached) and for Card A (retrieval collapsed selection accuracy). Neither DPR-0002, DPR-0003 nor HYP-0005 mentions it. The literal sentence ("together with task success") may stand; the omission of the nearest instance does not.
2. **R-cache is stated as a rule; the record shows provider variation.** DPR-0003 R-cache: "during a session the prefix is never rewritten; tools are added only by appending after the cache breakpoint; removal only at a conversation boundary (EXT-0008, EXT-0014)". The record also holds: OpenAI's "changing the loaded tool set will break the model's cache from that point forward" (EXT-0011), a suffix break, whereas Anthropic's table says "Modifying tool definitions | Entire cache" (EXT-0008); and the ledger's C3-27: Anthropic's mid-conversation tool-changes beta "lets tools be added, defined by value or withdrawn without editing the cached tools array (first by-value definition may cost one cache miss)", with the limit "removal likely does not shrink prefix tokens of non-deferred tools (inference)" (ledger L39; not re-read by me at the original). So "removal only at a conversation boundary" and F7's "cache break" are provider- and beta-specific, and the mid-conversation beta is a shipped mechanism missing from section F.
3. **Hierarchical disclosure is described as a grade, not a hierarchy.** F4 and Card C cite "OpenAI default form (EXT-0010, per map): name and description visible, schema deferred". EXT-0010 (read) says the model "still sees the name and description" for an individual deferred function ("mostly deferring the parameter schema") and, for namespaces and MCP servers, "sees only the namespace or server name and description at the beginning"; the recommendation is namespaces. The supervisor's staged idea in its group-then-tool form is thus already a vendor-recommended shipped design, which section F does not state as overlap.
4. **Prior-art list is partial.** Section F lists vendor deferred search, FitText, on-device JIT, Skill Blocks, CE-MCP, ComplexMCP. The governing records also hold: Executor's passthrough mode `integrations`/`search`/`invoke` (ledger C3-23: the non-default mode), which is P5; Dynamic ReAct's `search_tools`+`load_tools`, hierarchical `search_apps`, and fixed set with `get_tool_info`+`call_tool` (S4H closure L55; mechanism description only, its efficiency claims must not be cited, erratum Q-4), which are P3/P4/P5 and a group-level design; MCP-Zero (model requests on a capability gap plus hierarchical routing; STAGE4_PRIOR_ART_COMPARISON L22, worker-reported); MemTool and Pichay session-scoped stubs for F8 (S4D quality addendum L29). "Executor" as the supervisor's baseline is an identification in researcher records (CAVEATS row 6). None of this is a novelty verdict; the point is that the overlap list under-reports shipped mechanisms covering P3, P4, P5 and the staged idea itself.
5. **Evidence-map inconsistency (lead's SUM-0002).** The map says the EXT-0044 window "did not contain its results" and that C3-04 is "not re-verified here"; the extract does contain the qualitative result statement ("CE-MCP architecture consistently reduces the execution time, token usage, and number of turns", section 6.2) but no figures and no task-success numbers, and DPR-0002 F5 correctly says so. Not an error by the proposer; the map should be corrected by its owner.

**Evidence.** DPR-0002 sections A, B, F; DPR-0003 R-cache, Cards C and E; S4I-GOVERNING-ERRATUM L13-L14, L22, L37; STAGE3 ledger L39 (C3-27), C3-23 (L35); EXT-0008, EXT-0010, EXT-0011, EXT-0044 (read); S4H closure L55; STAGE4_PRIOR_ART_COMPARISON L22; S4D quality addendum L29.

**What would resolve it.** Cite Toollery (with limits) in section A, Card A and HYP-0005; mark R-cache provider-specific with the OpenAI/Anthropic difference and the beta; describe F4 with group-level disclosure; extend section F with the items above under "overlap, verdict not made". All answerable now.
