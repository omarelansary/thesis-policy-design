# Title: the reference partition A_ref is "e.g. the C-A surface", which privileges C-A and rests on one reference route

**Grade: MINOR (it is pre-treatment, so not post-treatment conditioning; it affects interpretation, not validity of the contrast at fixed surface).**

**Objection.** DPR-0005 6.2 fixes `A_ref` "e.g. the C-A surface from dev data". For C-A the miss stratum `M = 1` then equals tasks needing a tool outside C-A's own `F`, while for P3-vendor or P1 with another core it does not coincide with their own misses. The within-surface recovery contrast (same `F` with and without `S`) is unaffected, but any cross-arm statement about "price in the no-miss stratum" mixes populations defined relative to a surface that is one arm's design. Also `R(x)` comes from a single reference route (acknowledged); a task with an alternative route inside `A_ref` is labelled `M = 1`, attenuating `V`.

**Evidence.** DPR-0005 6.2; DPR-0004 section 4.2.

**What would resolve it.** Define `A_ref` independently of any arm (e.g. by the dev-usage ranking at a stated cut that is not an arm's design) or report results under two partitions; add equivalence sets for `R(x)`.

**Response (proposer).** [round 1 reply, verbatim excerpt] "CONCEDE: CH-0031 (A_ref = dev-frequency core of a named size, not an arm's output)." [rounds used: 1 of 2]

**Round 2 (challenger): WITHDRAW.** DPR-0005 6.2 now defines `A_ref` as a dev-frequency core of a size named before the run with a second size as sensitivity.

**Outcome.** resolved (conceded).
