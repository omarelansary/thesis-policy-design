# V5-R: a staged and memory-informed tool-offering policy built from established parts

**Proposal.** The policy specified in `design/package-v5/04-design.md` sections 3 and 6 (V5-R01..R09): a deployment filter (S1) fixes which tools are declared, and the `tools` array never changes within a session; a regime switch (S2) chooses expose-all for small, non-caching tool blocks and a small core plus deferred tools with vendor search otherwise (D-01); a plain Markdown memory (M1, W) holds a short summary, tool question-answer pairs and the tools a user or role used; memory-informed offering (M2-M3) offers those tools at session start **after** the shared cached prefix, through the providers' offering mechanisms (Anthropic `tool_addition` by reference, beta; OpenAI `allowed_tools` or preloaded search output), never by editing `tools`; discovery (D) appends matches inline and is the recovery path; observation masking (H) applies to long single runs only when the cleared tokens pay the cache rewrite. The cost criterion is DPR-0006.

**Basis.** Every mechanism is reused from `design/package-v5/03-reuse-map.md` (sections 1-7), checked by three stewards (FND-0040..0042): cache hierarchy and deferral (EXT-0158, EXT-0131), OpenAI restriction at a stable prefix (L/v5-openai-prompt-caching-20261022.md:440-441), Anthropic offering at a fixed prefix (L/v5-anthropic-midconv-sysmsg-20261022.md:27, :452), minimum cacheable length (EXT-0150, EXT-0142), Copilot's shipped core-plus-groups design and its cache-miss cost (EXT-0228), the fixed prefix carrying most of the bill in coding agents (L/pdf-tokennotcost-2607.12161v5.txt:243), masking (L/v5-complexitytrap-2508.21433.txt:23-25), programmatic calling's mixed cost effect (EXT-0183), retrieve-then-select attack risk (EXT-0227). Derived arithmetic D-01, D-02 (`design/package-v5/calc/`).

**What is new.** Only M2-M3 (memory deciding which declared tools are offered to a returning user, placed after the shared prefix) and the per-deployment regime switch; neither was found measured anywhere searched (`03` section 5, `inputs/search-log-20261022.md`).

**Alternatives considered.** K0 expose-all with caching and a summary; K1 vendor deferral without memory; V4 unchanged; the proposer's simplest rival (DPR-0008); the blind alternative (DPR-0009); Executor as a baseline. Comparison: `04` section 4.

**Falsifier.** V5-R is not worth its extra parts if, in the proof-of-concept loop, (a) the share of memory-seeded tools actually used by returning users stays below the break-even h* of D-02 for the session lengths observed (HYP-0017), or (b) its accuracy is lower than K1's beyond run-to-run variation, or (c) the university API does not expose cache fields, so the bill terms that motivate the regime switch and the memory placement cannot be observed (HYP-0020).

**Assumptions.** Provider documentation of its own caching and offering mechanisms is accurate for the models used (vendor statements, dated 2026-10-22); the Anthropic offering mechanism is beta and may change.

**Not claimed.** No saving, no accuracy result, no novelty beyond the combination (REQ-O14F-03), no parameter value. Not approved; the human and the supervisor decide.
