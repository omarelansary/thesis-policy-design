# V5-R: the rival's core plus a deployment filter and a gated memory-informed offering

**Proposal (revision 2).** The policy in `design/package-v5/04-design.md` sections 3 and 6: the core of DPR-0008 (a byte-stable prefix; a per-deployment regime switch between expose-all and a small core with vendor deferral and search, set from D-01; discoveries appended inline as the recovery path; a short Markdown memory with an index of tool question-answer pairs), plus a deployment filter S1 that fixes which tools are declared, plus memory-informed offering M2-M3 that offers a returning user's previously needed tools after the shared prefix through the route the student's API supports. **M2 is off by default** and is switched on for a deployment only where `05` P1 measures a hit rate above the break-even of D-02. The cost criterion is DPR-0006.

**Basis.** Mechanisms reused from `design/package-v5/03-reuse-map.md`, checked by three stewards (FND-0040..0042) and reviewed (RV-0021, RV-0022): cache hierarchy and deferral (EXT-0158, EXT-0131), offering at a stable prefix (OpenAI `allowed_tools` and `additional_tools`; Anthropic `tool_addition`, beta), minimum cacheable length (EXT-0150, EXT-0142), Copilot's usage-based core and its cache-miss cost per group expansion (EXT-0228, vendor figures), the fixed prefix carrying most of the bill in coding agents (L/pdf-tokennotcost-2607.12161v5.txt:243), retrieve-then-select attack risk (EXT-0227). Arithmetic D-01 and D-02, revision 2.

**What is new.** Only M2-M3 as a combination (per-user seeding of tool definitions from a large catalogue after a shared prefix, judged on the bill). Personalized tool memory over small tool sets exists (`03` section 5). The regime switch is reused (Claude Code ships one; DPR-0008 proposes it independently).

**Why this and not DPR-0008 alone.** Only because REQ-U21-04 requires the staged policy and memory deciding the offering to be combined. On present evidence DPR-0008 is at least as good, and the arithmetic does not settle M2: the share of seeded tools that must be called ranges from about a fifth to a half, or "never" in long sessions with one match per search (D-02 revision 3). Keeping M2 gated makes V5-R equal to DPR-0008 wherever M2 does not pay. Seeds wait for the first user turn that names a task (the supervisor's "just by saying hi", INT-T-002 L219).

**Alternatives considered.** K0; K1; V4 unchanged; DPR-0008; DPR-0009; Executor. Comparison: `04` section 4.

**Falsifier.** M2 is removed (V5-R reduces to DPR-0008 plus S1) if, in `05` P1, the precision of the seed set (the share of seeded non-core tools called in the returning session) is below the h* that D-02 gives for the observed session length, matches per search, discovery mode and history size; or if seeded tools lower accuracy (stale memory). V5-R as a whole is not worth more than K0 on a deployment if `05` P5 shows the deployment below n*.

**Assumptions.** Provider documentation of its own mechanisms is accurate for the models used (vendor statements dated 2026-10-22); the student's API passes the mechanisms through (unknown until `05` P0).

**Not claimed.** No saving, no accuracy result, no parameter value. On present evidence the V5-specific addition is not established. Not approved; the human and the supervisor decide.
