# The simplest candidate: cached stable prefix, a regime switch on the tool block, deferral with native search, and a short summary

Labels: [F] stated in a cited source; [D] derived arithmetic (lead's calc files, first-order, no measurement); [I] interpretation; [U] unknown. Every parameter is a symbol and a decision for the human; no value is proposed.

## 1. Proposal
Call it **S-min**. It is the cheapest policy I can state that still touches every element of the objective (REQ-U21-07), and it is meant as the *bar* a staged or memory-heavy design must clear, not as a final policy.

Four rules, nothing else:
1. **Keep the prefix byte-stable and cached.** Everything that is the same on every request (system prompt, the always-loaded tool definitions) sits first, with the longest sensible cache lifetime for the expected return gap (a decision, symbol `L`).
2. **Regime switch on the tool block.** If the whole catalogue's definitions are small (total `P = n*d` below a break-even `P*`, a decision measured per provider), expose all of them in the cached prefix (the all-tools baseline of REQ-O02-01 *is* S-min in this regime). Otherwise load a small static core (`k_core` tools, a decision) and defer the rest behind the provider's native tool search, with discovered definitions appended after the cached prefix, never inserted into it.
3. **Recovery is the same search.** A model that finds the core insufficient asks the search tool; an empty result is the signal that nothing matches (REQ-O02-09). A cap on discovery calls per turn is a symbol `D_max`, a decision.
4. **Memory is one short text.** At session end, write a short summary of the interaction plus the question and answer of each tool call that mattered (REQ-O21-03), as plain Markdown (REQ-O21-09); at session start, inject it after the cached prefix. Memory does **not** choose which tools are offered; it informs the model, which then searches as in rule 3.

There is no stage graph, no router model, no embedding step of our own, no memory-driven pre-loading, no tool-result file store, no compaction.

## 2. Run-time steps in order
- **D0 session start or return.** (a) Read `P` against `P*`: pick the regime (rule 2). (b) If the user's role or invoker is known and the catalogue is already partitioned by it, drop the partitions that cannot apply before the prefix is built (a static filter, REQ-O14F-04, REQ-U21-09; only if it is free to compute). (c) Build the cached prefix in the fixed order tools, system, then messages (EXT-0009 states the caching order; the lead's pointer is C1 in `01` section 3). (d) Inject the stored summary after the breakpoint. (e) If the return gap exceeds `L`, the first request re-writes the prefix; nothing is done to avoid it other than the choice of `L` (and optionally one keep-alive request, a decision, only where `[gap-cost] < [keep-alive cost]` by the DPR-0006 arithmetic).
- **D1 each user turn.** Append the user message. Offered tools are the prefix tools only. Nothing is changed in the prefix.
- **D2 each model request inside a turn.** If the model calls a core or exposed tool, run it. If it calls the search tool, run it and append the returned definitions after the prefix (no prefix change). Count discovery calls; stop at `D_max` and answer with what is available.
- **D3 end of turn or session.** Write the summary text (one extra request, counted in the session sum of DPR-0006 section 3). Do not edit the prefix, do not clear old tool results, do not switch tools mid-session except by appending.

## 4. Evidence for each step
- **Rule 1 (stable cached prefix).** Cache is a prefix hierarchy (tools, system, messages); a change at one level invalidates that and all later levels: `L/v5-anthropic-tool-use-caching-20261022.md:57-63` (`01` C1). Prices: write 1.25x or 2x, read 0.1x, 0.05x or 0.025x (EXT-0085, EXT-0086, EXT-0152). OpenAI: whole rendered prefix must match (`L/v5-openai-prompt-caching-20261022.md:23, :35, :49`). Multi-turn agent study: caching cut cost 41-80%, and caching variants differed by 2-4 points on cost (`L/v5-dontbreakcache-2601.06007v2.txt:33, :414-423`) [F, one study; the catalogue was not varied]. Where the cost sits: system prompt plus tool definitions were 74.7% of billed cost in coding agents (`L/pdf-tokennotcost-2607.12161v5.txt:200-224`; EXT-0016) [F, one study; tool block not separated]. This is the reason the policy spends its complexity on the prefix and nowhere else.
- **Rule 2 (regime switch).** [D] `calc/regime_bill.stdout.txt`: with core 5, discovery one request, the tool-block bill ratio deferral/expose-all is about 1.0 at 20 tools of 100 tokens, 0.2 at 100 tools, and below 0.05 from 400 tools (lines 4-9, 39-55); at 20 tools of 100 tokens with three discoveries, deferral is dearer (ratio 1.7-2.2, lines 5, 24). Break-even catalogue size lies between about 10 and 74 tools at d=250 depending on reads per session and discoveries (lines 118-127). Inputs are the lead's assumptions (`regime_bill.py:11-14`: core 5, `H`=5,000, `q`=150, `k`=3), not measurements. Vendor-side confirmation of the sign: a vendor preliminary test found progressive loading dearer than static for a simple task at 40 tools and cheaper for a complex one (`L/v5-speakeasy-dynamic-toolsets-20261022.txt:67, :75-77`) [F, a few runs]. Minimum cacheable length: a small block may not cache at all (`L/v5-synthorai-mcp-overhead-20261022.txt:176`, self-reported), which moves `P*` upward [I]. Claude Code ships the same switch: MCP tools are loaded upfront while definitions are small and deferred beyond a window share (`L/v5-claudecode-mcp-20261022.md:1441, :1470`) [F]. The threshold value is a decision.
- **Rule 2 (deferral and append).** "The prefix is untouched, so prompt caching is preserved" (`L/v5-anthropic-tool-use-caching-20261022.md:49`); OpenAI injects discovered tools at the end of context, gpt-5.4 and later only (`L/v5-openai-tool-search-20261022.md:5, :7`). Search is not metered (EXT-0131); loaded definitions are billed as input (`L/v5-anthropic-tool-search-20261022.md:821-822`). Failure mode of changing the set mid-session: re-billed 13.5% of spend in a user report (`L/v5-ccissue-92033-cachebust-20261022.txt:180-190`) [F, uncontrolled].
- **Static core size by usage.** Advice of a few core tools (EXT-0012); a shipped staged design uses a core chosen from usage statistics and found a static list covers the needed tool 69.0% of the time against 87.5% (LLM) and 94.5% (embedding routing) (EXT-0228) [F, vendor benchmark]. This is the strongest evidence *against* S-min's weak core (see section 5).
- **Rule 3 (recovery).** Empty search is a result, not an error (`L/v5-anthropic-tool-search-20261022.md:658`); the "recovery signal" reading is [I]. Cap value: NONE FOUND (`03` slot 7).
- **Rule 4 (short summary).** Selective persistent memory kept 3.9K tokens against 7.7K for full history with no significant difference in completion (`L/arxiv-2607.09493.txt:20-36`) [F, small]; observation masking halved cost at equal solve rate in coding agents, which supports not re-sending history but is not adopted here (`L/v5-complexitytrap-2508.21433.txt:96-100`). Summaries share a cache cost: up to 7.2% of instance cost in that study (`:529-535`) [F], so the summary write must be counted.
- **Why no memory-informed offering (rejection evidence, not omission).** [D] `calc/memory_seed.stdout.txt:1-5`: seeding pays only when more than about a quarter to a third of seeded tools are needed in short returning sessions, and more in long ones (0.45-0.69 at T=30-100 for r=0.1). Part 2 (lines 9-15): a cached added block still costs 0.1 of a fresh send per request. The hit rate of memory seeding is unmeasured [U].
- **Why no stages.** Copilot's group expansion costs "a cache miss, an extra round trip" (EXT-0228); multi-step narrowing 1,000 to 10 is NONE FOUND as measured (`03` section 4); a retrieve-then-select stage is an attack surface (EXT-0227).
- **Why no tool-result store or compaction.** Tool outputs were about 3.3% of cost in one coding-agent study (`L/pdf-tokennotcost-2607.12161v5.txt:240-243`); a 38.4% cut in tool-output tokens was about 1.3% of total cost; programmatic calling was +8% on one benchmark (EXT-0183); clearing results invalidates the prefix (`L/v5-anthropic-context-editing-20261022.md:71`). All coding-agent or vendor evidence; other agent kinds [U].

## 5. When it loses (conditions, stated to be tested)
Each is a comparison on the DPR-0006 bill at accuracy nearly the same.
1. **Mid-size catalogues with a cheap offering mechanism.** If per-turn offering at a fixed prefix (Anthropic `tool_addition`/`tool_removal`, OpenAI `allowed_tools`; EXT-0158 aside, `L/v5-anthropic-midconv-sysmsg-20261022.md:27`, `L/v5-openai-prompt-caching-20261022.md:440-441`) raises accuracy or cuts wrong-tool errors with the definitions still cached, a stage that offers fewer tools beats S-min on accuracy at equal bill, and S-min's fixed core loses where wrong-tool errors dominate. Test: same cached prefix, same tasks, offered-set size as the only variable.
2. **Weak core.** If the static core's coverage of the needed tool is much below a routed or memory-informed set (EXT-0228 shows 69.0% static against 87.5-94.5%), every miss costs a discovery request (`H*r + o*q + definition write`). S-min loses when mean discoveries per session `D` exceed the break-even `D*` for the regime (`regime_bill.stdout.txt:118-127`).
3. **Returning users with stable, repeated tool needs.** Memory seeding beats S-min if the seeded hit rate exceeds `h*` (`memory_seed.stdout.txt:1-5`). Test: log per user which non-core tools were needed in successive sessions and compute the hit rate of seeding the previous session's set.
4. **Short sessions with long gaps.** If gaps exceed `L` for most returns, each return re-writes the whole prefix at the write price. S-min's prefix is small only in the deferral regime; in the expose-all regime a staged/memory design with a small prefix wins (`regime_bill.stdout.txt:111-116`: 5,750 against 1,782 at 20 tools, up to 287,500 at 1,000 tools).
5. **Provider without a stable deferral mechanism.** Where deferral is not available or breaks the cache (OpenAI before gpt-5.4; the university API, unknown), S-min's rule 2 degrades to expose-all or to cache breaks; a staged design using only prefix-neutral offering could win.
6. **Search discipline.** If models do not initiate search unprompted (uninstructed initiation: NONE FOUND, `03` slot 7), rule 3 fails silently and accuracy falls; memory or a stage that pre-loads wins.
7. **Large summaries.** If the summary write plus inject exceeds the history it replaces over the typical session length, rule 4 raises the bill; it is then dropped.

## 6. Falsifier
S-min is falsified as "the bar to beat" if, in the end-to-end set with repeated runs, any staged or memory-informed arm has a lower mean bill per turn (both ratio-of-sums and per-session means, DPR-0006 section 4) at accuracy nearly the same *in both a long-run and a returning-user setting*, with the bill computed from usage records and the price table. The two testable sub-claims are HYP-0015 and HYP-0016.

## 7. Alternatives considered (strongest case for each)
- **A. Expose-all with caching only (rule 2 small regime alone).** Strongest case: no discovery request, no search dependence, nothing to break. Loses beyond the window and at large `P` (`regime_bill.stdout.txt` "fits 200k" column).
- **B. Always defer with a core (rule 2 large regime alone).** Strongest case: one rule, no threshold `P*`. Loses at small catalogues where it costs up to about twice (ratio 1.7-2.2).
- **C. Staged narrowing (REQ-O14F-06).** Strongest case: the supervisor's novelty and the only form that addresses accuracy by shrinking the offered set. Evidence against as a *first* step: extra request per stage and cache miss without a fixed-prefix offering (EXT-0228); no measured multi-stage policy found.
- **D. Memory-informed offering (REQ-U21-04).** Strongest case: Copilot names it future work (EXT-0228) and the arithmetic shows a break-even hit rate near a quarter to a third in short returns (`memory_seed.stdout.txt`). Against: unmeasured, NONE FOUND in prior art.
- **E. Observation masking or file store for results.** Strongest case: halved cost in one study. Against: that study's workload is coding agents, and results were about 3.3% of cost in another.
- **F. A cheaper model for easy turns.** Outside the scope (REQ-O21-01) and not evidenced here.

## 8. Assumptions
Provider usage records expose fresh, write and read tokens (DPR-0006 assumption; EXT-0123 for Anthropic only). The university API supports prompt caching and a deferral or search mechanism (unknown, `03` section 10 item 1). The regime break-even `P*` can be measured per provider. The `calc/` arithmetic uses the lead's parameter choices, which are assumptions and not data.
