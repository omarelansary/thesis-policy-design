# DPR-0005: Cache and exposure dynamics, comparison with alternatives, and the corrected evaluation outline

**Proposal.** (1) Treat "exposure is add-only after the first turn" as hypothesis HYP-0009 and give the cost expressions under which add-only, rewrite, by-reference withdrawal, a stable interface and per-request varying sets each win or lose. (2) Replace the cost-direction claim by a closed-form cost model with an estimated response curve (HYP-0007, HYP-0008). (3) Compare candidate C-A (DPR-0004) with its strongest simple and different rivals. (4) Give an evaluation outline whose estimands are population-level, whose strata are not defined by treatment, whose initiator comparison is a trade-off analysis, and whose every component has a falsifier that is the negation of its claim.

## 1. Notation and assumptions of the cost model
`N` model-visible and billed input tokens of the tool-related block of one request; `ρ = N_restricted / N_full` (a token ratio, `ρ<1` for a restriction); `h` cache hit rate (share of those tokens read from cache); `p_u` base input price per token; `p_r` price of a cached read; `r = p_r/p_u`; `w` write multiplier for the first processing of a cacheable block (EXT-0021: 1.25 for the 5-minute cache on that vendor; a provider value, estimated not assumed); `T` turns per session; `Λ` cache lifetime (EXT-0057: 5 minutes by default, refreshed on each use, measured from the start of the request); `g` the gap between consecutive requests.
**Linear price model [assumption].** Billed input of the block = `N·[p_u(1−h) + p_r·h]`, ignoring the write premium on the cold path unless stated, output tokens, tool outputs, history, distraction effects, extra turns and latency. These omissions mean the model bounds only the *tool-block* component; in one corpus the harness base (system prompt plus tool definitions, not separable) was 74.7% of cost (EXT-0015, MAP, not re-read), so the tool block's share of total cost, not the token ratio, caps any saving.

## 3. Closed forms (DERIVED under the linear model; each needs the measurement in HYP-0007/0008 to be trusted)
**3.1 Which arm is cheaper at given hit rates.** Restricted is cheaper iff `ρ·[1 − (1−r)·h_r] < 1 − (1−r)·h_f`. 
- *Equal hit rates* (`h_r = h_f = h`): the cost ratio is `ρ` for every `h`; a restriction cannot lose on input cost if the hit rate does not drop. An inversion needs `h_r < h_f` (or extra turns, a write premium, or a larger prefix elsewhere).
- *Toollery natural* (`ρ≈0.025`, `h_f=0.989`, `r≈0.009`): the break-even restricted hit rate is `h_r* ≈ 0.22`; the observed 0.144 lies below it and predicts a cost ratio of about 1.09, matching the observed 1.09 (0.000819/0.000749). So the *point estimate* is an inversion produced entirely by the hit-rate differential; the interval includes no difference.
- *Cold caches* (`h_r = h_f = 0`, e.g. sparse traffic with `g>Λ`): ratio `ρ`; restriction's relative advantage is largest when caches are cold.
**3.2 Per-task varying surface in an agent loop (single-step vs loop gap).** If the surface differs per task but is fixed within a task, the restricted block is written at turn 1 and read at turns 2..T; the full library is warm across tasks. **Corrected after CH-0028:** a changed tools array also invalidates everything after it in the prefix (EXT-0058: the tools array "sits even earlier in the hashed request prefix than the top-level system field"), so the system prompt (`N_s` tokens, `s = N_s/N_f`) is re-written with the restricted block. Restricted: `(ρ+s)·N_f·[w + r(T−1)]`; full, warm: `(1+s)·N_f·r·T`. Restricted is cheaper iff `T > T* = (ρ + s)(w − r) / (r(1 − ρ))`. (My first form omitted `s`; it is the `s=0` case.) `T*` is inversely proportional to `r` and grows with the system-prompt share `s`. The `w` is also provider-specific: I earlier mixed the `r` implied by Table 15 with the 1.25 of the Anthropic page (EXT-0021); the Table 15 cells are fitted without any write premium (`w≈1`, challenger's check), so for that provider `T*≈(ρ+s)(1−r)/(r(1−ρ))`, about 2.9 turns at `s=0` and rising by about 141 turns per unit of `s`: with a non-trivial system prompt, per-task varying surfaces can need very long loops. `w` and `r` must come from the tested provider's own cache fields (HYP-0008 calibration), not from different sources. A single-step replay is `T=1`, below `T*` under the implied `r`, which is consistent with, but does not prove, Toollery's single-step null; a loop with `T>T*` would favour the restriction even with a per-task varying surface. This is the single-step vs agent-loop gap: the single-step replay measures only `T=1`. Not measured by any source in the corpus.
**3.3 Stable surface (per deployment or cohort).** Written once per cache lifetime across all sessions that share it, read at `r` thereafter: cost per request `ρ·r·N_f` against `r·N_f` for the full library, i.e. ratio `ρ`, provided requests arrive within `Λ` of each other so the entry stays warm (traffic reuse, which EXT-0061 itself names: "Cost savings therefore depend on cache state and traffic reuse"). If traffic is sparser than `Λ`, both pay writes and the ratio is again about `ρ`. HYP-0007 tests whether the hit rate really matches.
**3.4 Not covered here [U].** Minimum cacheable prefix length by provider (not in the extracts; a core `F` below it would not cache at all, which sets `h_r=0`; by 3.1 the restriction is then cheaper than a warm cached full library only if `ρ < 1 − (1−r)h_f`, the full library's effective price share, which is about 0.02 with the Table 15 numbers: a small uncacheable core can lose to a large warm cached library; per-provider check required); whether the provider shares entries across sessions with an identical prefix; the 1-hour option's price (EXT-0057 says "at additional cost"); other providers' lifetimes.

## 4. Add-only as a hypothesis: the surface-change options (correction 4)
Let a discovery append `κ` definitions of mean length `L̄` with `T_rem` turns left; `P` = non-history prefix after the change; `H_s` = history so far; `ΔL` = tokens removed by a withdrawal or rewrite.
| Option | Extra cost relative to leaving the surface unchanged | Saving | What must be true | What overturns it |
|---|---|---|---|---|
| **Add-only (append after the breakpoint)** | `κ·L̄·(w + r·T_rem)` per discovery | none; false-positive appends persist to session end | provider supports append without prefix change (EXT-0009 vendor; EXT-0059 beta); breakpoint moves with the conversation (EXT-0021 "automatically manages cache breakpoints") | accumulated unused appended tokens exceed what withdrawal or a boundary rewrite would save; appended tokens lower success |
| **Withdraw by reference** (one provider's beta) | one system message; prefix intact (EXT-0058) | model-visible tokens drop; **billed saving unknown**: no passage says whether withheld/withdrawn definitions count toward input tokens (V2 CANNOT DETERMINE); EXT-0009 says deferred definitions are "still send[t] in the tools array on every request" | provider offers it; keep at least one non-deferred tool (EXT-0066) | withheld definitions are billed in full (saving is only the visible-token/distraction effect) |
| **Mid-session rewrite** | `(w − r)·(P + H_s)` once (the tools array sits earliest in the hashed prefix, so the whole conversation is re-written, EXT-0058) | `r·ΔL` per later turn | `T_rem > (w − r)(P + H_s) / (r·ΔL)`; the factor `(w−r)/r` grows as reads get cheaper | `T_rem` short; history long |
| **Boundary rewrite** (new conversation) | `(w − r)·P` if the old entry is still warm and shared; **zero extra if the entry has expired** (`g > Λ`, EXT-0057) because the next request writes anyway | `r·ΔL` per later turn | gap statistics; whether other traffic keeps the old prefix warm [U] | warm shared prefix of the old variant is worth keeping |
| **Free-rewrite window** | zero: when the time since the last request exceeds `Λ` the cache has lapsed, so a rewrite costs only the write that would occur anyway | as above | the system can observe `g` (R) and no other session shares the entry [U] | shared entries kept warm by others |
| **Stable meta-tool** (EXT-0014: a "single stable `call_tool({name, args})` meta-tool so the array never changes") | interface schema `ι` in the prefix; a describe step per tool used; schemas enter the transcript | no tools-array change ever | dispatcher accuracy as native [U]; discovery steps cheap | accuracy loss; per-use steps exceed carried schemas |
| **Per-request varying set** | `(ρ+s)·w·N_f` written each request (the system prompt, share `s`, is re-written too) plus lost reads | token count falls | `T > T*` (3.2, with `s`) or cold caches | any regime with `T ≤ T*` and a warm full library (Toollery natural is one point) |

**Session horizon and cadence.** If the gap between requests stays below `Λ`, each use refreshes the entry at no extra cost (EXT-0057, V1), so a long, steady session stays warm and rewrites are expensive; a pause longer than `Λ` (a human in the loop, a slow tool) lapses it, and the next request writes everything at `w`: at that moment a rewrite is free. A request that takes long to stream counts against the lifetime ("lifetime measured from the start of the request", V1). The 1-hour option shifts these windows at a higher write price. Session horizon `T` and cadence `g` are therefore regime variables of the evaluation, not constants.

**Position for the candidate (adopted as a hypothesis, HYP-0009).** C-A uses *add-only inside a session* and *no mid-session rewrite* because (i) a mid-session rewrite re-writes the whole conversation prefix while the saving is `r·ΔL` per later turn, which pays only for long `T_rem` relative to `(P+H_s)/ΔL`; (ii) appends are documented as cache-preserving by two vendors (EXT-0009 and EXT-0010, both read; EXT-0010: discovered tools "injected at the end of the context window" to preserve the cache), which are claims, not measurements; (iii) the unsolved cost of persisting false positives is bounded by `B_s·κ·L̄·(w + r·T_rem)` per session, a design bound. By-reference withdrawal and free-rewrite windows are **arms**, not part of the candidate, because their billed benefit is unestablished (V2). **What would overturn the adoption:** a measured billed saving from withdrawal that exceeds the accumulated append cost in the claimed regimes; evidence that persisting appended tools lowers success; a provider without append support (then C-A is not applicable: node A0).

## 6. Corrected, falsifiable evaluation outline (correction 5)
Nothing here is authorized to run. All margins, repeat counts and symbols are human decisions.

### 6.1 Estimand (population level)
For arm `a` and task population `𝒟`: `Ȳ_a = E_{x∼𝒟}[Y_a(x)]` and `C̄_a = E_{x∼𝒟}[C_a(x)]` (a cost vector), estimated on the **same tasks** for all arms under one scorer and one code path (REQ-O14-03). Contrasts are against `pi_ref` and pairwise. Unit of analysis: task (clustered by session for multi-turn). The headline is `(Ȳ_a − Ȳ_ref, C̄_a − C̄_ref)` with intervals, and the F1 admissibility `Ȳ_a ≥ Ȳ_ref − δ` (δ human).

### 6.2 Strata without conditioning on treatment (5a)
- A **reference partition** `A_ref` is applied identically to all arms. It is **not any arm's output** (CH-0031: using the C-A surface would privilege C-A): it is the dev-frequency core of a size named before the run, with a second size as a sensitivity analysis. Stratum `M(x)=1` iff the task's required set `R(x)` (from the reference, scorer-side only, class P at runtime) intersects `K∖A_ref`; else `M(x)=0`. `M(x)` is a property of the task and the fixed partition, not of any arm's exposure, so it is pre-treatment.
- Prevalence `w = P(M=1)` is estimated from the sample and then **varied by post-stratification reweighting**: every effect is reported as `w·(effect in M=1) + (1−w)·(effect in M=0)` over a range of `w`, because the benchmark's `w` is not the deployment's.
- The arm's **own** miss indicator (`R(x)` not within the arm's exposure) is a post-treatment mediator; it is reported descriptively and never used to form comparison strata.
- **Recovery** (the path `S`): value `V = E[Ȳ(with) − Ȳ(without) | M=1]`, price `U = E[C(with) − C(without) | M=0]`, price in misses `P_1`. Population net effect (as the pair, or in cost units under a pre-registered exchange rule): `w·(V − P_1) − (1−w)·U`. It is a **function of `w`**, with break-even `w* = U/(V − P_1 + U)` when `V>P_1`. The falsifier is evaluated at the **estimated** prevalence `ŵ` of the declared task population with its interval (CH-0030: "positive at some `w` in a range" is near-vacuous because `w=1` gives `V−P_1`); the curve over `w` is a transportability report, not the test. Under F1 the test is admissibility and cost at `ŵ`, not a scalar net, so no exchange rate is smuggled in.
- **Extra-turn control.** Same number of extra turns, no tools, to separate tool value from a second attempt (EXT-0063/0064: under five percentage points for most models in a planning setting, V4, not a tool setting).
- Caveats: `R(x)` from a single reference under-counts valid alternative routes (EXT-0053 uses equivalence sets); a replay vehicle fixes the route; direction of the bias unknown.

### 6.3 Initiation mechanisms: a trade-off, not a conjunction (5b)
Mechanisms: `M` prompted model emission, `M₀` unprompted model, `S` system trigger, none, extra-turn control. For each, estimate `(R_m, U_m, P_m)` as in 6.2. A mechanism with higher `R` and higher `U` is **not dominated**. Compare on (i) dominance when it holds; (ii) otherwise the net at the estimated prevalence `ŵ` (the test) and, as transportability, the break-even `w_SM = ΔU/(ΔR − ΔP + ΔU)` and the curve over `w`; (iii) under F1, admissibility and cost at `ŵ`, with the admissible region in `w` reported as sensitivity. HYP-0012 replaces HYP-0006 (a conjunction of "recovery higher" and "price lower" cannot be the negation of "S is preferable at some `w`"). Prompted vs unprompted is a factor (HYP-0010): FitText's emission is prompt-prescribed with no alternative path (EXT-0065; V5), so it is evidence for `M` at best.

### 6.4 Response curves, not "no inversion observed" (5c)
- *Existence claim* (an inversion exists): one **verified** instance suffices: a cell whose 95% interval for (restricted − full billed cost) lies wholly above zero while the restricted arm exposes fewer tokens. The Toollery natural cell is not one (interval includes zero). The claim is falsified only by a sweep over regimes that contains no such cell (HYP-0008a).
- *Monotonicity claim* (cost is monotone in exposure): needs an estimated response curve with intervals by regime: **more than two exposure levels** per regime (two levels give a sign, not a shape), crossed with surface stability (stable vs varying), cache state (cold, natural, warm), horizon `T`, and provider `r`. Compare to 3.1-3.3; HYP-0008b is falsified when the model's prediction lies outside the interval. "No inversion observed" supports neither claim.
- Table 15 supplies two levels and three cells; it is a first point of the grid, not the grid.

### 6.5 Arms
`pi_ref`/P0 (C-0); P1; P3-vendor; P4 listed; **P1f/P3f** (frequency core by dev `p̂`, `|F|` equal to A1's, without/with `S`) and **P-sweep** (frequency core, `|F|` chosen by a dev sweep on the measured criterion; needs no price model; CH-0020); **C-A** (rule A1) with ablations: no `S`; `S` without the instruction; ranker variants; surface-change options of section 4 (add-only, boundary rewrite, free-window rewrite, withdraw-by-reference where offered); C-B; C-C where feasible; an **oracle-exposure arm** (scorer-side U1) as headroom; the **extra-turn control**. Where `pi_ref` cannot run (context overflow), the substitute is named and the claim is relative to it.

### 6.6 Falsifiers (each the negation of the claim, per regime, after correction for the number of regimes, models and conventions)
| Component | Claim | It is not justified if |
|---|---|---|
| Whole candidate (HYP-0013) | C-A is non-dominated by the comparators in some regime | in every claimed regime some comparator dominates on the pre-registered rule |
| Core rule A1 (HYP-0014) | the estimated core covers more held-out usage than size-matched controls | it does not, in every claimed population |
| Stable surface (HYP-0007) | hit rate not lower than full library | lower beyond spread in some claimed cell |
| Cost response (HYP-0008) | inversion exists; response follows the model | no verified inversion in the sweep (a); prediction outside the interval (b); **only when interval half-widths are below the human-set equivalence margin, otherwise inconclusive**; `r`, `w` calibrated on separate probes |
| Add-only (HYP-0009) | not beaten on billed cost at non-inferior success | some other surface-change arm is cheaper beyond spread in a claimed regime |
| Initiation (HYP-0010) | prompted (and, separately, unprompted) models search | rate not above the no-interface baseline, per model and condition |
| Recovery (HYP-0011) | the recovery arm is preferred to no recovery at the estimated prevalence `ŵ` of the declared population | at `ŵ` (with its interval) the pre-registered rule does not prefer it (under F1: not admissible-and-cheaper) |
| Initiator (HYP-0012) | `S` preferable to `M` at `ŵ` | at `ŵ` the pre-registered rule does not prefer `S`; the curve over `w` is transportability only |
Ties inside the repeat spread count for nothing either way. A result for one provider does not carry to another.

### 6.7 Order of questions (cheapest first, each can end the line)
1. Cost mechanics per provider: `r`, `w`, `Λ`, minimum cacheable length, hit rate of a stable vs varying surface (HYP-0007, 0008) — decides whether cost differences are mechanical.
2. Usage concentration on dev (HYP-0014) — decides whether a core exists.
3. Prompted and unprompted initiation (HYP-0010) — decides whether model-driven deferral is viable.
4. Population-level recovery and initiator comparison (HYP-0011, 0012).
5. The full comparison (HYP-0013).

### 6.8 Threats to validity (apply to all; direction usually unknown)
Replay vehicle limits (single reference, stub schemas as cues, steering error messages, no cache fields, no sessions, fixed 12-turn budget; EXT-0042's budget-30 control is exploratory on one model, V7); scorer conservatism makes accuracies lower bounds (EXT-0043 MAP); single-step benchmarks (Toollery) cannot show loop effects; provider specificity of every cache number; vendor statements unreplicated; a dev/test split must be recorded; multiplicity across regimes, models, conventions.

### 6.9 What the human must set before any run
`δ`, `ε`, the per-falsifier margins, the cost convention and tokenizer, `pi_ref` or its substitute, the primary criterion (Q1), the range of `w` and `T` claimed, repeats and models, and whether U1-U3 are reported.

## 7. Unsupported
Billed treatment of withheld definitions; the cause of the Toollery hit rate; `r` on any provider other than by inference; minimum cacheable length; cross-session sharing of entries; initiation; usage concentration; the value of any prevalence; any multi-stage benefit.

## Alternatives considered
Keeping add-only as a constraint (DPR-0003 R-cache): rejected as a premise because the by-reference beta removes the forcing argument on one provider and because a rewrite can be free after `Λ`; kept as the candidate's default. Evaluating recovery inside "no-miss/miss" strata defined by each arm's own exposure: rejected (post-treatment).

## Falsifier and assumptions
Falsifiers: section 6.6. Assumptions: the linear price model holds for the tested provider; cache fields are reported; the reference partition can be computed scorer-side.

## Not claimed
That any closed form holds beyond its assumptions; that restriction reduces billed cost; that add-only is optimal; that any numeric value cited from a source transfers to another provider.
