# The blind alternative: static core plus native tool search, role filter, short memory (from thread T-20261022-113)

**Proposal.** Recorded on behalf of the two blind instances, whose outputs are stored verbatim in `design/package-v5/inputs/blind-output-A-20261022.md` and `blind-output-B-20261022.md`; the lead has not changed their content, only merged their common core: a stable cached prefix (system prompt, a small usage-derived core, a short category index); a static filter by invoker or deployment at session start; deferral of the remaining tools with the provider's native search, appended inline, as the recovery path; a short summary written at session end and injected at the next start; tool results moved out of the context only where results are large; cache lifetime chosen by expected gap (instance B only). Both instances cut multi-step narrowing and LLM-based filtering, and both name expose-all with caching as the rival; instance A names "a static usage-derived core set plus the provider's native tool search, with no custom memory" the likelier practical winner.

**How it differs from DPR-0007.** It has no memory-informed offering (instance A lets memory pre-load tools as an option; instance B defers it until search round trips are measured), and it was designed without the per-turn offering mechanisms of `design/package-v5/03-reuse-map.md` section 2, which were not in its allow-list.

**Basis.** As cited in the two outputs; the decisive mechanism claims are re-read in `design/package-v5/01-problem-and-evidence.md` section 3 (EXT-0158, EXT-0131; L/pdf-tokennotcost-2607.12161v5.txt:243; EXT-0016).

**Falsifier.** It is dominated by DPR-0007 if memory-informed offering passes HYP-0017 at no accuracy loss; it dominates DPR-0007 if HYP-0017 fails.

**Not claimed.** It is model output recorded as a candidate, not a finding.
