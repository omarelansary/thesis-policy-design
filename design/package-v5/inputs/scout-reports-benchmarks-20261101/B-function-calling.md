## 5. Possible wrong assumptions
- P3 names "BFCL's withheld-function design", whose native protocol appends functions to the tools list mid-conversation (B1, to verify), the operation V5 forbids; adapting it to deferral is a modification and the scorer's assumptions must be checked in code.
- Catalogues are 13-50 tools per task; none reaches R-large; ToolHop and ToolMATH are larger only as pools; n* needs padded or constructed catalogues.
- Deterministic state scorers are not neutral (B8, B10); scorer noise can hide or create a difference.
- User simulators need strong external models; on an open-weight route the simulator changes, published pass^k is not comparable, and simulator tokens cost money.
- Version drift (tau2 2.0 on 2026-10-19; BFCL continuous fixes): lock by commit.
- BFCL V4 memory cannot stand in for P1 (own memory tools, restored snapshot, no tool seeding).
- AppWorld is code-execution style; whether definitions are in the prompt or looked up in-loop is unverified; if in-loop, the tools-array construct differs.
