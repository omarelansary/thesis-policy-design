## 2. Searched and not found (in the places searched, not "does not exist")
- No benchmark found that scores feasible sub-tasks of a multi-need task separately from an impossible one and rewards doing the feasible part plus reporting the rest. Nearest: FTA "useful partial help" (single failed tool, human-annotated), AgentAbstain's judge rule on safe subtasks, SGC in AppWorld (all-or-nothing). Two searches including the extended one found none.
- No benchmark found that combines false-claim, substitute-action and collateral-damage penalties in one deterministic score for a missing-tool task. Combine C9/C10 (collateral), C4 (minefields) and C5 (false success).
- No tool-retrieval benchmark found (TOOLRET: NDCG, Precision, Recall, Completeness @10 [S]; MTRB: Sufficiency@k [S]) that includes queries with no relevant tool in the library, or that studies agents repeatedly rewording search_tools calls. ## 3. Recommended evaluation designs / metrics to reuse (two-need tasks)
Design A: paired task with a need-removed twin, scored on state. Build each two-need task in two versions: both needs present, and one need's tool removed from the catalogue. Pair outcome is correct only if the full version completes both needs and the removed version completes the remaining need and does not complete the other (AgentAbstain Paired Accuracy, C2; masking critical tools, C1; AppWorld-style state diff as the checker, C9). Add a 'the one present tool still gets used' count so a blanket stop does not score well (over-stopping control; C7 FAIL false positives, C8 asymmetric grading, C5 over-refusal).

Design B: deterministic penalty layer. For the removed-need version, define in advance the near-miss calls as ToolSandbox-style minefields (C4). Report three separate rates, not one score: substitute action (minefield or unexpected state change, C4 and C9/C10), false success claim (final text claims the removed need was done while the state shows it was not; C5 definition, checked by comparing claim text patterns to state, not by an LLM judge where possible), and FCR-style "kept searching to the backstop" (C1). Report goal-satisfaction and collateral rate side by side (C10: 4.7x spread at comparable goal rates).

Design C: stop timing, per need. Log the first search whose result is the note and the first later search or action, and compute "calls and tokens after the earliest warranted step" (C2 future-work metric; C1 token cost to early stop vs task failure ratio). Report the stop rule with precision on the feasible need as well as recall on the absent need (C8). Include a plain-prompt and a structured final-report condition (C5 STATUS / EVIDENCE / LIMITATION / NEXT ACTION) as comparison arms, enforcing the report fields in code if you want the format to count as system-side.

Cautions: C2 and C5 use human or LLM judges, so we should only take their definitions, not their scoring. C11's critical-failure wording is unconfirmed. Everything above except where a quote is marked [Q] rests on summaries of the papers.
