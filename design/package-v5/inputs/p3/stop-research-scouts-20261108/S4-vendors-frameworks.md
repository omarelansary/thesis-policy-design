## (3) Synthesis
Deterministic, not turn counts (and what they key on):
1. Identical call plus identical result, consecutive (CrewAI): note on the 4th, hard stop of tool use on the 5th. It resets on any other call or changed result. Outcome-based, but exact-equality, so drifting queries (issue #89469) escape it.
2. Stop on a named tool or a condition on a result: OpenAI `StopAtTools`, custom `ToolsToFinalOutputFunction`; AutoGen `FunctionCallTermination`, `FunctionalTermination`; Semantic Kernel `context.Terminate`. All are client hooks that see each tool result. A "no-match" result can be an input to such a hook, but none of these docs ships that rule.
3. Per-call pre-execution guards that return a reason to the model: OpenAI input tool guardrails (`reject_content`), ADK `before_tool_callback` (dict skips tool), Claude Code PreToolUse (`deny`/`ask`, matcher by tool name incl. `mcp__server__tool`), LangChain HITL middleware (approve/edit/reject). These are the vendor-supported places for a substitute-action guard or a confirmation on state-changing calls. None of the docs ships a criterion such as "not the requested action"; the check is user code.
4. Counted limits (not what we want, but common): LangChain ToolCallLimit per tool (`run_limit`, exit 'continue' / 'error' / 'end'), OpenAI `max_turns`, LangGraph `recursion_limit`, smolagents `max_steps`, AutoGen MaxMessage.
5. Typed outcomes that help a rule key on "absent" versus "failed": Redis gateway (`matched`, `truncated`, `unknown_tool`, `completion`); issue #89469 asks Claude Code for the same.

Per need: only items 2 and 3 can be per need, because the hook can hold state keyed by the current need. No source I found does this. CrewAI's counter is per (tool, args, result) and resets on change, which approximates a per-need counter only if queries repeat verbatim.

Facts that bear on design:
- Vendors treat no-match as a normal empty result (Anthropic: "not an error"; Pydantic AI: "never spends a retry"), so the stop falls to the client by design.
- The one real-world report (#89469) shows the same failure family as yours (retry with drifting queries, workaround, false conclusion) but with the opposite root cause (the tool exists and is not yet loaded). A rule that stops on "no match" must know whether the catalogue is final.
- Across the sources, the ladder note then hard block recurs (CrewAI vendor docs; community loop detectors [P]). That matches your run 3 note-then-withdraw proposal. Whether that ladder works for models is not shown by any of these sources; it is documented as design, not as measured.
- The ADK Python page and a TypeScript snippet disagree on whether an empty dict skips the tool; check per language if relevant.
