## COMMON
You are helping a master's thesis on a **tool-access policy for LLM agents**: which tool definitions the model sees, when, and how a session or a returning user's memory changes that, judged by the **bill** (input, cache-write, cache-read and output tokens at a price table, averaged over turns and sessions) with accuracy nearly the same. The current draft policy (V5) is in `design/package-v5/04-design.md`; read sections 1, 3 and 6 first. In short: a deployment filter (S1) declares the tools a deployment may use; below a break-even catalogue size all tools sit in a cached prefix, above it a small core plus a search tool, with the rest deferred and discovered tools appended at the end (never editing the tools array within a session, because that breaks the prompt cache); a plain Markdown memory file per user (M1, W: short summary, an index of past tool question-answer pairs, tools used) is read at session start, and for returning users the tools they needed before are **seeded** at the first turn that names a task (M2, M3). The model runs on open-weight models behind an OpenAI-style LiteLLM endpoint (no vendor tool search there), so discovery and seeding are client-side. What V5 has already covered is in `design/package-v5/03-reuse-map.md` and `design/package-v5/14-expose-ideas-verified.md`; skim them so you do not repeat their sources unless you find something new about them.
