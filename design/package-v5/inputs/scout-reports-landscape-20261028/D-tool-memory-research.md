The closest items and what each lacks:

## 5. What contradicts a V5 choice, shows a similar idea failed, or shows it costs more than it saves
- **Cost of memory (bill).** Three papers that report tokens show memory raised them: MemToolAgent input 307,822 vs 72,345 without memory (D8); ExpeL 4310 vs 1320 per trajectory on HotpotQA (D20); EvoMemBench CrossEp-Tool, every memory method above the no-memory backbone's 55,787 (D25). Counter-examples where overhead was small: SWE-Exp +7% tokens (D24), Agent KB $0.27 on $86.0 (D23), PRefine 26 memory tokens per instance (D12). V5's break-even arithmetic (D-02) should be compared with these overheads, not only with the seed definitions.
- **Unfiltered writing hurts.** Add-all memory reduced success below fixed memory (D4); self-generated skills gave no gain (D27); DC fell below baseline on small models (D21); including failures hurt AWM (D19).
- **Always-on or many entries hurt.** Memp (D18), ToolMem (D7), SWE-Exp (D24: one experience best, more degraded), SkillsBench (D27: 4+ skills +5.9pp vs +18.6pp), ExpWeaver (D26). This bears on how many seeds M3 offers, and supports a small seed set.
- **Long history hurts tool choice.** PEToolBench (D10) and UserToolBench (D11): accuracy falls as history grows. V5's choice of a short summary and an index (M1) is consistent; it argues against putting a raw tool log in the context.
- **Memory biases tool parameters** (D1, D2). Not yet measured for tool **selection**, which is exactly what M2 changes; a P1/P2 check on whether seeded tools are over-called would address it.
- **Offering remembered procedures as tools was not clearly better** (AWM_AS, D17).
- **No paper found shows M2-style seeding failing or working at large-catalogue scale;** the evidence is either small catalogues or no bill.
