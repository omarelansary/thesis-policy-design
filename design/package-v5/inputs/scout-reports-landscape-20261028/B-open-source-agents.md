## 5. Contradicts, failed, or costs more than it saves
- Kilo's Memory Bank deprecated (B4) and Gemini CLI's `save_memory` tool seemingly dropped for file editing (B27): two projects moved away from a dedicated memory tool or file-bank. Reasons are not stated in either page, so read this as a signal, not a finding.
- Cline's "read ALL files every task" (B5) and Goose's "all memories in every prompt" (B16) are eager-load designs with no stated limit and no cost numbers; V5's index-first design is the better-bounded version, and Kilo and Mnemopi are the two shipped counterparts.
- Codex memories exclude chats that used MCP tools or web search (B7). V5 records tools used in W; the Codex option exists because of a stated concern about external context (the page gives no reason beyond the setting name), which bears on the staleness and poisoning risk of seeding from tool history.
- Goose's own page says more than 50 tools reduces tool-selection quality (B17), which supports deferral above a size but is a docs rule of thumb, not a measurement.
- Nothing found says per-user seeding of tool definitions costs more than it saves, and nothing shows it working. That gap is the same as V5's.
