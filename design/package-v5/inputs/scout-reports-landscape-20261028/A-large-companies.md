## 5. Anything that contradicts or complicates a V5 choice

1. Memory is placed after the tools block in the two Claude Code layer tables (A1, A16) and is read once at session start (A6). This supports V5-R06 and M1. It is also the reason a seed set that is changed mid-session or seeded per user cannot sit inside a shared prefix.
2. Vendors that built automatic memory have narrowed it. Cursor's automatic Memories lost their management UI or were removed in 2.1.x (A27). Windsurf's Memories are legacy-agent-only with the docs steering users to Rules and AGENTS.md (A28). Devin Knowledge is deprecated into Skills (A29). Codex memories are off by default (A22), Gemini Auto Memory is experimental and off by default (A24), and Kiro memory is off by default (A31). None of these pages states a reason. [I] The pattern fits V5's own finding that memory-informed offering is unproven, but it is not evidence about cost.
3. Codex excludes sessions that used MCP or tool search from memory generation through a setting (A23). V5's W records exactly those tool question-answer pairs. The reason and default are unknown.
4. Where vendors validate, they validate at read time against current state (Copilot, A18, A20) and expire by disuse (28 days). Claude Code's auto memory only timestamps (A12). V5's W/M2 currently has no staleness rule beyond S1; the Copilot design is the nearest shipped alternative.
5. Copilot's own page contains two 2-5 point statements pointing in opposite directions (see A21). Not a contradiction of V5 but a reason not to cite either without the steward's check.
6. No page read says memory reduces the bill; the one explicit statement is that "using memory can increase context usage" (Kiro, A31). Vendors' performance numbers (A15, A19, A21) are claims, not results.
