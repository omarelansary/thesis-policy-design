3. ARCHITECTURE NOTES

Copilot Memory (GitHub): stores facts with citations to code locations, scoped to repository or user. Written by the agent during work. Entered into the prompt when relevant memories are found. Citations checked against the current branch before use. Unused entries deleted after 28 days; a successful use may reset the timer. Cache, cost: "adding no significant latency" is the only cost statement; prompt caching not stated in the pages read. Size limits not stated in the pages read.

Anthropic memory tool: a client-side directory of files under /memories, six file commands. The model views the directory first (a system-prompt instruction added by the API), then reads files on demand as tool results. The model writes as it works. Limits: the page advises the application to cap file size and the characters returned by view; expiry is left to the application. Prompt caching: not stated in the pages read.

MCP (spec 2025-11-25) and Claude Code: tool list is fetched with tools/list; listChanged notification is the staleness signal; Claude Code replaces the list on refresh and keeps the old one if the refresh fails; an optional discovery cache of tool names is persisted across sessions (off by default). Prompt caching: not stated in the part of the page read.

Poisoning papers: AgentPoison, MINJA, Zombie Agents and MemSentry-type work attack a store that is read into the prompt; none of the abstracts is about a store that holds tool names for offering. ToolHijacker, MCPTox and MPMA attack the catalogue, not memory.

Not covered at architecture level: Antigravity /learn (see 4).

5. WHAT CONTRADICTS OR QUALIFIES A V5 CHOICE
- M2 seeding from a memory index: the poisoning papers show that memory written from untrusted content can persist and trigger tool behaviour (G5, G6), and that content screening and provenance weights failed in one study (G10). V5's S1 limits the damage (a poisoned seed can only name a declared tool), which G9's origin-binding idea and G26's hash check complement. V5 does not yet say what W copies. The safest reading of the evidence is to write only user-authored and executed-tool entries.
- Staleness: MCPEvol-Bench (G24) shows models lose 13.7 to 14.4% on evolved tool interfaces. A seed that points to a renamed or changed tool is not neutral. The Copilot design (G18, G20) shows that read-time validation was cheap in a vendor test; V5's equivalent check (definition hash against catalogue) needs no model call, so it adds nothing to the bill in the V5 equation unless the definition changed.
- Memory content other than tool pairs can bias parameters (G11); the V5 W stores tool question-answer pairs and tools used, which is fine, but any free-text "summary" is the carrier MEMDRIFT describes.
- Poisoning is probably harder with real prior memory (G4), but that is one EHR study on idealised attacks.
- Nothing found says seeding tools is a failed idea; nothing found measures it either.
