# 05. Proof-of-concept loop and end-to-end study: only what the reuse map leaves untested (V5, AUTH-020)

Status: provisional, lead, 2026-10-22. **Nothing here is authorised to run**; each item needs its own human authorization (ledger C-D09). The order follows the human's process (REQ-U21-06): small proof-of-concept items in a test-verify-improve loop, plain Markdown memory first, "don't engineer it at all" (REQ-O21-09), about 20 samples to start (REQ-O02-10); then one end-to-end study with repeated runs (REQ-O21-09). Everything `03` marks REUSE is **not** re-tested here (REQ-U21-03). No thresholds: "nearly the same" accuracy and "lower" bill are read against the paired baseline with run-to-run variation shown, and the reading is argued, not set in advance (DPR-0006 section 4).

## 2. End-to-end study (after the loop; outline only)
- **Arms:** K0 expose-all with caching and a summary; K1 vendor deferral; V5-R as revised by the loop; DPR-0008 (the proposer's simplest rival); DPR-0009 (the blind alternative); Executor (REQ-O02-06); the all-tools baseline (REQ-O02-01) where it fits the window.
- **Axes:** catalogue size across R-small, R-mid and R-large; session pattern (one long run; returning users with gaps shorter and longer than the cache lifetime, REQ-U21-10); at least two models through the university API (REQ-U21-08, AS-12).
- **Measures:** the bill per turn by DPR-0006 under both averagings (ratio of sums; mean of per-session ratios; the human chooses the primary one), its components, requests per turn, response time, task success; repeated runs so variance is shown (REQ-O21-09).
- **Not decided here:** sample sizes, the number of repeats, the models, the vehicle mix, any margin (there is none, REQ-U21-07).
