# 02. Why C-A deserves investigation, and how it compares with the strongest alternatives

Status: provisional. Sources: DPR-0004 sections 2-3, DPR-0005 section 5, RV-0003 section 2 (the challenger's strongest-rival case, argued at full strength). Labels: [F] stated in a cited extract, [I] interpretation, [DERIVED] arithmetic from extracts, [U] unknown.

## 1. The honest claim
C-A is **worth testing**, not worth adopting. The record does **not** discriminate among expose-all (P0), a static core (P1), vendor-native deferred loading (P3) and C-A (challenger, RV-0003 section 2). C-A survives as a **conditional** case: on the price implied by the only direct cache table in the record it cannot win on billed tool-block cost; it can win in named regimes whose numeric region is unknown. Its value as a research object is that it is fully specified, contains the strongest simple rivals as special cases, and has a cheap first experiment that can end the line.

## 2. Reasons it deserves investigation (each can be wrong)
1. **It is a policy, not a family** (01): every decision has a question, actor, inputs with class, rule, transitions and a test. The one new decision content is rule A1.
2. **It passes the runtime-information test row by row** (01 section 7; audited by the challenger, who found no use of gold tools, reference trajectories or benchmark annotations at runtime as written).
3. **It contains rivals as special cases**, so one scorer tests them together: surface equal to the whole catalogue is expose-all; the same surface without the search interface is a static core and isolates the search interface; a listed grade is a comparator. The proposer's first wording, "the comparison isolates A1", was **false** (challenger CH-0020, rated decisive when raised, later downgraded after the fix): vendor-native deferral differs in size, ranking and data of its core. Arms that do isolate the rule were added: a frequency core with the same size as A1's surface, with and without search; and a frequency core whose size is chosen by an **empirical sweep** on the measured criterion (needs no price model). **A1 earns a place only if it is not dominated by that sweep.** If the sweep ties it (the challenger expects it may), the price model adds nothing and the finding is that the empirical sweep suffices.
4. **Recoverability is designed in, conditionally.** A deferred tool stays reachable by the model's own re-query, whereas a hidden tool in a system-run selector with a system trigger leaves the model no way to ask. This difference exists **only if models initiate search** (unmeasured, HYP-0010). The earlier claim that deferred failures are "observable at runtime" was withdrawn: a model that does not search is a non-event, just like a trigger false negative.
5. **Cache-compatible by construction.** The surface is identical across requests and changes in a session only by appending. This avoids, by design, the hit-rate drop that explains the Toollery natural-replay result **if** that inference holds (the cause of Toollery's low hit rate is not in the stored text; inference only, HYP-0007).
6. **Cheap, decisive first experiment.** Cost mechanics per provider (cache-read and write multipliers, billing of deferred definitions, minimum cacheable length, hit rate of a stable vs varying surface) decide whether any difference in billed cost is even available. If none of the regimes below exists on the tested providers, the answer is expose-all.

It is **not** chosen because it resembles the supervisor's example; it does not: it has no stages and no staged filtering. The staged graph is kept as candidate C-B (below).

## 4. When the alternative wins: the decision procedure by evidence
- **Prefer expose-all** if no restriction pays in billed cost with success non-inferior in any regime tested (HYP-0008, HYP-0013).
- **Prefer C-B** if prompted models do not search (HYP-0010) **and** a usable trigger exists (HYP-0012).
- **Prefer C-C** if dispatcher calls are as accurate as native ones **and** usage is not concentrated (HYP-0014 false).
- **C-A is complete only under objective reading O1.** Under O2 (minimise exposure subject to success and cost) rule A1 must be replaced.

## 5. Where cost differences come from (why the cheapest experiment matters)
Closed forms, [DERIVED] under a linear price model (the challenger reproduced the algebra and the fit; not steward-verified): if hit rates are equal the cost ratio of a restricted to a full block is the token ratio, at any hit rate; an inversion needs the restricted arm's hit rate to be lower, or extra turns, a write premium or a larger prefix elsewhere. Under the Table 15 numbers the break-even restricted hit rate is about 0.22 against the observed 0.144, which reproduces the observed cost ratio near 1.09; the paper's interval includes no difference, so this is **not** a verified inversion. A per-task varying surface in an agent loop beats a warm full library only above `T* = (rho + s)(w - r) / (r (1 - rho))` turns, where `s` is the system-prompt share re-written with the tools array (EXT-0058); about 2.9 turns at `s = 0` and rising by about 115 turns per unit of `s` (lead arithmetic; the proposer's text says 141, which does not follow from its own formula; the qualitative point is unchanged). A single-step replay measures only one turn. **Cache state, not exposure count, is the first-order driver in Table 15** (full-library cost differs about 50 times between cache states).

## 6. The supervisor's staged graph
Kept as **C-B**, not adopted and not excluded: system-run relevance questions at the start, a system trigger for re-adding during the run. It differs from C-A in who decides relevance and what information the decision uses. The record gives no evidence that a second filtering stage pays or fails to pay on tools (a two-stage router matched single-stage retrieval in success; token data absent). Its binding force on the policy is the supervisor's to state (REGISTER G.3 Q2). The supervisor's examples (10,000 tools, stage numbers) are not specifications.
