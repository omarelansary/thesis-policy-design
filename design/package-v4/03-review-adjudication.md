## 2. Further defects found while checking (not in the review's list)
1. **Misattributed scale figure in the untracked 19 Oct draft.** It says the 1,168-tool catalogue is "about 292k tokens ... by its authors' estimate". The paper says only that flat exposure is "10-30x the prompt of any other cell" (EXT-0053). The 292k figure is the benchmark **repository's development document** (hypothesis H5), reached here through the project's own S4F digest, with the caveat that placeholder schemas make it "not clean" (S4F line 41; S4G lines 23 and 28; steward V18, EXT-0084; direction of the error not stated). v4 says so.
2. **Power arithmetic used two-sided tests for a one-sided problem.** The draft's 160 and 1,700 pairs are the two-sided versions; one-sided noninferiority needs about 124 and 1,371 (single contrast) and about 209 and 2,322 with six Bonferroni contrasts (`02` section 7; assumptions stated). Larger, not smaller, for the multi-arm tournament; the stratum rule multiplies it.
3. **A mechanism family was dropped between packages.** Package v1 carried model-driven group-then-tool navigation (P4g, DPR-0002 F4); v3's arm list (D3) did not, although it is the only arm in which the **model** answers each stage's question and the only one with a vendor example at large size (EXT-0023). Added to the arm table (`02` section 5). No evidence says it is better.
4. **"Stage present only where justified" is satisfiable by anything** (v3 itself says so). v4 turns it into a stated test: a component is kept only if the arm containing it is feasible and cheaper than the same arm without it, on paired data (`02` section 5). This does not add a decision; it makes the existing one checkable. It is path-dependent (listed as a weakness).
5. **Objective in the supervisor's motivating regime.** "Not below expose-all by a margin" is vacuous at 10,000 tools. Reported as an open question to the supervisor, not resolved here (brief questions 3-4).
6. **Further draft misattributions found by the steward (`findings/SUM-0004`):** the 75% static-prefix share belongs to "Token Reduction Is Not Cost Reduction" Table 1 (cache attribution inferred), not ProMCP, and ProMCP's tool-result dominance holds for one workload block only; DynamicMCPBench scores an unexercised route as *failing* (reported accuracies are lower bounds), not "unscored"; the "12-turn" budget in the paper is the explorer's, the evaluation budget is in the dev document; the vendor blog's own wording is "preliminary results from a handful of test runs" and its table has cells favouring each side. The ComplexMCP Gemini-3-flash row is 55.31 (token columns match; an inference), so the 16.3 and 18.4 gaps stand.
7. **Cosmetic but material:** the draft and v3 sometimes write "matched" or "~" for non-significant differences; v4 text avoids it.
