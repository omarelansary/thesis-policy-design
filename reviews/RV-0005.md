## 4. The opposite conclusions: what evidence would favour what v4 did not choose
- **Expose-all or minimal restriction wins wherever it fits, and the beyond-window question is only feasibility.** Stored evidence pointing that way: ComplexMCP full context above every retrieval variant at about 300 tools (EXT-0026) including the search-tool arm (EXT-0075 lines 48-54); ToolMenuBench all tools above keyword filters (EXT-0028); DMB flat approximately equal to rag:32 (EXT-0053, one model); Toollery natural replay with no billed saving (EXT-0061). Evidence pointing the other way: Toollery cache-suppressed (-97.5% billed), ToolMenuBench CMTF (gold-path-like), Speakeasy 100 tools. The brief reports the first set more fully than the second (CH-0055).
- **Strongest rival to v4:** a two-regime rule fixed in advance: "expose-all where the catalogue plus working context fits, vendor-style deferral with a small core beyond", with no staged components. v4 contains it as arms, so v4 cannot lose to it in the sense of excluding it; the question is whether v4's additional arms and components (P1 levels, P3, navigation) ever beat it. The experiment that separates them is the one v4 already names as the end-to-end sweep, but restricted to a pre-committed comparison: for each catalogue size within the window, expose-all versus search-only versus core plus search, tokens and billed cost both reported, plus the "ask" initiation rate (E2); and for sizes beyond the window, search-only versus each component in matched pairs. If the two-regime rule is not beaten at any size by a margin larger than `epsilon`, v4's staged content is empty, as the brief says. This needs sample sizes of the order in CH-0053; with the sample sizes available it is likely to return "not shown" (CH-0057).
- **A termination-time trigger** is the only mechanism with a stored trigger-like result (EXT-0063) and it is excluded from the arm table by placement (CH-0045). If the lead's reason is the one in package A (D5), the brief should say so.
