## 3. Retained disagreements (objections I still hold after the fix)

- **R1 (should-fix, from CH-0075).** D-02 omits the K = 3 definitions per discovery that D-01 uses, so it is not on "the same inputs" as claimed (`memory_seed.py:3-4` vs `regime_bill.py:19`). With K = 3 the client h* at r = 0.1 falls to 0.21 (T = 10), 0.31 (T = 30), 0.47 (T = 100) and the server "never" becomes 0.51. The "narrow band" and "never pays in long sessions" statements (04:8, DPR-0007:21, 00-README:10, HYP-0017:15) need this stated as a sensitivity. Resolve: run D-02 with K as a parameter and state the range.
- **R2 (should-fix, from CH-0087).** Three different quantities are called the hit rate (D-02: fraction of seeded tools needed; P1: fraction of needed tools previously used; HYP-0017 and DPR-0007 falsifier: share of sessions with any recurrence). The gate in P1 can open when D-02's condition fails. Resolve: define h once, on the seeded set, in P1, HYP-0017 and DPR-0007, and merge or fix HYP-0016/0017.
- **R3 (should-fix, from CH-0080).** The break-even range "10 to 170 tools ... depending on definition length" is not computed for d = 100 with an uncached core, which is the realistic case there; by hand it is about 196-231 at D = 10, r = 0.025. Stale "10-25" remains at 02:54 and 08:16. Resolve: add d = 100 and d = 1000 to the uncached columns of table B and update the three sentences.
- **R4 (should-fix, from CH-0090).** "NONE FOUND" still stands, with the search log named as basis, at 03:98 (log:29 says not re-searched) and in 03:99, 03:122, 04:71, 02:16, 06:22, 08:8, 08:19; each remaining absence rests on one query and unread hits. Resolve: one wording ("not found in the stated limited search, or not searched") across files; list the unread hits as leads. Tool-to-Agent Retrieval should not count as the overturn of the multi-step-narrowing negative.
- **R5 (should-fix, from CH-0083/0085).** "Embedding routing adds no model request" is attributed to EXT-0228 (02:52, 04:94, 06:33) which does not state it, the ranker's embedding cost is outside DPR-0006's terms, and the decision cites a vendor figure that 04:104 says is not relied on. Resolve: mark it [I], add an embedding-call term (or state it as unpriced), and drop the vendor figures from the basis.
- **R6 (should-fix, from CH-0084/0099).** Q-J31 counts M2 as a stage though it is off by default and absent in R-small; in the default configuration two stages decide. Resolve: state the default configuration in Q-J31.
- **R7 (note, from CH-0088).** Standard error of a two-arm difference at 20 tasks per arm is about 16 points, not 10, unless paired; and the end-to-end study has no stated rule for "nearly the same".
- **R8 (note, from CH-0097).** Pointer L213 should be L211; the supervisor's L219 answer (do not re-give all tools on "hi") is in tension with session-start seeding and is not discussed in 02.
- **R9 (note, from CH-0076/0077).** Server-side search billing (a second sampling pass over the prefix?) is unknown and the uncached-core variant prices the core uncached and the appended block cached; both are one-sided assumptions that should be labelled.
