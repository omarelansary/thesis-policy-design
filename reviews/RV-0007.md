## Answers to the five questions
1. **Numbers/definitions.** One unsupported figure (65/65). "Spurious call = 100 minus irrelevance detection" is the authors' own reading, not a lead error, but rests on the BFCL irrelevance scoring that is not shown in the stored text. The larger error is the NTA label: queries name the tool and a direct answer counts as hallucination.
2. **Saturation.** Overstated in `05` section 2 item 5; section 3's hedge is fair but its evidence (recurrence) is weak and round 3 found nine new neighbours (CH-0073).
3. **Arms.** Not sound as written: the counted event is reversed in our setting (search is the correct call when the target exists); the two source rates are different constructs with 2x differences for the same model; the model-list rule cannot be met by a strong closed model on both arms (CH-0072).
4. **Stronger than a source.** `01` row heading ("cannot yet be assumed to ask for the right one unprompted"); "real prior numbers to compare against"; "hallucinated a tool" (CH-0074, CH-0069, CH-0070).
5. **Missing literature (query names, my background, not evidence [S]):** "BFCL irrelevance / live irrelevance detection results"; "function-calling relevance detection" (Hammer, ToolACE, xLAM papers report it); "tool abstention / refusal when tool unavailable"; "ToolHallu / function hallucination benchmark"; "MCP-Bench", "MCP-Universe", "MCPToolBench++" (hidden-catalogue MCP tasks with no-tool or search ablations); "RAG-MCP / tool retrieval for MCP" with instructed vs uninstructed arms; "tool search tool ablation" and "deferred tool loading evaluation"; "cost-aware / budget-aware tool use agents" (price per task, not tokens); "prompt caching agent evaluation" (agent trajectories billed with cache fields); "agent workflow memory", "skill library", "procedural memory tool reuse across sessions"; "knowing when to use tools / tool-need detection / metacognition".
