# Safeguards: what is enforced, what is only instructed, what was tested

Read this before trusting any "isolation" claim. **This workspace is not a sandbox.** Native Windows Claude Code has no OS-level sandboxing; every control below is a Claude Code permission rule, a deterministic hook, an instruction, or an after-the-fact check. A determined or careless session that runs arbitrary code can get around the hook layer (see "Known bypasses").

Legend: **P** = permission rule in `.claude/settings.json` (evaluated before the model acts; deny rules also hold under `bypassPermissions`). **H** = PreToolUse hook `tools/guard.py` (deterministic, fires for the lead and for every subagent, fails closed). **I** = instruction only (CLAUDE.md, agent definitions, PROTOCOL; the model is asked to comply). **D** = detective (`tools/verify_workspace.py` reports it afterwards; nothing prevents it).

## Known bypasses and unverified items
- **Obfuscated-path read** (confirmed, A1): `python -c` building the origin path from fragments read a harmless origin file. The origin boundary holds against honest or careless sessions, not against an adversarial one. Closing it needs an OS sandbox or a user account without access to the origin; neither was set up (not authorized, not available natively).
- **Bash writes bypass ownership and immutability** (by construction). Only the evidence-steward has Bash; its definition restricts it to the sanctioned tools (instruction).
- **Edit tool path** tested only indirectly: an Edit no-op was rejected by the tool before the hook ran (C1); the hook's Edit branch is covered by the Write tests and the guard table, not by a live Edit.
- **Interactive / VS Code sessions**: this bootstrap tested the bundled CLI in `-p` mode. The same `.claude/settings.json` should apply interactively after the folder-trust dialog, but interactive behavior (including any first-time project-hook approval prompt) is **unverified**. Consequence: on first open, check `/hooks` and `/permissions` and run `python tools/verify_workspace.py --quick`.
- **Native agent teams** (shared task list, teammate mailbox): not enabled, **unverified interactively**. With `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` under `-p`, no team-creation tool appeared; the Agent tool gained a `name` parameter and lead->agent and agent->agent sends by name were accepted; the reply leg was not confirmed (C5b). See WD-004.
- **Peer sessions**: item 10 blocks this workspace's agents from messaging other sessions. Nothing stops another session from messaging this one; such a message is not an authorization.
- **Lead discipline**: the lead edited `ops/STATE.md` during test B against its own thread rules (caught by git, reverted). Only git and review catch this.
- **Not tested**: adversarial prompt injection through evidence text; two threads at once; `bypassPermissions` with the hook disabled; Windows 8.3 short-name aliases of the origin path.
