# Models search when a needed tool is absent: prompted and unprompted initiation are different claims

**Hypothesis.** [hypothesis, not a finding] A model that is told to search when no visible tool fits (condition A) does so when the needed tool is deferred; whether it does so without the instruction (condition B) is a separate, weaker claim.

**Correction of HYP-0004.** HYP-0004 did not separate these conditions. In FitText the agent's only starting function is "Finish" and the system prompt says "To call any other function, you must first retrieve it" and "write: {BEGIN} [Describe the function you need in detail] {END}" (EXT-0065; steward V5 SUPPORTED; EXT-0050 says "may emit", the prompt says "must"). "Model-emitted retrieval" in FitText is therefore prompt-prescribed and has no alternative path: it is not evidence of spontaneous initiation when other tools are visible. MCP-Atlas "No Tool Use" shares (EXT-0047; V8 PARTLY: shares of diagnosed failures, definition "even though tools were required") do not state whether the required tools were visible, so they do not decide condition B either. EXT-0012 (OpenAI): "Discovery adds a step and depends on finding the relevant tool".

**What would falsify it.** The front-matter falsifier; margin set by the human before any run.

**Assumptions.** Initiation can be separated from search quality (measure recall of the ranker separately with scripted queries); the instruction text is fixed on dev data.

**Alternatives it competes with.** A system-side trigger (HYP-0012); no recovery.

**Not claimed.** That prompted initiation transfers to a mixed surface (core plus deferred); EXT-0012 states that mixing eager and deferred functions in one session is "supported but generally not recommended".
