# Models recover by searching without being told to

**Hypothesis.** When a needed tool is deferred, current models start a search on their own often enough that deferral's accuracy is nearly that of expose-all, given a one-line category index in the system prompt.

**Why it is plausible.** Vendors document search as the way to reach deferred tools and advise describing tool categories in the system prompt (EXT-0131) [F, practice advice]; no per-task uninstructed initiation rate was found (FND-0037 row C-S08/UNINSTR; FND-0042) [U].

**What would falsify it.** The falsifier above, with arms: target deferred but present; target absent; a wrong tool visible; with and without the category line.

**Assumptions.** The category line is short and charged in the bill.

**Alternatives it competes with.** Expose-all; an instructed search prompt; a system trigger (V4 P3, dropped from the default).

**Not claimed.** No rate is asserted.

## P3 result (added 2026-11-09 by the lead, AUTH-032 as amended by INT-T-103; status unchanged)
- Run 1 (2026-11-07, `design/package-v5/inputs/p3/RESULTS-P3-RUN1.md`): with the target deferred and no instruction to search, MiniMax-M3, DeepSeek-V4.1-Flash and GLM-5.3 searched in 20 of 20 sessions each and called the target in 20 / 19 / 20 of 20, against 20 / 20 / 20 with all tools shown. With a similar wrong tool visible, MiniMax-M3 searched in 19 of 20.
- The falsifier (a large failure rate) is not met on this set (`design/package-v5/05-poc-loop-and-e2e.md:15`).
- Limits: three open-weight models, one provider (OpenRouter, GMICloud, fp8), 20 lead-written tasks over AppWorld's definitions, stub results, one run per cell, temperature 0; the one-line category index assumed above had no visible effect and was dropped after run 1; ranker misses were not tested.
- The hypothesis is not closed here; closing it is the human's decision.
