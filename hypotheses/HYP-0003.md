# The unused price of an append-only recovery path is small

**Hypothesis.** [hypothesis, not a finding] When nothing was missed, adding an append-only re-add path (search/describe interface and/or a system trigger) costs little in cumulative tokens, billed cost and turns, because the prefix is preserved and the path rarely fires falsely.

**Why it is plausible.** Vendor documentation states that appended discovered definitions leave the prefix and cache untouched (EXT-0008) and that rewriting does not (EXT-0014); discovery "adds a step" (EXT-0012) only when used. All are documentation claims, not measurements; the standing cost of the interface in the prefix and trigger false positives are not measured in the stored corpus.

**What would falsify it.** The falsifier above (margin is a human decision, not set here); also a measured cache-break or extra turns attributable to the path in the no-miss stratum.

**Assumptions.** Provider caches as documented; the no-miss stratum can be identified scorer-side.

**Alternatives it competes with.** No recovery path; recovery by rewriting the tool array.

**Not claimed.** That recovery has value.
