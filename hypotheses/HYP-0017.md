# Memory-informed offering pays for returning users

**Hypothesis.** For returning users, offering at session start the declared tools that memory says this user or role needed before (placed after the shared cached prefix) lowers the session bill against discovery from scratch, because enough of the seeded tools are needed again to save more searches than the seeded definitions cost to carry.

**Why it is plausible.** Copilot chose its core of 13 tools from aggregate usage statistics (EXT-0228) [F, vendor]; personalized tool memory helps tool choice over small tool sets (`03` section 5) [F]. The bill threshold is arithmetic (D-02, revision 3 after CH-0075 and RV-0023 R1): h* ranges from about 0.15 to 0.51 with three matches per search and from about 0.21 to "never" with one, rising with session length [D] (revision 4 of the script: an avoided client-side search also saves the core-prefix re-read, found by the literature review of 2026-10-27); the arithmetic sets the threshold, it does not decide the outcome. No source measures h for per-user seeding from a large catalogue (`03` section 5).

**Revision.** 2026-10-22: the h* figures were corrected after RV-0021 CH-0075 (the first version omitted the longer carry of needed seeds and priced every avoided search as an extra request).

**What would falsify it.** The falsifier above, measured on the provider's usage records (DPR-0006), with accuracy recorded beside it; a stale-memory failure that lowers accuracy also counts against it.

**Assumptions.** The provider offers tools after the prefix without a cache break (Anthropic beta, OpenAI `allowed_tools`); users do return within the deployment's horizon.

**Alternatives it competes with.** K1 vendor deferral without memory; DPR-0009; DPR-0008.

**Not claimed.** No hit rate is asserted; h* is derived under stated assumptions.

## Result from P1 (2026-11-10, AUTH-033; status unchanged: proposed; revised after one review round)
- **Desk, on gold** (`design/package-v5/inputs/p1/P1-PREP.md` sections 6 and 7): for AppWorld's 34 returning users, seeding the
  tools a user needed before has a mean precision of 0.14, below every h* of `calc/memory_seed.py` (lowest 0.15), and reaches h*
  in at most 7 to 22 of 64 returning sessions. All per-user rules lose on the bill except "used in 2+ earlier sessions", which
  seeds almost nothing (+88 and +10 fresh-token equivalents at T = 8; negative at T = 30). Not tested live. A role memory (the
  six tools other users need most; it looks ahead, counting later-dated sessions) has precision 0.24 on gold.
- **Run** (`design/package-v5/inputs/p1/RESULTS-P1.md`): role memory against no memory, GLM-5.3 on OpenRouter GMICloud,
  client-side search, 33 sessions of 16 users completed in all runs, 2 repeats, $11.394. Measured h 0.27 against the desk's 0.24;
  searches −1.1 per session (−1.7 to −0.6). The bill estimate is −16%, −5% (without one no-memory runaway) or +16% (with one
  session cut by a run's cap), every interval including zero; success: no difference detected (about ±0.1 per session).
- **Reading [I]:** memory seeds save searches; a bill effect is not shown, because single expensive sessions in either arm
  decide the sign. The falsifier is not tested live for per-user memory and is not decided for role memory.
- **Not shown:** per-user memory live, the oracle arm, memory built from the model's own earlier sessions, a history-only role
  memory, other models, longer sessions, a route where discovery does not end the cached prefix.
