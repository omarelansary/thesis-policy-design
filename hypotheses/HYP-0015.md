# A regime switch on the tool block beats staged narrowing on the bill

**Hypothesis.** Once the tool definitions sit in a stable cached prefix, the bill is dominated by that prefix and by the number of requests, so a policy that only chooses between expose-all and core-plus-native-deferral (DPR-0008 rules 1-3) has a bill no higher than a staged policy that adds a narrowing step, at accuracy nearly the same, for the catalogue sizes and session lengths tested.

**Why it is plausible.** System prompt plus tool definitions were 74.7% of billed cost in one coding-agent study (EXT-0016; `L/pdf-tokennotcost-2607.12161v5.txt:200-224`) [F, one study]. A shipped staged design pays a cache miss and an extra round trip per group expansion (EXT-0228) [F]. First-order arithmetic gives deferral/expose-all tool-block ratios from about 1.0 to below 0.05 as the catalogue grows (`design/package-v5/calc/regime_bill.stdout.txt:4-55`) [D, lead's assumptions]. Reasoning, not evidence: an extra stage adds a request.

**What would falsify it.** The falsifier above. Test needed: provider usage records for both arms, computed with DPR-0006; the staged arm must use prefix-neutral offering (so its extra cost is only its own requests), otherwise the comparison favours S-min trivially. No threshold is set; "nearly the same" is read against the all-tools baseline as in DPR-0006 section 4.

**Assumptions.** Deferral and append preserve the cache on the tested provider (vendor statement, not measured here). Accuracy of S-min's core plus search is nearly that of the rival (not shown; EXT-0228 reports static lists covering the needed tool less often). The lead's `calc/` parameters are assumptions.

**Alternatives it competes with.** Staged narrowing at fixed prefix (offering per turn); memory-informed offering (HYP-0016).

**Not claimed.** Any saving size; any catalogue size; that the effect holds beyond coding agents.
