# Offering fewer tools at a fixed prefix keeps accuracy nearly the same

**Hypothesis.** When the full tool set stays cached in `tools` and a stage offers only a subset per turn (Anthropic `tool_addition`/`tool_removal`, OpenAI `allowed_tools`), accuracy stays nearly the same as offering everything, and may improve when the full set is large.

**Why it is plausible.** A large visible toolset cost 2-5 points of resolution rate in Copilot's benchmarks (EXT-0228) [F, vendor]; the offering mechanisms keep the prefix (FND-0040 rows on slot 2) [F]. No source measures accuracy under offering at a fixed prefix [U].

**What would falsify it.** The falsifier above, in a paired comparison with several runs per arm (REQ-U21-06).

**Assumptions.** The model respects the offered set; the offering mechanism behaves as documented (beta on Anthropic).

**Alternatives it competes with.** Offering everything (K0 within its regime); deferral with search.

**Not claimed.** No bill saving is claimed: at a fixed prefix the definitions are still read at the cache price.

## Result from P2 and P2b (2026-11-08, P2b added 2026-11-09; status unchanged: proposed; INT-T-044: "donot close it we moght need more eviddenve")
- **Test** (`design/package-v5/inputs/p2/RESULTS-P2-MAIN.md`):
  - AppWorld dev, 30 Spotify tasks, 128 definitions declared and cached; oracle subsets of 6-10 tools.
  - OpenAI Responses API with `allowed_tools`; gpt-5-mini and gpt-5.4-mini; 2 repeats per arm.
- **Falsifier not met on this set.** Accuracy with the subset offered against everything offered, per task:
  - gpt-5-mini +0.117 (95% scenario-bootstrap interval +0.033 to +0.217);
  - gpt-5.4-mini −0.050 (−0.167 to +0.050).

  Run-to-run noise between identical runs of the `all` arm: 6 and 8 of 30 tasks.
- **The assumption "the model respects the offered set" held** under server enforcement: 0 calls outside the subset in 120
  task-runs. The cache was kept: cached shares equal to or above the `all` arm.
- **Unenforced offering by instruction: its cost effect depends on the model** (corrected 2026-11-10; the first wording said gpt-5-mini "broke" the subset): all three models stayed inside the named subset about as well as, or better than, without the instruction (gpt-5-mini 19 of 1,507 tool calls outside against 29 of 1,936 in `all`; gpt-5.4-mini 0 of 1,782 against 44 of 1,655). It changed gpt-5-mini's batching (1.06 tool calls per request against 2.78), which doubled its requests (697 to 1,417, cost x1.37); gpt-5.4-mini's requests were x0.98.
- **P2b (2026-11-09; `design/package-v5/inputs/p2/RESULTS-P2B.md`):** GLM-5.3 on OpenRouter (GMICloud fp8, no effort setting sent: GMICloud's default; mean 481 reasoning tokens per request, median 38),
  `instr` against `all`, 2 repeats: 0 calls outside the subset in 60 task-runs; accuracy +0.067 per task (−0.033 to +0.217);
  calls x0.93, cost x0.80; run-to-run noise 1 of 30. Planned on the university API, which could not complete it (timeouts
  and HTTP 408), so the university route itself (4-bit weights, maximum effort) is still untested.
- **Not shown:**
  - realistic subsets that miss needed tools (P1, end-to-end);
  - catalogue sizes other than 128;
  - other benchmarks;
  - Anthropic's mechanism;
  - accuracy differences of a few points (a loop item cannot show them, `05` section 1).
