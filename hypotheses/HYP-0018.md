# Offering fewer tools at a fixed prefix keeps accuracy nearly the same

**Hypothesis.** When the full tool set stays cached in `tools` and a stage offers only a subset per turn (Anthropic `tool_addition`/`tool_removal`, OpenAI `allowed_tools`), accuracy stays nearly the same as offering everything, and may improve when the full set is large.

**Why it is plausible.** A large visible toolset cost 2-5 points of resolution rate in Copilot's benchmarks (EXT-0228) [F, vendor]; the offering mechanisms keep the prefix (FND-0040 rows on slot 2) [F]. No source measures accuracy under offering at a fixed prefix [U].

**What would falsify it.** The falsifier above, in a paired comparison with several runs per arm (REQ-U21-06).

**Assumptions.** The model respects the offered set; the offering mechanism behaves as documented (beta on Anthropic).

**Alternatives it competes with.** Offering everything (K0 within its regime); deferral with search.

**Not claimed.** No bill saving is claimed: at a fixed prefix the definitions are still read at the cache price.
