# Tool usage is concentrated and the estimate transfers to held-out tasks (precondition of any core rule)

**Hypothesis.** [hypothesis, not a finding] Per-tool usage probabilities estimated on a dev split rank held-out usage better than size-matched controls; without that, no core rule can beat expose-all or a vendor heuristic, and the candidate has no mechanism.

**Why it is plausible.** Only indirect: the vendor design rule keeps "3-5 most frequently used tools non-deferred" (EXT-0009), which presumes a frequency skew; EXT-0053 shows curated pools of about 8 tools do well against retrieval (curated 37.3-54.0 vs rag 16.7-40.0 in single attempts, cell interval about +-8). No source in the stored corpus measures the usage distribution of tools in a catalogue [U].

**What would falsify it.** The front-matter falsifier. Note the estimation uses calls observed in dev runs of the reference policy (class D), never annotated gold tools (class P); where the reference cannot be run (context overflow of the flat catalogue, EXT-0053 and the evidence map), the substitute pool is named and the claim weakens accordingly.

**Assumptions.** A dev split of sufficient size and disjoint from evaluation tasks; task populations stable between dev and deployment.

**Alternatives it competes with.** Flat usage (no core exists); usage predictable only from the query (favours C-B).

**Not claimed.** Any concentration level; no number is set.
