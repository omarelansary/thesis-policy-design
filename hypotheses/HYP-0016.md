# A text summary alone is as cheap as memory-seeded tool offering

**Hypothesis.** Letting memory only carry a short summary and tool Q/A text (DPR-0008 rule 4), and leaving tool discovery to the model's search, gives a mean bill per session no higher than seeding the previous session's tools at session start, at accuracy nearly the same.

**Why it is plausible.** [D] Seeding pays only above a break-even hit rate: about a quarter to a third in returning sessions of 3-10 requests, 0.36-0.69 for sessions of 30-100 requests (`design/package-v5/calc/memory_seed.stdout.txt:1-5`), because every carried definition is read at the cache read price on every request. Prior art: no system was found that lets memory choose or pre-load tool definitions with a bill measured (`design/package-v5/03-reuse-map.md:69`); Copilot names remembering tool usage as future work (EXT-0228) [F]. The hit rate for real users is unknown [U]; this hypothesis is the claim that it is low.

**What would falsify it.** The falsifier above. The measurement is cheap: a hit-rate count from tool-use logs before any arm is built. A hit rate above h* in the relevant session lengths falsifies it for those lengths.

**Assumptions.** The calc parameters (history 5,000 tokens, one search request per missed tool, definition 250 tokens) are the lead's assumptions and may be wrong; the break-even moves with them. The deferral mechanism preserves the cache.

**Alternatives it competes with.** Memory-informed offering as part of the combined policy (REQ-U21-04), which this hypothesis does not dismiss; it only states the condition under which the simple form wins.

**Not claimed.** That memory seeding never pays; any value of the hit rate; any result on the human's combined-policy requirement.
